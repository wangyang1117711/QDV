# 监控模块设计文档

> 版本：v2.8.0 | 更新日期：2026-07-22

## 1. 架构概述

监控模块是 QDetectVision 系统的可观测性中枢，负责周期性采集系统资源指标（CPU、内存、磁盘 I/O、网络、GPU）、识别资源与服务异常、持久化监控数据，并向 UI 上报实时快照与异常告警。模块以静态库 `Monitoring` 形式构建，采用单例 orchestrator 模式统一调度各采集器与检测器。

### 1.1 模块定位

- **所属层级**：基础设施层（位于 `Core` 之上，被 `AI` / `TrainingInference` 等业务模块依赖）
- **构建产物**：`Monitoring` 静态库（`src/Monitoring/CMakeLists.txt`）
- **运行时依赖**：Qt6 Core / Qt6 Network / Windows API（`iphlpapi`、`psapi`）/ `nvidia-smi`

### 1.2 子系统组成

| 子系统 | 核心类 | 职责 |
| --- | --- | --- |
| 监控编排器 | `TrainingInferenceMonitor` | 单例，定时采集 → 异常检测 → 持久化 → 上报 UI |
| 系统指标采集 | `SystemMetricsCollector` | Windows API 采集 CPU、内存、磁盘 I/O、TCP 连接数 |
| GPU 指标采集 | `GpuMetricsCollector` | 通过 `nvidia-smi` 异步采集 GPU 利用率、显存、温度 |
| 异常检测 | `AnomalyDetector` | 6 条规则识别资源与服务异常，支持语义级进度停滞检测 |
| 持久化 | `MonitoringStorage` | JSONL 格式按日分文件，保留 7 天 |
| 快照模型 | `ProcessSnapshot` / `Anomaly` | 数据传输对象 |

### 1.3 监控循环时序

```
┌────────────────────────────────────────────────────────────┐
│           TrainingInferenceMonitor (单例 orchestrator)      │
│                                                            │
│   QTimer (m_tickTimer, 2000ms)                            │
│      │                                                     │
│      ▼ onTick()                                            │
│   ┌──────────────────────────────────────────────────────┐ │
│   │ 1. SystemMetricsCollector::collect()                │ │
│   │    → CPU / 内存 / 磁盘 / 网络（本进程）              │ │
│   ├──────────────────────────────────────────────────────┤ │
│   │ 2. GpuMetricsCollector::lastMetrics()               │ │
│   │    → GPU 利用率 / 显存 / 温度（异步刷新）            │ │
│   ├──────────────────────────────────────────────────────┤ │
│   │ 3. 填充训练进度 / 推理延迟 / 模型加载状态           │ │
│   ├──────────────────────────────────────────────────────┤ │
│   │ 4. AnomalyDetector::evaluate(current, previous,     │ │
│   │                              recentErrors)          │ │
│   │    → 6 条规则评估，返回异常列表                      │ │
│   ├──────────────────────────────────────────────────────┤ │
│   │ 5. MonitoringStorage::appendSnapshot()              │ │
│   │    MonitoringStorage::appendAnomaly() * N           │ │
│   ├──────────────────────────────────────────────────────┤ │
│   │ 6. 发射信号：                                        │ │
│   │    - snapshotReady(snapshot)                        │ │
│   │    - anomalyDetected(anomaly) * N                   │ │
│   └──────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

## 2. 核心类与接口

### 2.1 TrainingInferenceMonitor（监控编排器）

单例 orchestrator，协调所有监控组件。

```cpp
class TrainingInferenceMonitor : public QObject {
    Q_OBJECT
public:
    static TrainingInferenceMonitor* instance();

    void start(int intervalMs = 2000);   // 启动监控循环
    void stop();

    // 业务模块上报接口
    void recordTrainingProgress(const TrainingProgressDetail& detail);
    void recordTrainingProgress(double progress, const QString& status);  // 兼容旧接口
    void recordInferenceLatency(qint64 ms);
    void recordModelLoadStatus(int loadedCount, const QString& lastError);
    void recordServerHealth(bool reachable, qint64 latencyMs,
                            quint32 pid = 0, double cpuPercent = -1.0);

signals:
    void snapshotReady(const QDV::ProcessSnapshot& snapshot);
    void anomalyDetected(const QDV::Anomaly& anomaly);
};
```

**关键设计要点**：

- **单例 + 多互斥锁**：每个业务上报通道独立互斥锁（`m_progressMutex` / `m_inferenceMutex` / `m_modelMutex` / `m_serverMutex` / `m_gpuMutex`），避免上报阻塞采集。
- **推理性能窗口**：保留近 60 秒（`INFERENCE_WINDOW_MS = 60000`）的推理延迟记录，计算吞吐量（次/分钟）与平均延迟。
- **错误缓存**：从 `Logger` 获取 `recentErrors`，作为异常检测规则 5（错误率突增）的输入。
- **GPU 异步采集**：`GpuMetricsCollector` 在独立 `QProcess` 中调用 `nvidia-smi`，通过 `metricsUpdated` 信号回传，避免阻塞采集线程。

### 2.2 SystemMetricsCollector（系统指标采集器）

基于 Windows API 采集本进程资源指标。

```cpp
class SystemMetricsCollector {
public:
    ProcessSnapshot collect();   // 单次采集，返回带 CPU% 的快照
private:
    struct RawCounters {
        quint64 processKernelTime;
        quint64 processUserTime;
        quint64 systemIdleTime;
        quint64 systemKernelTime;
        quint64 systemUserTime;
        quint64 workingSetBytes;       // 工作集（物理内存）
        quint64 privateBytes;          // 私有内存
        quint64 diskReadBytes;
        quint64 diskWriteBytes;
        int tcpConnectionCount;
        qint64 timestamp;
    };
    RawCounters m_prev;                // 上一次采样（用于差值计算）
    bool m_hasPrev = false;
    double calculateCpuPercent(const RawCounters& prev,
                                const RawCounters& curr) const;
};
```

**采集原理**：

- **CPU 占用率**：通过两次采样的 `processKernelTime + processUserTime` 差值除以 `systemKernelTime + systemUserTime + systemIdleTime` 差值，得到本进程占整个系统的 CPU 百分比（非核心数倍数）。
- **内存**：`workingSetBytes`（工作集）与 `privateBytes`（私有内存）双指标。
- **磁盘 I/O**：通过 `GetProcessIoCounters` 获取累计字节数，差值即为单周期 I/O 量。
- **TCP 连接数**：通过 `iphlpapi` 枚举 `GetTcpTable` 统计本进程的 TCP 连接数。
- **Windows 平台依赖**：链接 `iphlpapi` 与 `psapi` 库（见 CMakeLists.txt）。

### 2.3 GpuMetricsCollector（GPU 指标采集器）

基于 `nvidia-smi` 异步采集 GPU 指标。

```cpp
class GpuMetricsCollector : public QObject {
    Q_OBJECT
public:
    void start(int intervalMs = 2000);
    void stop();
    GpuMetrics lastMetrics() const;

signals:
    void metricsUpdated(const QDV::GpuMetrics& metrics);
};

struct GpuMetrics {
    bool available = false;          // 是否成功采集
    QString name;                    // GPU 名称
    int utilizationPercent = 0;      // 利用率 0-100
    int memoryUsedMB = 0;
    int memoryTotalMB = 0;
    int temperatureC = 0;
    QString error;                   // 失败时的简短错误
};
```

**关键设计要点**：

- **单卡监控**：取索引 0 的 GPU（`--query-gpu=...` 命令行指定单卡）。
- **异步非阻塞**：通过 `QProcess` 异步执行 `nvidia-smi`，避免阻塞采集线程。
- **降级容错**：NVIDIA 驱动/硬件不存在时 `available=false`，调用方可显示 `"--"`。
- **重入保护**：`m_busy` 标志防止上一次 `nvidia-smi` 未结束时再次启动。
- **解析失败容错**：`nvidia-smi` 输出格式异常时记录错误，不更新 `m_lastMetrics`。

### 2.4 AnomalyDetector（异常检测器）

基于规则引擎识别资源与服务异常。

```cpp
class AnomalyDetector {
public:
    QList<Anomaly> evaluate(const ProcessSnapshot& current,
                            const ProcessSnapshot& previous,
                            const QList<Logger::ErrorRecord>& recentErrors);

    // 阈值配置
    void setCpuThreshold(double percent, int consecutiveSamples);
    void setMemoryThreshold(quint64 bytes);
    void setDiskIoThreshold(quint64 bytesPerSample);
    void setLatencyThreshold(qint64 ms);
    void setErrorRateThreshold(int count, int seconds);
    void setProgressStallThreshold(int seconds);   // 0=禁用
};
```

### 2.5 MonitoringStorage（持久化）

JSONL 格式按日分文件持久化监控数据。

```cpp
class MonitoringStorage {
public:
    explicit MonitoringStorage(const QString& baseDir);
    void appendSnapshot(const ProcessSnapshot& snapshot);
    void appendAnomaly(const Anomaly& anomaly);
    void cleanupOldFiles(int keepDays = 7);
};
```

## 3. 数据流

### 3.1 监控采集主循环

```
[QTimer 触发 onTick (2000ms)]
      │
      ▼
[SystemMetricsCollector::collect()]
      │
      ├── 计算本进程 CPU%（差值法）
      ├── 读取 workingSetBytes / privateBytes
      ├── 计算单周期磁盘 I/O 差值
      └── 统计 TCP 连接数
      │
      ▼
[合并 GPU 指标 m_lastGpuMetrics]
      │
      ▼
[填充业务上报字段]
      ├── 训练进度（m_lastTrainingDetail，加锁读取）
      ├── 推理性能（m_inferenceLatencies 滑动窗口聚合）
      ├── 模型加载状态（m_loadedModelCount / m_lastModelLoadError）
      └── 训练服务健康（m_serverReachable / m_serverLatencyMs）
      │
      ▼
[AnomalyDetector::evaluate(current, previous, recentErrors)]
      │
      ├── 规则1：CPU 持续高占用（连续 N 次 > 阈值）
      ├── 规则2：内存高占用（> 阈值）
      ├── 规则3：磁盘 I/O 突增（单周期 > 阈值）
      ├── 规则4：训练服务不可达 / 延迟过高
      ├── 规则5：错误率突增（窗口内 Error/Critical > 阈值）
      └── 规则6：训练进度停滞（progress 在 N 秒内无变化）
      │
      ▼
[MonitoringStorage 持久化]
      ├── appendSnapshot() → {date}_metrics.jsonl
      └── appendAnomaly() * N → {date}_anomalies.jsonl
      │
      ▼
[信号上报 UI]
      ├── snapshotReady(snapshot)
      └── anomalyDetected(anomaly) * N
```

### 3.2 业务上报流程

```
[业务模块（TrainingBridge / InferenceEngine / ModelManager）]
      │
      ▼
[TrainingInferenceMonitor 单例接口]
      ├── recordTrainingProgress(detail)  ──► m_progressMutex
      ├── recordInferenceLatency(ms)      ──► m_inferenceMutex
      ├── recordModelLoadStatus(...)      ──► m_modelMutex
      └── recordServerHealth(...)         ──► m_serverMutex
      │
      ▼
[下一次 onTick 时被读取并填充到快照]
```

## 6. 安全考虑

### 6.1 异常检测规则详述

#### 规则 1：CPU 持续高占用

- **触发条件**：CPU 占用率连续 `m_cpuConsecutiveSamples` 次超过 `m_cpuThresholdPercent`。
- **设计意图**：避免单次峰值误报，要求持续高位才告警。
- **状态管理**：`m_highCpuCount` 累加器，CPU 回落到阈值以下时复位为 0。

#### 规则 2：内存高占用

- **触发条件**：`workingSetBytes > m_memoryThresholdBytes`。
- **设计意图**：工作集反映实际占用的物理内存，是 OOM 风险的早期信号。

#### 规则 3：磁盘 I/O 突增

- **触发条件**：单周期内 `diskReadBytes + diskWriteBytes` 差值超过 `m_diskIoThresholdBytes`。
- **设计意图**：异常的 I/O 突增可能源于日志风暴、缓存失效或磁盘故障。

#### 规则 4：训练服务健康

- **不可达**（`error` 级别）：服务进程崩溃或网络中断。
- **延迟过高**（`warning` 级别）：超过 `m_latencyThresholdMs`，可能是服务过载。

#### 规则 5：错误率突增

- **触发条件**：在 `m_errorRateThresholdSeconds` 窗口内，`Logger::Error` + `Logger::Critical` 记录数超过 `m_errorRateThresholdCount`。
- **设计意图**：日志错误率是服务异常的强信号，常先于资源指标异常。

#### 规则 6：训练进度停滞（语义级检测）

- **触发条件**：服务在线（`serverReachable`）、任务 `running`、`progress` 在 `m_progressStallThresholdSeconds` 秒内变化不超过 0.01。
- **设计意图**：检测训练回调未注册、trainer 内部异常、GPU/CPU 训练死锁等"服务正常但实际异常"的语义级异常。
- **告警去重**：`m_progressStallAlerted` 标志保证同一停滞周期内仅告警一次，避免每 2 秒重复刷屏。
- **状态复位**：progress 真正变化时复位 `m_progressStallAlerted`；任务非 running 状态时重置所有追踪变量。

### 6.2 持久化安全

- **互斥锁保护**：所有文件操作通过 `m_mutex` 串行化，避免并发写入损坏文件。
- **追加模式**：使用 `QIODevice::Append` 模式，不会覆盖已有数据。
- **日期滚动**：跨日时自动切换文件，并触发旧文件清理。
- **失败静默**：文件打开失败时不抛异常，仅返回（避免监控子系统故障影响主业务）。

### 6.3 单例线程安全

- `TrainingInferenceMonitor::instance()` 通过 `s_instanceMutex` 保护，避免多线程首次访问时的竞态。
- 业务上报接口均通过独立互斥锁保护共享状态，避免上报阻塞采集主循环。

### 6.4 GPU 采集容错

- `nvidia-smi` 不存在或调用失败时 `available=false`，不影响主循环。
- 解析失败保留上次有效指标，避免指标抖动。
- `m_busy` 标志防止重入，避免 `QProcess` 资源泄漏。

## 7. 后续改进计划

### 7.1 已识别的待改进项

1. **跨平台支持**：`SystemMetricsCollector` 当前仅支持 Windows API，需补充 Linux（`/proc` 文件系统）与 macOS（`mach` API）实现。
2. **告警去抖动**：当前部分规则（如内存、磁盘 I/O）每次评估都会触发，可考虑引入冷却期机制。
3. **告警通道扩展**：当前仅通过 Qt 信号上报 UI，可扩展邮件 / Webhook / 企业微信通知。
4. **历史数据查询接口**：`MonitoringStorage` 当前仅支持写入，缺少查询 API，UI 难以回放历史趋势。
5. **指标聚合降采样**：长期监控数据未做降采样，7 天后文件可能较大。可按小时 / 天聚合。
6. **GPU 多卡支持**：当前仅采集索引 0 的 GPU，多卡场景下需扩展为列表采集。
7. **训练服务 HTTP 轮询**：当前 `recordServerHealth` 由调用方主动上报，未实现 HTTP 轮询逻辑。

### 7.2 建议的演进方向

- **Prometheus 集成**：将监控数据导出为 Prometheus 格式，接入 Grafana 仪表盘。
- **分布式追踪**：引入 OpenTelemetry，支持跨进程调用链追踪。
- **异常根因分析**：基于历史数据训练异常预测模型，从"阈值告警"升级为"根因定位"。
- **自适应阈值**：根据历史数据动态调整阈值，避免固定阈值导致的误报/漏报。
