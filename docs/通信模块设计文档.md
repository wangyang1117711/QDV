# 通信模块设计文档

> 版本：v2.8.0 | 更新日期：2026-07-22

## 1. 架构概述

通信模块是 QDetectVision 与外部设备（PLC、上位机、传感器、执行器）交互的统一通道，提供 TCP 网络通信、串口通信、数字量 IO 控制三类基础通信能力。模块以静态库 `Communication` 形式构建，所有类均继承自 `QObject`，通过 Qt 信号槽机制解耦收发逻辑。

### 1.1 模块定位

- **所属层级**：基础设施层（位于 `Core` 之上，业务层之下）
- **构建产物**：`Communication` 静态库（`src/Communication/CMakeLists.txt`）
- **运行时依赖**：Qt6 Core / Qt6 Network

### 1.2 子系统组成

| 子系统 | 核心类 | 职责 |
| --- | --- | --- |
| TCP 通信 | `TCPCommunicator` | 基于 `QTcpSocket` 的客户端通信，支持二进制与 JSON 帧 |
| 串口通信 | `SerialCommunicator` | 串口通信封装（当前为存根实现，待接入 QtSerialPort） |
| IO 控制 | `IOController` | 数字量 IO 线路管理（输入/输出/脉冲模式） |
| 通信自检 | `CommunicationVerifier` | 通信组件可用性自检（环回测试、串口枚举、IO 校验） |

### 1.3 设计原则

1. **同步连接 + 异步收发**：`connectToHost` 阻塞等待 3 秒，数据收发通过信号异步通知。
2. **错误上下文完整化**（P1-C2 修复）：所有错误路径都通过 `Logger` 记录完整上下文（host/port/peer/errorCode/errorString），并通过 `errorOccurred` 信号上报。
3. **缓冲区保护**：TCP 接收缓冲区上限默认 10 MB，溢出时断开连接防止 OOM。
4. **存根透明化**：串口当前为存根实现，启动时一次性警告，便于上层识别"假连接"。

## 2. 核心类与接口

### 2.1 TCPCommunicator（TCP 通信）

基于 `QTcpSocket` 的 TCP 客户端封装，支持二进制帧与 JSON 帧。

```cpp
class TCPCommunicator : public QObject {
    Q_OBJECT
public:
    explicit TCPCommunicator(QObject* parent = nullptr);

    // 连接管理
    bool connectToHost(const QString& host, int port);   // 阻塞 3s 等待
    void disconnect();
    bool isConnected() const;

    // 数据发送
    bool sendData(const QByteArray& data);    // 二进制
    bool sendJson(const QJsonObject& obj);    // JSON Compact 编码

    // 缓冲区配置
    void setMaxBufferSize(qint64 maxSize);     // 默认 10 MB
    qint64 maxBufferSize() const;

signals:
    void connected();
    void disconnected();
    void dataReceived(const QByteArray& data);
    void errorOccurred(const QString& error);
    void bufferOverflow(qint64 receivedSize, qint64 maxSize);
};
```

**关键设计要点**：

- **参数校验**（P1-C2 修复）：`connectToHost` 在 host 为空或端口非法时立即返回 false 并记录详细错误，避免静默失败。
- **重连保护**：若已连接，再次 `connectToHost` 会先断开旧连接。
- **写入完整性**：`sendData` 检查 `bytesWritten == data.size()`，部分写入视为失败。
- **立即 flush**：写入后调用 `m_socket->flush()` 减少发送延迟（不阻塞等待 ack）。
- **缓冲区溢出保护**：超过 `m_maxBufferSize` 时发射 `bufferOverflow` 信号、清空缓冲区并断开连接。
- **JSON 帧**：`sendJson` 使用 `QJsonDocument::Compact` 编码，无额外帧分隔符（上层需自行处理粘包）。

### 2.2 SerialCommunicator（串口通信）

串口通信封装，定义了完整的串口参数枚举，但当前为存根实现。

```cpp
class SerialCommunicator : public QObject {
    Q_OBJECT
public:
    enum BaudRate {
        Baud9600 = 9600, Baud19200 = 19200, Baud38400 = 38400,
        Baud57600 = 57600, Baud115200 = 115200
    };
    enum DataBits { Data5 = 5, Data6 = 6, Data7 = 7, Data8 = 8 };
    enum StopBits { StopOne = 1, StopTwo = 2 };
    enum Parity { NoParity = 0, EvenParity = 2, OddParity = 3 };

    bool open(const QString& portName,
              BaudRate baudRate = Baud115200,
              DataBits dataBits = Data8,
              StopBits stopBits = StopOne,
              Parity parity = NoParity);
    void close();
    bool isOpen() const { return m_isOpen; }

    bool configure(const QString& portName,
                   int baudRate, int dataBits,
                   int stopBits, int parity);
    bool send(const QByteArray& data);
    bool send(const QString& text);

signals:
    void dataReceived(const QByteArray& data);
    void errorOccurred(const QString& error);
    void connectionStatusChanged(bool connected);
};
```

**当前实现状态**（P1-C8 已知限制）：

- `open()` 是存根实现，仅更新内部状态，不实际打开串口设备。
- `send()` 是存根实现，数据仅追加到 `m_txBuffer`，未实际写入串口。
- 启动时一次性警告：`"SerialCommunicator::open: 使用存根实现，未实际打开串口设备"`。
- 计划在 M8 里程碑接入 QtSerialPort 后端。

### 2.3 IOController（数字量 IO 控制）

管理数字量输入/输出线路，支持输入采样、输出置位、脉冲输出三种模式。

```cpp
class IOController : public QObject {
    Q_OBJECT
public:
    enum LineMode {
        InputMode = 0,      // 输入采样
        OutputMode = 1,      // 输出置位
        PulseOutput = 2      // 脉冲输出
    };

    bool initialize(int totalLines = 8);   // 1-32 条线路
    void shutdown();

    bool setLineMode(int lineIndex, LineMode mode);
    LineMode lineMode(int lineIndex) const;

    bool setOutput(int lineIndex, bool high);
    bool readInput(int lineIndex, bool& state) const;
    bool sendPulse(int lineIndex, int durationMs);  // 0-10000 ms

    QMap<int, bool> readAllInputs() const;
    QMap<int, LineMode> allLineModes() const;
    int totalLines() const;

signals:
    void inputChanged(int lineIndex, bool state);
    void outputChanged(int lineIndex, bool state);
    void triggerDetected(int lineIndex);
};
```

**关键设计要点**：

- **线路数量约束**：`totalLines` 范围 1-32，超出返回 false。
- **模式保护**：对 `InputMode` 线路调用 `setOutput` 会失败并记录错误日志。
- **脉冲约束**：`durationMs` 范围 0-10000 ms，且线路必须处于 `PulseOutput` 模式。
- **关闭时复位**：`shutdown()` 会强制将 line 0 输出置低，保证执行器安全。

### 2.4 CommunicationVerifier（通信自检）

提供通信组件可用性自检能力，用于启动诊断与故障定位。

```cpp
class CommunicationVerifier : public QObject {
    Q_OBJECT
public:
    QList<CommVerifyResult> verifyAll();
    CommVerifyResult verifyTCPLoopback();       // TCP 环回测试
    CommVerifyResult verifySerialEnumeration(); // 串口枚举
    CommVerifyResult verifyIOController();      // IO 控制器校验

    int passedCount() const;
    int totalCount() const;
};
```

```cpp
struct CommVerifyResult {
    QString componentName;
    bool passed = false;
    QString message;
};
```

## 3. 数据流

### 3.1 TCP 数据收发流程

```
[业务层调用 connectToHost(host, port)]
      │
      ▼
[参数校验] ── 失败 ──► [Logger::error + errorOccurred 信号] ──► return false
      │ 成功
      ▼
[若已连接，先 disconnect]
      │
      ▼
[QTcpSocket::connectToHost + waitForConnected(3000)]
      │
      ├── 失败 ──► [Logger::error + errorOccurred 信号] ──► return false
      │
      └── 成功 ──► [connected 信号] ──► return true
                                    │
                                    ▼
                            [业务层 sendData/sendJson]
                                    │
                                    ▼
                          [QTcpSocket::write + flush]
                                    │
                                    ▼
                          [对端响应] ──► onReadyRead 触发
                                    │
                                    ▼
                          [缓冲区溢出检查]
                                    │
                                    ├── 溢出 ──► [bufferOverflow + errorOccurred
                                    │            + 清空缓冲区 + disconnect]
                                    │
                                    └── 正常 ──► [dataReceived 信号]
```

### 3.2 IO 控制流程

```
[IOController::initialize(totalLines)]
      │
      ▼
[全部线路默认 InputMode, 输出 false]
      │
      ▼
[setLineMode(lineIndex, mode)] ── 配置每条线路工作模式
      │
      ├── 输入线路 ──► readInput(lineIndex, &state)
      │                 └──► inputChanged 信号
      │
      ├── 输出线路 ──► setOutput(lineIndex, high)
      │                 └──► outputChanged 信号
      │
      └── 脉冲线路 ──► sendPulse(lineIndex, durationMs)
                        └──► setOutput(true) + 延时复位
```

## 6. 安全考虑

### 6.1 缓冲区溢出防护

- TCP 接收缓冲区硬上限 10 MB，溢出时立即断开连接并上报 `bufferOverflow` 信号，防止 OOM 攻击。

### 6.2 错误上下文完整化（P1-C2 修复）

- 所有错误路径记录完整上下文：host/port/peerAddress/peerPort/socketError/errorString/errorCode。
- 通过 `Logger` 与 `errorOccurred` 双通道上报，便于上层实时感知与事后追溯。

### 6.3 IO 输出安全

- `shutdown()` 强制将 line 0 置低，避免异常退出时执行器保持危险状态。
- 对 `InputMode` 线路拒绝 `setOutput` 调用，防止模式误用。
- 脉冲时长上限 10 秒，避免长时间激活执行器。

### 6.4 存根透明化（P1-C8 修复）

- 串口存根实现启动时一次性警告，便于上层识别"假连接"状态。
- 上层可通过 `CommunicationVerifier::verifySerialEnumeration()` 识别实际能力。

### 6.5 TLS 支持计划（TODO）

- 当前 TCP 通信为明文传输，未集成 QSslSocket。
- 计划在后续版本通过 `QSslSocket` 替换 `QTcpSocket`，支持 TLS 1.2+ 加密通信。
- 应用场景：跨网段通信、与云端 MES/ERP 系统对接。

## 7. 后续改进计划

### 7.1 已识别的待改进项

1. **串口实际接入**：当前 `SerialCommunicator` 为存根，需在 M8 里程碑接入 QtSerialPort，实现真实的串口读写。
2. **TLS 加密通信**：当前 TCP 为明文，需引入 `QSslSocket` 支持 TLS 1.2+，用于跨网段安全通信。
3. **协议帧分隔**：当前 `sendJson` 无帧分隔符，上层需自行处理粘包。可考虑引入长度前缀或自定义分隔符协议。
4. **重连机制**：当前断线后需上层手动重连，可加入指数退避自动重连策略。
5. **IO 硬件抽象**：当前 `IOController` 为软件模拟，需后续接入实际 IO 板卡驱动（如 Advantech PCI-1753 等）。
6. **脉冲输出异步化**：当前 `sendPulse` 仅置高，未实现延时自动复位，需引入 `QTimer` 异步复位。

### 7.2 建议的演进方向

- **统一协议层**：抽象出 `IProtocol` 接口，支持 Modbus TCP/RTU、Profinet、OPC UA 等工业协议。
- **通信链路聚合**：支持多链路冗余，主链路故障自动切换备链路。
- **配置热加载**：支持运行时修改通信参数而不重启服务。
- **通信质量监控**：集成 `Monitoring` 模块，统计丢包率、延迟、重连次数等指标。
