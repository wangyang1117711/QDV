# 数据库模块设计文档

> 版本：v2.8.0 | 更新日期：2026-07-22

## 1. 架构概述

数据库模块是 QDetectVision 检测结果持久化的核心，基于 SQLite 提供轻量级嵌入式存储能力。模块以静态库 `Database` 形式构建，采用双层架构：底层 `ResultDatabase` 封装 SQL 操作，上层 `DatabaseIntegrator` 对接业务域 `DetectionStats` 数据结构。两个类均为单例，通过 Qt 信号槽与业务模块解耦。

### 1.1 模块定位

- **所属层级**：数据持久化层（位于 `Core` 之上，业务层之下）
- **构建产物**：`Database` 静态库（`src/Database/CMakeLists.txt`）
- **运行时依赖**：Qt6 Core / Qt6 Sql（QSQLITE 驱动）

### 1.2 子系统组成

| 子系统 | 核心类 | 职责 |
| --- | --- | --- |
| 结果数据库 | `ResultDatabase` | 单例，封装 SQLite 表结构、CRUD、批量插入、查询 |
| 数据库集成器 | `DatabaseIntegrator` | 单例，对接 `DetectionStats`，提供业务友好的保存/加载接口 |

### 1.3 设计原则

1. **嵌入式 SQLite**：无需独立数据库服务进程，数据库文件随程序部署。
2. **单例 + 递归互斥锁**：`QRecursiveMutex` 允许 `open/createTables`、`deleteResults/countResults` 嵌套加锁。
3. **批量事务优化**（P1-C5 修复）：批量插入采用 `BEGIN TRANSACTION + N×INSERT + COMMIT`，性能提升约 10 倍。
4. **SQL 错误上下文化**（P1-C15 修复）：所有 SQL 失败路径记录实际错误信息（`lastError().text()`、`driverText()`），便于排查。
5. **安全删除**：`requireConfirmation=true` 时阻止无 schemeId 的大批量删除（>10 条）。

## 2. 核心类与接口

### 2.1 ResultDatabase（结果数据库）

封装 SQLite 表结构与 CRUD 操作的单例类。

```cpp
class ResultDatabase : public QObject {
    Q_OBJECT
public:
    static ResultDatabase* instance();

    bool open(const QString& dbPath = "./data/qdv_results.db");
    void close();

    // 单条插入（自动提交）
    bool insertResult(const QString& schemeId, const QString& schemeName,
                      bool ok, double score, const QString& imagePath,
                      const QString& timestamp = QString());

    // 批量插入（事务包装，10x 性能）
    struct ResultItem {
        QString schemeId;
        QString schemeName;
        bool ok;
        double score;
        QString imagePath;
        QString timestamp;
    };
    bool insertResultsBatch(const QList<ResultItem>& items);

    // 查询（支持按 schemeId + 时间范围过滤）
    QList<QMap<QString, QVariant>> queryResults(
        const QString& schemeId = QString(),
        const QString& startTime = QString(),
        const QString& endTime = QString());

    // 删除（requireConfirmation=true 时阻止批量删除）
    bool deleteResults(const QString& schemeId, bool requireConfirmation = true);

    int getResultCount(const QString& schemeId = QString());

signals:
    void resultInserted(bool success);
    void resultsDeleted(int count);
};
```

### 2.2 DatabaseIntegrator（数据库集成器）

对接业务域 `DetectionStats` 的单例集成层。

```cpp
class DatabaseIntegrator : public QObject {
    Q_OBJECT
public:
    static DatabaseIntegrator* instance();

    bool initialize(const QString& dbPath = "./data/qdv_results.db");
    void shutdown();

    // 业务友好接口
    bool saveDetectionResult(const QString& schemeId, const QString& schemeName,
                             const DetectionStats& stats);
    bool saveDetectionResult(const QString& schemeId, const QString& schemeName,
                             bool ok, double score, const QString& imagePath = QString());

    DetectionStats loadStatsForScheme(const QString& schemeId);

signals:
    void resultSaved(bool success);
    void errorOccurred(const QString& error);
};
```

**关键设计要点**：

- **重载保存接口**：`saveDetectionResult` 提供两种重载——一种接受 `DetectionStats` 业务对象，一种接受原始字段（ok / score / imagePath）。
- **统计聚合**：`loadStatsForScheme` 从 `results` 表读取后聚合 `passed / failed / passRate` 字段。
- **错误信号双通道**：失败时同时发射 `resultSaved(false)` 与 `errorOccurred(error)`，便于上层区分"操作完成"与"操作失败"事件。

## 3. 数据流

### 3.1 检测结果保存流程

```
[业务模块（检测主循环）]
      │
      ▼
[DatabaseIntegrator::saveDetectionResult]
      │
      ├── 方式1：传入 DetectionStats ──► 转换为 ok/score
      │
      └── 方式2：直接传入 ok/score/imagePath
      │
      ▼
[ResultDatabase::insertResult]
      │
      ▼
[QRecursiveMutex 加锁]
      │
      ▼
[SQL INSERT，参数化绑定]
      │
      ├── 失败 ──► [Logger::error + resultInserted(false)] ──► return false
      │
      └── 成功 ──► [resultInserted(true)] ──► return true
                                    │
                                    ▼
                          [DatabaseIntegrator::resultSaved 信号]
```

### 3.2 批量插入流程（P1-C5 优化）

```
[业务模块批量保存 N 条结果]
      │
      ▼
[ResultDatabase::insertResultsBatch]
      │
      ▼
[BEGIN TRANSACTION] ── 失败 ──► Logger::error + return false
      │
      ▼
[循环 N 次：参数化 INSERT]
      │
      ├── 任一失败 ──► [Logger::error + ROLLBACK] ──► return false
      │                 └──► 失败时 ROLLBACK 也失败再次 Logger::error
      │
      └── 全部成功
            │
            ▼
      [COMMIT] ── 失败 ──► [ROLLBACK + Logger::error] ──► return false
            │
            ▼
      [Logger::info "N items committed"]
      [resultInserted(true)] ──► return true
```

### 3.3 查询流程

```
[业务模块]
      │
      ▼
[ResultDatabase::queryResults(schemeId, startTime, endTime)]
      │
      ▼
[动态拼装 SQL]
  SELECT * FROM results WHERE 1=1
    [AND scheme_id = :scheme_id]      ← 当 schemeId 非空
    [AND timestamp >= :start_time]   ← 当 startTime 非空
    [AND timestamp <= :end_time]     ← 当 endTime 非空
  ORDER BY timestamp DESC LIMIT 1000
      │
      ▼
[QSqlQuery::exec]
      │
      ▼
[逐行读取 → QMap<QString, QVariant>]
      │
      ▼
[返回 QList<QMap<QString, QVariant>>]
```

## 6. 安全考虑

### 6.1 SQL 注入防护

- **参数化查询**：所有用户输入（`schemeId`、`startTime`、`endTime`、`imagePath` 等）通过 `bindValue` 参数化绑定，避免 SQL 注入。
- **动态 SQL 拼接安全**：`queryResults` 中的 SQL 拼接仅基于"是否非空"添加占位符，实际值仍通过 `bindValue` 绑定。

### 6.2 数据完整性

- **批量插入事务性**（P1-C5 修复）：`insertResultsBatch` 使用 `BEGIN TRANSACTION + COMMIT`，任一条失败 `ROLLBACK` 整批，保证原子性。
- **ROLLBACK 失败处理**：若 ROLLBACK 本身失败，记录额外错误日志，便于事后追溯。
- **COMMIT 失败处理**：COMMIT 失败时尝试 ROLLBACK 并返回 false，避免数据不一致。

### 6.3 并发安全

- **递归互斥锁**：`QRecursiveMutex` 允许 `open/createTables`、`deleteResults/countResults` 等嵌套加锁场景。
- **单例线程安全**：`instance()` 通过局部 `QMutex` 保护首次创建，避免多线程竞态。

### 6.4 安全删除保护

- **批量删除拦截**：`requireConfirmation=true` 且无 `schemeId` 时，若待删除记录数 > 10，拒绝操作并记录警告日志。
- **可配置开关**：`m_safeDeleteEnabled` 允许在可信场景下禁用安全保护。

### 6.5 错误上下文化（P1-C15 修复）

- **数据库打开失败**：记录 `dbPath` + `lastError().text()` + `driverText()`。
- **表创建失败**：记录 `query.lastError().text()`。
- **索引创建失败**：记录警告（不阻断，索引非关键路径）。
- **插入失败**：批量插入失败时记录"第 N/M 条"上下文，便于定位问题数据。

### 6.6 加密方案（当前状态）

- **当前状态**：SQLite 数据库文件为明文存储，未启用 SQLCipher 加密。
- **风险点**：检测结果（含图像路径、schemeId、score）以明文存储，若部署在不可信环境存在泄露风险。
- **后续计划**：见第 7 节"后续改进计划"。

## 7. 后续改进计划

### 7.1 已识别的待改进项

1. **数据库加密**：当前为明文 SQLite，需集成 SQLCipher 启用 AES-256 透明加密。Qt Sql 模块支持 SQLCipher 驱动，可通过 `setPassword()` 设置密钥。
2. **表结构扩展**：当前 `results` 表仅存储基本字段，缺少：
   - 缺陷类型分类（`defect_type`）
   - 检测设备信息（`device_id` / `device_name`）
   - 操作员信息（`operator_id`）
   - 详细缺陷标注（JSON 字段，存储 bbox / polygon）
3. **数据归档策略**：缺少自动归档机制，长期运行时 `results` 表会无限增长。可考虑按月分表或自动归档到压缩文件。
4. **查询接口扩展**：
   - 缺少分页查询（`LIMIT offset, count`）
   - 缺少按 `ok` 状态过滤（仅查询失败记录）
   - 缺少按 `score` 范围过滤
5. **统计聚合 SQL 化**：`loadStatsForScheme` 当前读取所有记录到内存再聚合，应改为 SQL 聚合（`SELECT COUNT(*) WHERE ok=1`）。
6. **连接池**：当前单连接单互斥锁，高并发场景下可能成为瓶颈。可引入连接池支持并发查询。
7. **数据库迁移框架**：缺少 schema 版本管理，未来表结构变更需要迁移机制（类似 Alembic / Flyway）。
8. **备份与恢复**：缺少自动备份机制，可基于 SQLite Online Backup API 实现。

### 7.2 建议的演进方向

- **多数据库后端**：抽象 `IResultRepository` 接口，支持切换 PostgreSQL / MySQL，用于多机部署场景。
- **时序数据扩展**：对于长期监控类数据（如检测趋势），可考虑 TimescaleDB 或 InfluxDB 时序数据库。
- **数据导出 API**：提供 CSV / Excel / JSON 导出接口，与 `Export` 模块协同。
- **审计日志**：记录所有删除/修改操作的审计日志，满足工业场景合规要求。
