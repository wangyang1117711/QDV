# 导出模块设计文档

> 版本：v2.8.0 | 更新日期：2026-07-22

## 1. 架构概述

导出模块是 QDetectVision 算子流程工程化交付的核心，负责将编辑器中可视化编排的算子流程（pipeline）打包为可独立部署的产物包，包含 DLL/EXE/Python wrapper、运行时依赖、方案 JSON、接口文档、调用示例与 manifest。模块以静态库 `QDVExport` 形式构建，采用异步编排模式（`QtConcurrent::run + QFutureWatcher`），通过门面类 `SchemeExporter` 统一对外暴露能力。

### 1.1 模块定位

- **所属层级**：业务服务层（被 `UI` 模块调用，依赖 `Export` 子模块与 OpenCV）
- **构建产物**：`QDVExport` 静态库（`src/Export/CMakeLists.txt`）
- **运行时依赖**：Qt6 Core / Qt6 Gui / Qt6 Concurrent / OpenCV

### 1.2 子系统组成

| 子系统 | 核心类 | 职责 |
| --- | --- | --- |
| 编排门面 | `SchemeExporter` | 异步导出流程编排，对外暴露 `exportAsync` |
| 配置 | `ExportConfig` | 导出参数数据结构 + 自检 `isValid()` |
| 包结构 | `ExportPackage` | 产物包目录与文件名常量 |
| 模板定位 | `TemplateLocator` | 定位预编译模板（DLL/EXE/头文件） |
| 运行时打包 | `RuntimePackager` | 收集 OpenCV/Qt 运行时依赖 DLL |
| 接口文档 | `InterfaceDocGenerator` | 生成 Markdown 接口文档与使用说明 |
| 示例代码 | `ExampleCodeGenerator` | 生成 C++/Python 调用示例代码 |

### 1.3 产物包结构

```

├── bin/
│   ├── QDVPipeline.dll           # 算子流程动态库
│   ├── QDVPipelineRun.exe        # 命令行运行器

│       └── platforms/qwindows.dll

├── models/                        # AI 模型文件（如有 AI 算子）
```

### 1.4 设计原则

1. **异步非阻塞**：`exportAsync` 立即返回，通过 `exportProgress` / `exportFinished` 信号通知结果，避免阻塞 UI 线程。
2. **门面模式**：`SchemeExporter` 作为唯一入口，内部协调 7 个子组件。
3. **模板预编译**：模板 DLL/EXE/头文件在主项目构建时预先生成，导出时仅复制。
4. **配置自检**：`ExportConfig::isValid()` 在导出前同步校验，避免无效配置进入异步流程。
5. **可观测性**：每个步骤发射 `exportProgress(percent)`，UI 可实时显示进度条。

## 2. 核心类与接口

### 2.1 SchemeExporter（导出编排器）

```cpp
class SchemeExporter : public QObject {
    Q_OBJECT
public:
    explicit SchemeExporter(QObject* parent = nullptr);

    /// 异步导出（立即返回，通过信号通知结果）
    /// @param config 导出配置
    /// @param nodes 当前方案节点（QVariantList of QVariantMap）
    /// @param connections 当前方案连边
    void exportAsync(const ExportConfig& config,
                     const QVariantList& nodes,
                     const QVariantList& connections);

    bool isBusy() const;
    void cancel();   // 尽力中止，已生成文件不回滚

signals:
    void exportProgress(int percent);                          // 0-100
    void exportFinished(bool success, const QString& message); // message 含产物路径
    void confirmOverwriteRequested(const QString& existingPath);
    void errorOccurred(const QString& message);
};
```

**关键设计要点**：

- **同步预校验**：`exportAsync` 在异步启动前同步执行 `config.isValid()`、`nodes.isEmpty()`、`TemplateLocator::checkTemplates()`，失败立即发射 `errorOccurred`。
- **数据拷贝隔离**：worker 线程捕获 `cfgCopy` / `nodesCopy` / `connsCopy`，避免直接持有 Qt 对象引用导致线程安全问题。
- **取消能力受限**：`QtConcurrent::run` 不支持取消，`cancel()` 仅标记意图，实际取消需要将 `doExport` 拆分为可中断步骤（TODO）。
- **析构等待**：析构时若仍 busy，调用 `m_watcher->waitForFinished()` 等待 worker 完成，避免悬挂线程。

### 2.2 ExportConfig（导出配置）

```cpp
struct ExportConfig {
    // 基础项
    bool exportDll = true;
    bool exportExe = true;
    bool exportPython = true;
    QString exportName;        // 导出包名（目录名）
    QString interfaceName;     // 接口名（Python 类名/C++ 类名/文档命名）
    QString outputPath;        // 输出根目录（默认 D:\exports\）

    // 额外项
    bool embedScheme = true;   // 方案嵌入 DLL/EXE 还是外置文件
    bool generateDoc = true;        // 生成 Markdown 接口文档
    bool generateExamples = true;   // 生成调用示例代码
    QString version = "1.0.0";      // SemVer
    QString author;
    QString description;

    // 自检（可选，不阻断导出）
    bool runSelfCheck = false;
    QString selfCheckSampleImage;

    bool isValid(QString* err = nullptr) const;
};
```

**校验规则**（`isValid`）：

| 检查项 | 失败提示 |
| --- | --- |
| `exportName` 非空 | 导出名称不能为空 |
| `interfaceName` 非空 | 接口名称不能为空 |
| `outputPath` 非空 | 输出路径不能为空 |
| 至少一种导出格式 | 至少选择一种导出格式（DLL/EXE/Python） |

### 2.5 RuntimePackager（运行时打包器）

```cpp
class RuntimePackager {
public:
    /// 收集运行时依赖到目标目录
    /// @param destDir 目标目录（通常是 bin/qdv_runtime/）
    /// @param copiedFiles 返回已复制的文件列表
    /// @return true=成功；false=部分失败
    static bool package(const QString& destDir,
                        QStringList* copiedFiles = nullptr,
                        QString* err = nullptr);
private:
    static bool copyFile(const QString& src, const QString& destDir, ...);
    static QStringList findOpencvDlls();          // OpenCV 运行时
    static QStringList findQtDlls();             // Qt 基础 DLL（不含 QML）
    static QStringList findQtPlatformPlugins();   // Qt platforms 插件
};
```

**关键设计要点**：

- **模仿 windeployqt**：手动复制必要的运行时 DLL，精简运行时不含 QML。
- **OpenCV 路径**：编译定义 `OPENCV_BIN_DIR="D:/opencv/build_mingw/bin"`。
- **幂等复制**：若文件已存在则跳过，避免重复复制。

## 3. 数据流

### 3.1 异步导出主流程

```
[UI 调用 exporter.exportAsync(config, nodes, connections)]
      │
      ▼
[同步预校验]
  ├── config.isValid() ── 失败 ──► errorOccurred ──► return
  ├── !nodes.isEmpty() ── 失败 ──► errorOccurred ──► return
  └── TemplateLocator::checkTemplates() ── 失败 ──► errorOccurred ──► return
      │
      ▼
[m_busy = true, emit exportProgress(5)]
      │
      ▼
[QtConcurrent::run → doExport(cfgCopy, nodesCopy, connsCopy)]
      │
      ▼ (worker 线程)
[1. 创建产物目录] exportProgress(15)
      │
      ▼
[2. 复制模板二进制（DLL/EXE/头文件）] exportProgress(35~45)
      │
      ▼
[3. 收集运行时依赖 RuntimePackager::package] exportProgress(60)
      │
      ▼
[4. 序列化方案 serializeScheme] exportProgress(70)
      │
      ▼
[5. 检测 AI 算子] (AiClassify / Dl* / Yolo*)
      │
      ▼
[6. 生成 Python wrapper] exportProgress(80)
      │
      ▼
[7. 生成接口文档 + 使用说明] exportProgress(88)
      │
      ▼
[8. 生成 C++/Python 调用示例] exportProgress(95)
      │
      ▼
[9. 写入 manifest.json] exportProgress(100)
      │
      ▼ (主线程)
[onExportFinished → emit exportFinished(ok, message)]
```

## 6. 安全考虑

### 6.1 配置自检

- `ExportConfig::isValid()` 在导出前强制校验，避免无效配置进入异步流程导致半成品产物。
- 模板存在性检查 `TemplateLocator::checkTemplates()` 避免运行时缺失模板。

### 6.2 线程安全

- worker 线程通过值拷贝捕获 `cfgCopy` / `nodesCopy` / `connsCopy`，避免直接访问 Qt 对象导致线程安全问题。
- 析构时 `waitForFinished()` 保证 worker 完成后再销毁，避免悬挂线程访问已释放对象。

### 6.3 文件覆盖保护

- DLL 复制时若已存在，先 `QFile::remove` 再 `QFile::copy`，避免重复导出失败。
- 提供 `confirmOverwriteRequested` 信号，UI 可在产物目录已存在时弹出二次确认。

### 6.4 AI 算子检测

- 通过算子类型字符串检测 AI 算子：`AiClassify` / `Dl*` / `Yolo*`。
- 检测结果记录到 manifest.json 的 `containsAi` 字段，便于部署时识别是否需要 AI 运行时。

### 6.5 取消能力（已知限制）

- 当前 `cancel()` 仅标记意图，实际取消需要将 `doExport` 拆分为可中断步骤。
- 取消后已生成的文件不回滚，调用方需自行清理。

## 7. 后续改进计划

### 7.1 已识别的待改进项

1. **取消能力完善**：`cancel()` 当前仅标记意图，需将 `doExport` 拆分为可中断步骤，支持真正的中途取消与文件回滚。
2. **增量导出**：当前每次导出都完整复制所有文件，可基于文件哈希实现增量更新，减少导出时间。
3. **CSV/JSON 数据导出**：当前模块仅支持算子流程导出，缺少检测结果 CSV/JSON 导出能力（可由 `Database` 模块协同提供数据源）。
4. **签名校验**：导出的 DLL/EXE 当前未做代码签名，部署到工业现场可能被安全软件拦截。可集成 `signtool` 自动签名。
5. **运行时依赖版本固定**：`RuntimePackager` 当前从固定路径复制 DLL，缺少版本校验，可能复制错误版本的依赖。
6. **跨平台支持**：当前仅支持 Windows（DLL/EXE），Linux/macOS 需生成 `.so` / `.dylib`。
7. **方案版本兼容性**：`pipeline.json` 当前固定 `version: 2.1.0`，缺少向后兼容性检查机制。
8. **自检能力落地**：`runSelfCheck` 配置项当前未实际实现，可基于示例图像验证导出产物可用性。

### 7.2 建议的演进方向

- **导出模板市场**：支持自定义导出模板，允许用户分享与下载模板。
- **Docker 镜像导出**：将算子流程打包为 Docker 镜像，便于云部署。
- **C# 接口支持**：当前仅支持 C++/Python 调用，可扩展 C# / Java / Go 绑定。
- **WebAssembly 支持**：将算子流程编译为 WASM，支持浏览器内运行。
- **插件化导出器**：抽象 `IExporter` 接口，支持 DLL / EXE / WASM / Docker 等多种产物格式插件化扩展。
