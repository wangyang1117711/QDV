## 一、概述

### 1.1 优化目标

本次优化旨在补齐 QDV 项目训练推理模块的 3 项关键架构缺口和 5 项功能短板，使该模块达到生产可用状态。

**三大关键缺口**：
1. **推理引擎桩实现未合并**：真实 `InferenceEngine` 实现存在于 `.pilot-worktree` 分支，主分支为桩代码（仅 clone 输入，未执行真正推理）
2. **模型管理器能力不足**：`ModelManager` 缺少 LRU 缓存、manifest 持久化、完整性校验、事务性删除等关键能力
3. **训练→推理闭环断裂**：训练完成后无法自动注册模型到推理库

**五项功能短板**：
- 缺少 YOLO 目标检测训练与推理支持
- 推理仅支持分类后处理，缺少 YOLOv5/v8 检测后处理
- 无三层缓存机制（引擎实例/推理结果/图像数据）
- 图像预览无金字塔缓存、无 Snapshot 历史、无前后对比
- 无数据集四维校验框架与 YOLO/COCO 导出

### 1.2 优化范围

本次优化覆盖 AI 推理层、训练桥接层、视觉算子层、缓存机制、UI 预览层共 5 个层次，涉及 20 个任务，分为 P0-P3 四个优先级阶段实施。

### 1.3 实施依据

- 以 `docs/训练推理模块_系统性优化方案.md` 为设计蓝图
- 以 `.trae/specs/training-inference-optimization/spec.md` 为契约规范
- 以 `.trae/specs/training-inference-optimization/tasks.md` 为任务分解
- 以 `.trae/specs/training-inference-optimization/checklist.md` 为验证检查清单

## 二、实施过程

### 2.1 P0 阶段：推理引擎修复与模型管理增强（Task 1-3）

**阶段目标**：替换推理引擎桩实现为真实 OpenCV DNN 实现，增强 ModelManager 的缓存、持久化、校验能力。

#### Task 1：合并 pilot-worktree 的 InferenceEngine 完整实现

**关键变更**：
- 将 `include/AI/InferenceEngine.h` 从桩实现替换为完整实现，新增 `Backend` 枚举、`InferenceMetrics` 结构、5 参数 `loadModel` 签名、`warmUp`/`inferBatch`/`lastMetrics`/`setBackend`/`setInferenceMode` 接口
- 将 `src/AI/InferenceEngine.cpp` 从 53 行桩代码替换为基于 `cv::dnn::readNetFromONNX` 的真实推理实现，包含预处理（resize + blobFromImage）、前向推理、后处理（分类 softmax→top5）
- 验证 `InferenceEngineAdapter.h`、`VisionClassifier.cpp`、`AiClassifyTool.cpp` 的接口兼容性（5 参数 loadModel / IInferenceEngine 接口注入）
- 确认 `CMakeLists.txt` 已链接 OpenCV dnn 模块

**技术要点**：
- `loadModel(QString, QSize, cv::Scalar, double, bool)` 支持 mean/scale/swapRB 预处理参数配置
- 推理结果 JSON 包含 `class_index`、`confidence`、`top5[]`、`latency_ms`、`backend` 字段
- `warmUp(iterations)` 使用 128 灰度虚拟图预热模型，稳定后续推理耗时

#### Task 2：增强 ModelManager 实现

**关键变更**：
- `include/AI/ModelManager.h`：存储结构从 `QMap<QString, InferenceEngine*>` 改为 `QMap` + `QList` LRU 实现（`m_accessOrder` 访问顺序列表），新增 `addCustomModel`/`removeCustomModelTransactional`/`verifyModelIntegrity`/`autoDetectModelType`/`autoDetectInputSize`/`loadManifest`/`saveManifest` 方法和 `modelsChanged` 信号
- `src/AI/ModelManager.cpp`：实现 LRU 缓存淘汰（`evictLRU`/`touch` 机制，容量 3）、manifest.json 持久化（兼容旧格式 `file_name`/`sha256`/`expected_size`）、SHA256 流式校验（1MB 缓冲区）、事务性删除（rename `.trash` 后缀 + manifest `deleted_models` 记录）、自定义模型自动识别（正则 `^(best|last)\d{14}\.(pt|onnx)$` → 640x640，否则 224x224）

**技术要点**：
- LRU 淘汰：`m_accessOrder` 列表 front=最近访问、back=最久未用，`evictLRU` 取 `takeLast` 淘汰
- SHA256 校验：`QCryptographicHash::Sha256` + 1MB 缓冲流式读取，校验失败拒绝加载
- 事务性删除：`QFile::rename` 到 `.trash` 后缀（可恢复），manifest 记录 `model_id`/`file_name`/`timestamp`/`operator`
- manifest 旧格式兼容：无 `sha256` 字段补空，无 `expected_size` 补 0，`name` 字段迁移到 `file_name`

#### Task 3：P0 阶段兼容性与单元测试验证

**关键变更**：
- 运行 `tests/AI/test_inference.cpp` 验证 InferenceEngine 推理正确性
- 运行 `tests/AI/test_model_manager.cpp` 验证 LRU 淘汰、事务性删除、SHA256 校验
- 端到端验证 AiClassifyTool 加载 resnet50.onnx 执行真实分类推理

### 2.2 P1 阶段：训练→推理闭环与 YOLO 支持（Task 4-10）

**阶段目标**：实现训练完成自动注册闭环，增加 YOLO 目标检测推理和训练支持。

#### Task 4：TrainingBridge 训练完成自动注册闭环

**关键变更**：
- `src/AI/TrainingBridge.cpp` 的 `parseAndEmitOutput` 方法中，处理 `type=="complete"` 信号时：
  - 检查 `onnx_path` 非空且文件存在（`QFile::exists`）
  - 调用 `::ModelManager::instance()->addCustomModel(onnxPath, displayName, labelsPath)` 注册模型
  - 注册成功后 `emit modelRegistered(displayName, onnxPath)` 通知 UI
  - ONNX 产物缺失场景记录警告日志，不触发注册
- `include/AI/TrainingBridge.h` 增加 `modelRegistered` 信号声明

**闭环链路**：
```
TrainingBridge 收到 complete 信号
  → 提取 onnx_path（非空且文件存在）
  → 调用 ModelManager::addCustomModel(onnxPath, displayName, labelsPath)
    → 复制 ONNX/labels 到 models/ 目录
    → 流式计算 SHA256
    → 更新 manifest.json 并保存
    → emit modelRegistered + emit modelsChanged
  → TrainingBridge emit modelRegistered 通知 UI
  → emit logOutput("模型已注册...")
```

#### Task 5：InferenceEngine 增加 YOLO 后处理三分支

**关键变更**：
- `src/AI/InferenceEngine.cpp` 的 `postprocess` 方法按输出维度自动判别：
  - **dims=2 [1,nc]**：分类分支，softmax → argmax → top5
  - **dims=3 [1,4+nc,anchors]**：YOLOv8 分支，概率已就绪过滤 + NMS（`postprocessYoloV8`）
  - **dims=3 [1,anchors,5+nc]**：YOLOv5 分支，sigmoid(cls)*sigmoid(obj) + NMS（`postprocessYoloV5`）
- 实现自包含 NMS（`nms` 方法，IoU 阈值默认 0.45）
- 新增 `setConfThreshold`/`setIoUThreshold` 接口（默认 0.25/0.45）
- YOLO 检测结果 JSON：`{model_type, num_detections, detections:[{class_id, confidence, cx, cy, w, h}], max_confidence}`
- 无检测时输出 `max_confidence` 诊断信息帮助定位根因

**判别逻辑**：`dim2 > dim1` → YOLOv8；`dim1 > dim2` → YOLOv5

#### Task 6-7：新增 YoloDetectTool 算子并注册

**关键变更**：
- 新增 `include/Vision/YoloDetectTool.h`：继承 `VisionTool`，含 `modelPath`/`confThreshold`/`iouThreshold`/`inputSize`/`categoryLabels` 成员
- 新增 `src/Vision/YoloDetectTool.cpp`：
  - `configure`：5 参数 `loadModel`（QSize, Scalar(0,0,0), 1/255.0, swapRB=true）+ `warmUp(3)`
  - `execute`：调用 `m_engine->infer(input, inferResult)`，解析 `num_detections`/`detections`/`max_confidence`
  - `drawDetections`：绘制检测框到 `overlayImage`（`cv::rectangle` + `cv::putText` 标签，8 色循环）
  - `serialize`/`deserialize`：与 AiClassifyTool 模式一致
- `src/Vision/ToolFactory.cpp`：注册 `YoloDetectTool`（`registerTool("YoloDetect", ...)`），创建后自动注入推理引擎
- `config/operators.json`：添加 YoloDetectTool 算子元数据（参数：modelPath/confidenceThreshold/iouThreshold/inputWidth/inputHeight/categoryLabels）

#### Task 8-9：YOLO 训练与数据集导出脚本

**关键变更**：
- 新增 `training/yolo_train.py`：
  - argparse `--config`/`--output_dir`，加载 ultralytics YOLO 预训练权重
  - 显式注册 `model.add_callback("on_fit_epoch_end", callback)` 输出 JSON Lines 进度
  - 训练完成后 `model.export(format="onnx", opset=12, simplify=True, dynamic=False)`
  - 强制命名产物 `best<YYYYMMDDHHMMSS>.onnx`（正则校验）
  - 输出 complete JSON（onnx_path/labels_path/total_time_sec/metrics）
  - 错误处理：空权重文件检测、data.yaml 缺失回退生成
- 新增 `training/data/yolo_export.py`：
  - 创建 `images/{train,val}` + `labels/{train,val}` 目录结构
  - 按 85:15 等距轮转采样划分（<10 张全进 train）
  - 生成 YOLO 标签文件（`class_id cx cy w h` 归一化到 [0,1]）
  - 保留无标注图片生成空标签文件（=背景样本）
  - 生成 `data.yaml`（path/train/val/nc/names 相对路径）

#### Task 10：依赖更新与 P1 测试验证

**关键变更**：
- `training/requirements.txt` 添加 `ultralytics>=8.0` 依赖
- 编译验证 YoloDetectTool 集成

### 2.3 P2 阶段：缓存机制与数据集校验（Task 11-15）

**阶段目标**：实现三层缓存机制、数据集四维校验、双格式导出、图像预览金字塔缓存。

#### Task 11：实现 InferenceCache（推理结果缓存）

**关键变更**：
- 新增 `include/AI/InferenceCache.h`：`QCache<QString, QJsonObject>` 容量 50，`QMutex` 保护
- 新增 `src/AI/InferenceCache.cpp`：
  - 缓存 Key：`modelPath|modelMtime|inputSize|confThreshold|imgFingerprint`
  - 图像指纹算法：`resize` 到 16x16 → `cvtColor` 转灰度 → `meanStdDev` 计算 mean + `cv::sum` 计算 sum → `m<mean>_s<sum>` 字符串
  - LRU 淘汰：QCache 自带机制，容量达 50 时自动淘汰最久未用
- 集成到 `InferenceEngine`：`infer` 前查缓存（`lookup`），`infer` 后写缓存（`insert`）

#### Task 12：实现 ImageCache（图像缓存）

**关键变更**：
- 新增 `include/AI/ImageCache.h`：`QCache<QString, CacheEntry>` 容量 100，`QMutex` 保护
- 新增 `src/AI/ImageCache.cpp`：
  - Key：`filePath`，`CacheEntry` 存储 `mtime`
  - mtime 失效机制：`load` 时比较 `currentMtime` 与 `cached->mtime`，不匹配则重新加载
  - 加载方式：`QFile` + `cv::imdecode`（内存解码，兼容中文路径）
  - 返回 `clone` 副本避免外部修改

#### Task 13：实现 DatasetValidator（四维校验）

**关键变更**：
- 新增 `include/AI/DatasetValidator.h`：`ValidationRequest`/`ValidationItem`/`ValidationReport`/`Severity`/`Category` 结构
- 新增 `src/AI/DatasetValidator.cpp`：
  - **Pairing 维度**：文件存在/无标注/类别引用
  - **Format 维度**：尺寸/bbox 越界/面积/占比/polygon 顶点
  - **Compatibility 维度**：模型存在/尺寸匹配/类别数匹配
  - **Distribution 维度**：类别无样本/样本<10/不平衡/尺寸变异
  - 健康评分：满分 100，Critical -30 / Error -10 / Warning -2
  - 训练门禁：`isHealthy()`（无 Critical/Error）、`canTrain()`（无 Critical 且 Error<=5）

#### Task 14：实现 ExportManager（YOLO/COCO 导出）

**关键变更**：
- 新增 `include/AI/ExportManager.h`：单例，`exportYOLO`/`exportCOCO`
- 新增 `src/AI/ExportManager.cpp`：
  - YOLO 导出：`images/{train,val}` + `labels/{train,val}` + `classes.txt` + `data.yaml`
  - COCO 导出：`images/annotations` + bbox/polygon 转换
  - 85:15 等距轮转采样划分
  - 保留无标注图片生成空标签文件

#### Task 15：ImageViewer 金字塔缓存

**关键变更**：
- 新增 `include/UI/ImagePyramidCache.h`：4 档缩放等级，`QCache<int, CacheEntry>` 容量 20
- 新增 `src/UI/ImagePyramidCache.cpp`：
  - 档位划分：`[0.1,0.5)` / `[0.5,1.0)` / `[1.0,2.0)` / `[2.0,10.0)`
  - 插值选择：档位 0-1 用 `INTER_AREA`（缩小），档位 2 用 `INTER_LINEAR`（轻微放大），档位 3 用 `INTER_NEAREST`（大幅放大）
  - 同档复用：`getLevel` 判断档位，缓存 Key 是档位编号 0-3
  - 跨档重建：源图像变化时 `clear` 缓存
  - `cv::Mat` → `QImage` 转换（支持 3/1/4 通道）
