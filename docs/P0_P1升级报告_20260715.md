## 1. 背景

原算子库存在三类系统性问题：
- **幻影算子**：3 个 3D 算子在 operators.json/Router 注册但无任何实现，createTool 返回 nullptr；
- **核心场景缺失**：缺少位置修正、相机标定、单位换算、卡尺测量、轮廓匹配、颜色比对、端到端 OCR、光源控制等工业视觉必备算子；
- **架构短板**：无 typed ports 类型校验、无流程控制算子、无表面缺陷检测、ScriptTool 缺失导致用户无法嵌入自定义逻辑。

本次升级目标：完成 P0（必修）与 P1（重要）全部条目，使算子库在功能完整性与架构严谨性上达到工业可用标准。

## 2. 执行过程

### 2.1 P0-1 幻影算子清理
- 删除 `config/operators.json` 中 Reconstruct3D / BinocularDisparity / SurfaceMatching 三个对象
- 注释 `AgentOperatorRouter.cpp` 中「3D视觉」路由分类（待真正实现 3D 算子后再恢复）
- 新增「标定与坐标」路由分类，HandEyeCalib/RobotPose 迁移至此

### 2.2 P0 新增算子（10 个，全部 OpenCV 真实实现）

| 算子 | 类型 | 核心实现 |
|---|---|---|
| PositionCorrect | P0-2 | 仿射变换矩阵（平移/旋转/缩放） |
| UnitConvert | P0-3 | px↔mm 单位换算（标定系数） |
| Caliper | P0-4 | 双卡尺亚像素边缘测量 |
| CameraCalib | P0-5 | 张正友标定（cv::calibrateCamera） |
| ContourMatch | P0-6b | Hu 矩抗形变轮廓匹配（cv::matchShapes） |
| ColorMatch | P0-6c | 多色彩空间（HSV/RGB/Lab）直方图比对 |
| DLOCR | P0-6d | 文本检测（OpenCV dnn/MSER 降级）+ 现有 Ocr |
| LightControl | P0-6e | 复用 IOController（无硬件时优雅降级） |

### 2.3 P0 已有算子扩展

- **P0-6a FindShapeModelTool**：增加各向异性 ScaleX/ScaleY 尺度搜索（三重循环：scale × ratio × angle + NMS）
- **P0-3 GeometryMeasureTool / DistancePpTool**：增加 `outputUnit` 参数（px/mm），输出经单位换算后的值到 `result.ports`

### 2.4 P1-3 typed ports 类型化数据端口改造（基础设施）

**架构变更：**
- `VisionTool.h` 增加 `PortType` 枚举（Any/Image/Region/Contour/Points/Number/Bool/String/...）、`PortDirection`、`PortDescriptor` 结构体
- `ToolResult` 增加 `QVariantMap ports` 字段（非图像 typed 数据通道，与 overlayImage 并行）
- `VisionTool` 基类增加 `outputPorts()/inputPorts()` 虚方法，默认返回空（向后兼容）
- 新建 `src/Core/PortDescriptor.cpp`：实现 `typeName()`、`compatible()`、`toMap()`
  - 兼容规则：Any 兼容一切；同类型兼容；Region/Contour/Points 互通
- `EditViewBridge` 在 `connectNodes()` 中增加端口类型校验，不兼容时 emit errorRaised
- `EditViewBridge::getOperatorPorts()` 提供 QML 查询端口元数据接口

**向后兼容策略：** 旧算子默认 outputPorts()/inputPorts() 返回空，连线期 checkPortCompatible 任一端未声明则放行；图像仍走 overlayImage 通道，避免 cv::Mat 包装进 QVariant 的复杂性。

### 2.5 P1-4 流程控制算子

| 算子 | 类型 | 实现 |
|---|---|---|
| Loop | P1-4a | 多 ROI/多目标遍历执行 |
| Script | P1-4b | 嵌入 CPython（D盘 Python314）+ AST 白名单安全沙箱 |
| Variable | P1-4c | 数值/字符串运算 + 格式化 |
| BranchControl（扩展） | P1-4c | 新增 ge/le/ne/contains/startswith/endswith/in 比较算子 |

**ScriptTool 安全设计要点：**
- 使用 CPython 标准 C API（Py_CompileString + PyEval_EvalCode），非 JavaScript eval()
- 用户脚本先经 ast 模块解析，按节点白名单校验（仅允许安全节点）
- 禁止 Import(os)/Import(sys)/open/exec/eval/compile/globals/locals/__import__
- 仅允许导入 allowedModules 列表中的模块（默认 math/json/re）
- 注入 sandbox 内置函数：get_var(name) / set_var(name,value) / log(msg)
- 用 `QDV_WITH_PYTHON` 宏条件编译保护，无 Python 环境时退化为 stub

### 2.6 P1-5 缺陷检测算子

| 算子 | 类型 | 实现 |

| ContourCompare | P1-5b | 实测轮廓 vs 标准轮廓偏差判定（cv::matchShapes） |

## 3. 构建验证

### 3.1 编译期错误修复

| # | 错误 | 修复 |
|---|---|---|
| 1 | 14 个头文件 `QList<PortDescriptor>` 找不到类型 | 统一改为 `QList<QDV::PortDescriptor>`（PortDescriptor 在 QDV 命名空间内，全局命名空间的派生类需完全限定） |
| 2 | `Python.h: object.h: PyType_Slot *slots` 与 Qt `slots` 宏冲突 | ScriptTool.h 引入 Python.h 前 `#pragma push_macro("slots")` + `#undef slots`，引入后 pop |
| 3 | `ScriptTool::stdoutBuffer()` private，sandbox_log 回调无法访问 | 改为 public |
| 4 | `LightControlTool.cpp` 链接错误：IOController 未定义 | Vision 模块 target_link_libraries 增加 `Communication` |
| 5 | `EditViewBridge.cpp` 用 `QDV::ToolFactory` 未声明 | 改为 `::ToolFactory`（ToolFactory 在全局命名空间） |
