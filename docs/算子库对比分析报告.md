# 算子库对比分析报告：QDV vs 海康威视 MVS/VM

> **分析对象**
> - **当前项目**：Q-DetectVision（QDV），v5.4.0 算子元数据，Qt6 + OpenCV 4.13 实现的视觉检测桌面软件
> - **对标对象**：海康威视 MVS（设备采集层）+ VM/VisionMaster 算法平台算子库
>
> **数据来源**
> - QDV 实测：`config/operators.json`（58 条算子元数据）、`src/Vision/ToolFactory.cpp`（55 个已注册算子）、`src/Vision/*Tool.cpp`（实现）、`include/Vision/*Tool.h`（接口）、`CodeWiki.md`
> - 海康：`E:\anchor\TEST\海康威视MVS算子库功能概览.md`（**2026-07-15 核实版**：原 20 个 `(推断)` 算子全部升级为 `(确认)`，新增《推断信息核实报告》附录）
>
> **结论速览**：QDV 已实现 **55 个可用算子**（10 大类），覆盖 VM 核心算子约 **70%**；另有 **3 个幻影算子**（仅元数据、无实现）。QDV 在预处理/形态学/分割粒度更细，但**严重缺失工业级支撑算子**（位置修正、单位换算、卡尺、光源控制、脚本/循环、端到端 OCR 等）；VM 在算子广度（千余）、亚像素精度、标定→物理坐标闭环上更成熟。
> **核实状态（2026-07-15）**：海康文档已将原标注 `(推断)`/`✓(推断)` 的 20 个算子条目经公开来源交叉核实**全部确认为 VM 真实能力**（详见其附录），故本报告所列"QDV 缺失项"均为**已核实的真实差距**，而非推测；仅 4 处子项细节列为**存疑**（双边滤波、独立 Clip 裁剪、Lua 脚本语言、部分数值默认值）。

### 1.2 海康 MVS/VM 算子现状（文档）

- **规模**：VM 平台集成**千余个**算子，文档列出 A~K 共 **11 大类核心算子**作为索引。
- **层次**：MVS 为设备/采集层（不含算法）；VM 为算法层（算子以流程节点 DAG 串联）。
- **精度**：定位/测量类普遍**亚像素**，配合相机标定可达微米级。
- **引擎**：自研原生优化，DL 建议 GPU，支持 SDK（C/C#/Python）二次开发。
- **核实状态（2026-07-15）**：文档 A~K 算子均已经公开来源交叉核实为 VM 真实能力（原 20 个 `(推断)` 全部升级为 `(确认)`，详见海康源文档附录《推断信息核实报告》）；仅 4 处子项细节列为**存疑**（双边滤波、独立 Clip 裁剪、Lua 脚本语言、部分数值默认值）。本报告的"QDV 缺失项"因此为**已核实的真实差距**，而非推测。

## 三、维度一：算子种类与覆盖范围差异

### 3.1 QDV 缺失的算子（按工业重要性）

| # | 缺失算子 | VM 类别 | 影响 | 严重度 |
|---|---|---|---|---|
| 1 | **PositionCorrect（位置修正）** | D | 无法让下游 ROI/测量框随工件平移旋转跟随，任意姿态测量误差大 | 🔴 高 |
| 2 | **UnitConvert（单位换算 px→mm）** | J | 测量输出只能给像素值，无标定驱动的物理尺寸，报告不可用 | 🔴 高 |
| 3 | **Caliper（卡尺/双边缘宽距）** | E | 无亚像素宽距测量算子，尺寸检测精度不足（Hough 圆/线误差大） | 🔴 高 |
| 4 | **LightControl（光源控制）** | A | 无法软件触发频闪/调光，高反光/透明件成像差 | 🟡 中 |
| 5 | **HighPrecisionMatch（各向异性尺度）** | D | FindShapeModel 仅旋转、无尺度搜索，缩放工件匹配失败 | 🟡 中 |
| 6 | **ContourMatch（轮廓形状匹配）** | D | 当前为 NCC 旋转匹配，抗形变/多尺度弱 | 🟡 中 |
| 7 | **SurfaceDefect（表面缺陷）** | H | 无专用模板差分缺陷算子 | 🟡 中 |
| 8 | **PathExtract（路径提取）** | C | 无密集点集采样，曲线轮廓/孔距分析弱 | 🟡 中 |
| 9 | **Script / Loop / Variable** | K | 无方案内脚本、循环（多 ROI）、变量计算，复杂逻辑受限 | 🟡 中 |
| 10 | **DLOCR（端到端文本）** | I/G | OCR 仅识别、无检测，低对比/复杂字体失效 | 🟡 中 |
| 11 | ColorMatch、GraphicMatch、LineLine/CircleCircle/PointCircle、ContourCompare、DLTemplate、DLRetrieve、CameraCalib、CalibBoard、DataMatrix | 多类 | 功能补全项（DataMatrix 缺失已确认：VM 读码支持 QR/DataMatrix/PDF417） | 🟢 低-中 |

> **核实状态（2026-07-15）**：上表缺失项对应的 VM 算子，均已由海康源文档经公开来源交叉核实为真实能力（`(推断)`→`(确认)`），即本表为**已核实的真实差距**，非推测。与 QDV 缺失项相关的 2 处存疑子项：
> - **K.1 脚本语言**：原文"Lua"非 VM 脚本语言（VM 证实支持 C#/VB，Python 经自定义模块），QDV 若实现 `ScriptTool`（P1-4）应优先 C#/VB 或 Python 路线。
> - **B.7 独立 Clip 裁剪**：VM 无独立"Clip"算子，区域提取经 ROI/图像运算实现 —— 与 QDV `RgbExtract`/`ImageTransform` 思路一致，拼写差异不影响能力判定。
> 其余"双边滤波存疑"（B.2）属 VM 自身滤波细节，不影响本表 QDV 缺失清单。

### 3.2 海康 MVS/VM 缺失（或弱于 QDV 的）算子

> 即 QDV 相较 VM 的**差异化/更细粒度**算子。VM 通过通用算子或训练工具内部实现，但未单列为可拖拽算子。

| QDV 算子 | 说明 | VM 对应/差异 |
|---|---|---|
| **FftGeneric** | 正/逆快速傅里叶变换 | VM 未单列频域算子（缺陷频域检测多走 DL） |
| **TopHat / BottomHat** | 顶帽/底帽变换 | VM `Morphology` 通用，未拆出顶/底帽 |
| **RgbExtract / ChannelSplit** | 逐通道提取与色彩空间转换 | VM `ColorConvert` 原记为"仅 RGB→Gray/HSV"；2026-07-15 核实 VM 实际支持 RGB/HSV/HSL/Lab/YUV 等多种色彩空间互转，故 QDV 的"粒度更细"优势需重估（QDV 为逐通道提取、VM 为空间互转，侧重不同，非代差） |
| **Histogram** | 直方图统计 | VM 未单列统计算子（嵌于显示/训练） |
| **Emphasize / ScaleImage** | 锐化增强 / 灰度线性缩放 | 对应 VM `BrightnessContrast`，但 QDV 拆分更细 |
| **Watershed / RegionGrowing / DynThreshold** | 显式分割算子 | VM 用 `SurfaceDefect`/`ContourCompare` 近似，QDV 更显式 |
| **Normalization** | DL 图像归一化预处理 | VM 在训练工具内完成 |
| **RobotPose** | 机器人位姿缓冲（v5.3） | VM 手眼标定后集成，但无独立位姿算子暴露 |
| **AgentOperatorRouter** | AI 智能体算子路由 | QDV 独有，非标准视觉算子 |
| **SelectShape / PointsHarris** | 形状筛选 / Harris 角点 | VM 用 Blob/FindEdge 涵盖，未单列 |

**小结**：QDV 在"预处理 + 形态学 + 分割"细粒度上优于 VM 的通用封装；但在"工业落地支撑算子"（标定闭环、位置跟随、卡尺、光源、流程控制）上全面落后。

## 四、维度二：参数配置、性能指标、适用场景对比

> 抽样对比同类算子，凸显接口成熟度与精度差距。

| 维度 | 海康 VM（典型） | QDV（典型实现） | 差异点评 |
|---|---|---|---|
| **模板匹配** | QuickMatch：尺度特征/对比度阈值/角度范围/MinScore/MaxMatch；**亚像素**；支持尺度+旋转+光照鲁棒 | FindShapeModel：模板路径/阈值0.7/角度范围/最大匹配数；实现为**旋转+NCC**（无尺度搜索） | QDV 缺尺度不变性、无亚像素插值；`FindNccModel` 为纯 NCC，光照敏感 |
| **边缘/找边** | FindEdge：滤波尺寸/边缘阈值/极性/卡尺数/投影；**亚像素点集** | EdgesSubPix：亚像素边缘 ✅；LineCircleDetect：Hough 圆/线（**像素级、对噪声敏感**） | QDV 有 EdgesSubPix 亮点，但圆/直线查找仍用 Hough，精度不及 VM 卡尺 |
| **几何测量** | Caliper：双卡尺边缘对、亚像素宽距；LineLine/CircleCircle 独立算子；LineFit/CircleFit 支持 **LS/Huber/Tukey** 拟合（2026-07-15 核实） | GeometryMeasure：距离/面积/周长/角（轮廓级）+ **手动 pixelScale**（默认 1.0） | QDV 无独立卡尺/线线/圆圆算子；物理尺寸靠手动 scale，无标定驱动；拟合仅最小二乘（无 Huber/Tukey 鲁棒选项） |
| **Blob** | BlobAnalysis：阈值/面积/圆度/长宽比/连通性 4/8；输出质心+数量 | BlobDetect（SimpleBlobDetector）+ Connection + SelectShape + ContourAnalyze | QDV 拆分更灵活，但 SimpleBlobDetector 对粘连/复杂形状弱于 VM 连通域分析 |
| **OCR** | OCR（传统模板）+ DLOCR（端到端检测+识别）；**DL-OCR 端到端识别率 >99%（2026-07-15 核实，传统 OCR 与 DLOCR 均成立）**；读码支持 15 种一维码 + QR/DataMatrix/PDF417 | Ocr：**cv::dnn CRNN + CTC**，需 ONNX 模型；无模型时**静默降级**（不报错） | QDV OCR 技术更现代，但缺检测阶段（DLOCR）且降级不报错易致"假成功"；读码仅 Barcode1d+QrCodeDetect，**缺 DataMatrix**（已确认 VM 支持） |
| **深度学习** | DLDetect/Classify/Seg 加载训练模型；GPU 推荐；置信度阈值 | YoloDetect/DetectObjectsDl/SegmentDl/AiClassify：OpenCV DNN 或 ONNXRuntime；**推理目前多为模拟/待接入** | QDV DL 接口层完整，但 `InferencePanel` 推理仍 QRandomGenerator 模拟（已知限制），真实推理待 M7 |
| **标定** | CameraCalib 出标定文件 → UnitConvert 全局 px→mm | HandEyeCalib（eye_in_hand/to_hand，真实实现）+ RobotPose；**无 CameraCalib/UnitConvert** | QDV 有手眼标定，但缺相机内参标定与下游单位换算闭环 |
| **性能** | 原生优化，DL 建议 GPU/独立线程；CPU 单线程满足多数节拍 | OpenCV CPU；DL 走 OpenCV DNN（慢）/ONNXRuntime（可选未默认）；ToolChainExecutor **同步顺序、execute() 恒返回 true** | QDV 缺 GPU 默认路径、缺失败中断、缺并行执行 |

## 五、维度三：实现方式与接口设计差异

### 5.1 数据流与执行模型

| 维度 | 海康 VM | QDV |
|---|---|---|
| 拓扑 | **DAG**（有向无环图，支持分支/汇聚） | **线性工具链**（Scheme 节点 + connections，顺序执行；`BranchControl` 做条件跳转） |
| 数据传递 | 显式**类型化端口**（Image/Region/Pose/XLD 等），schema 校验 | **隐式总线**：`ToolResult.overlayImage` 既作可视化又作下一工具输入；无类型 schema |
| 失败语义 | 节点失败显式阻断/告警 | `ToolChainExecutor::execute()` **恒返回 true**，工具失败仅记日志不中断（已知设计缺陷） |
| 异步 | 流程同步；SDK 支持异步回调/多线程 | `executeAsync` 经 `QtConcurrent::run`；但主流程未全面接入 |
| 坐标体系 | 像素→标定→物理(mm)，亚像素贯穿 | 像素为主；`GeometryMeasure` 手动 `pixelScale`；手眼标定独立，未与测量打通 |

### 5.2 算子接口设计

| 维度 | 海康 VM | QDV |
|---|---|---|
| 基类契约 | 算子模块（C/C#/Python），参数结构体 + 运行时 | `QDV::VisionTool` 抽象基类：`type()/configure()/execute()/serialize()`；非 QObject、无信号槽 |
| 参数驱动 | 图形属性面板，每算子专属 | **数据驱动元数据**（`operators.json` + `OperatorDescriptors`），7 种 `ParamType` 自动生成 QML 表单（亮点） |
| 元数据外部化 | 方案内嵌 | ✅ `operators.json` 可热改（损坏回退内置），优于 VM 强耦合 |
| 插件扩展 | VM 算子市场/SDK | `IPlugin` DLL 动态加载（已定义，`SerialCommunicator` 仍为存根） |
| 结果契约 | 模块输出变量 | `ToolResult{ok,data,score,elapsedMs,overlayImage}` + `QDV::Result<T>`（Rust 风格，亮点） |
| 持久化 | 方案文件 | SQLite 检测结果持久化（`ResultDatabase`）✅ |

### 5.3 关键差异点总结

1. **拓扑能力**：VM 是 DAG（分支/汇聚/并行），QDV 是线性链 + 单条件分支 —— 复杂多 ROI/多目标场景 QDV 受限。
2. **数据契约**：VM 类型化端口 + schema；QDV 隐式 `overlayImage` 总线，灵活但易出错、无静态校验。
3. **精度闭环**：VM 标定→UnitConvert 物理坐标闭环成熟；QDV 有手眼标定碎片，无统一单位换算算子。
4. **工业支撑算子**：VM 的 PositionCorrect/LightControl/Caliper/Script/Loop 是产线刚需，QDV 全缺。
5. **QDV 亮点**：元数据外部化、数据驱动表单、Result<T> 错误模型、SQLite 持久化、细粒度预处理/形态学/分割、真实手眼标定 + 实时配对模式。
6. **一致性风险**：`operators.json`（58）与 `ToolFactory`（55）**不同步**，3 个幻影算子会在运行时崩溃——这是当前最紧迫的工程债。
