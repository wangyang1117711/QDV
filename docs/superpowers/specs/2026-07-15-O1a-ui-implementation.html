A 选文件后触发预览解析
用户点击"浏览"选择 .qdvop 文件后，QML 将路径传递给 Bridge 层，Bridge 转发至 Controller 解析文件，返回 ImportPreview 结构体给 QML 渲染预览区。预览为只读，不产生副作用。
// QML onSelectFile OperatorLibraryBridge::requestPreview(path) → Controller::importFile(path) → return ImportPreview { meta, ports, params, validation }
B 提交按钮触发实际导入
校验结果区无错误项时按钮可用。点击后 Bridge 将 preview 提交至 Controller，Controller 执行实际导入（写入 config/operators_imported）并发射信号通知 QML 刷新算子库面板。
// QML onSubmit OperatorLibraryBridge::commitImport(preview) → Controller::commitImport(preview) → emit importedChanged(type, "added")
C 信号监听刷新算子面板
QML 端监听 importedChanged 信号，通过置空 model 触发 rebuild，复用 Main.qml 中已有的算子列表重建模式（L1383-1384）。
// QML onImportedChanged(type, action) operatorList.model = null → operatorList.model = operatorList.buildModel() // 复用 Main.qml L1383-1384 模式
! 冲突禁用规则（强约束）
当校验结果区存在红色"错误"项时，"提交导入"按钮必须禁用，按钮文字显示"请先解决冲突"。警告项（黄色）不阻断提交，由用户自行决定是否继续。本场景示意图展示的就是"有冲突被禁用"的状态。

说明 已删除的算子在下次启动后彻底消失，本次会话中仍可见但不可使用。这是由于 OperatorDescriptors 无反注册 API（已知技术债），删除后文件消失但 s_externalRegistry 仍保留。
A 列表数据源
QML 打开面板时调用 Bridge 拉取已导入算子列表，Bridge 转发至 Controller 查询 config/operators_imported 目录，返回 QVariantList 给 QML 作为 ListView model。
// QML onOpened OperatorLibraryBridge::listImported() → Controller::query() → return QVariantList
B 删除按钮 → 二次确认 → 移除
点击删除按钮先弹出 MessageDialog 二次确认；确认后 Bridge 调用 Controller 移除算子文件，Controller 发射 importedChanged(type, "removed") 信号通知 QML 刷新列表与算子库面板。
// QML onDelete → MessageDialog 确认 OperatorLibraryBridge::removeImported(type) → Controller::removeImported(type) → emit importedChanged(type, "removed")
C 画布预检阻断
删除前 Bridge 层遍历 EditViewBridge::currentNodes 检查该 type 在画布上的使用情况。若有节点正在使用，阻断删除并提示用户先清理画布上的相关节点。
// Bridge 画布预检 for node in EditViewBridge::currentNodes: if node.type == type: block + tip: "画布上存在 N 个使用该算子的节点"
D 置灰逻辑（已知技术债）
OperatorDescriptors 没有反注册 API，删除后文件消失但内存中的 s_externalRegistry 仍保留描述符，因此本次会话中算子仍可见但置灰（opacity 0.5），标注"已删除·重启生效"。下次启动时彻底从注册表移除。

A 入口位置 — 算子库面板底部
在 qml/EditView/Main.qml 算子库面板的 panel-body 之后、面板结束前，新增一个 RowLayout 包含两个按钮。"已导入 (N)" 中的 N 绑定到 operatorLibraryBridge.importedCount，随导入/删除实时刷新。
// qml/EditView/Main.qml 算子库面板 // panel-body 之后 / 面板结束前 RowLayout { Button { text: "＋ 导入算子" onClicked: operatorImportDialogLoader.item.open() } Button { text: "已导入 (" + operatorLibraryBridge.importedCount + ")" onClicked: importedOperatorsPanelLoader.item.open() } }
B 已导入算子标识 — 紫色 "I" 标签
在算子库列表的每一项中，若该算子来自 config/operators_imported 目录，则在算子名右侧显示紫色小标签 "I"（imported 标记），便于用户区分内置算子与已导入算子。详情面板的"来源"字段也显示"已导入"。
C Loader 实例化 — Main.qml
在 Main.qml 中添加两个 Loader，分别加载 OperatorImportDialog.qml 和 ImportedOperatorsPanel.qml，使用 active: false 懒加载，首次点击入口按钮时才实例化。
// qml/EditView/Main.qml Loader { id: operatorImportDialogLoader source: "OperatorImportDialog.qml" active: false // 懒加载 } Loader { id: importedOperatorsPanelLoader source: "ImportedOperatorsPanel.qml" active: false }
D 刷新机制 — 监听 importedChanged 信号
Main.qml 监听 Bridge 的 importedChanged 信号，触发后置空算子列表 model 并重建，复用现有 L1383-1384 模式。无论 added 还是 removed 都会触发刷新，确保列表与磁盘状态一致。
// qml/EditView/Main.qml Connections { target: operatorLibraryBridge function onImportedChanged(type, action) { operatorList.model = null operatorList.model = operatorList.buildModel() // 复用 Main.qml L1383-1384 模式 } }
E 初始化时机 — main.cpp 启动
main.cpp 启动时调用 Controller 单例的 init 方法，指定已导入算子的存储目录与内置算子目录。Controller 会扫描目录并填充 s_externalRegistry，供 Bridge 查询。
// main.cpp 启动阶段 OperatorLibraryController::instance()->init( "config/operators_imported", // 已导入目录 "" // 内置目录（默认） )
