# 编辑模块优化 —— 开发文档

> 面向开发者。对应 spec：`editor-output-connection-optimization`。
> 涵盖：输出项配置增强、多连接关系扩展、输入/输出冲突处理、智能算子推荐 四个子系统。
> 本文档描述的所有接口名、行为、路径均与当前代码一致。

---

## 一、模块架构概览

本 spec 在 `EditViewBridge`（C++ ↔ QML 桥）之上新增了四个专职协作者，均以**弱引用**持有 `EditViewBridge*`，生命周期跟随桥对象，不新增独立存储：

```
                    EditViewBridge（桥，持有各协作者，Q_PROPERTY 暴露给 QML）
        ▲  friend 访问私有数据（m_currentNodes / m_connections / m_useCounts / m_recents）
        │
   ┌────┴─────────┬───────────────┬───────────────────┬──────────────────┐
   │              │               │                   │                  │
OutputConfig--PortBinding--OutputConflict--OperatorRecommender       ToolChainExecutor
Manager       Manager       Detector       (Friend)                  (executeWithFlow /
(输出配置)     (端口绑定)      (冲突检测)      (智能推荐)                topoSortFlow 等)
   │              │               │
   └──────────────┴───────┬───────┘
                   复用/组合
```

### 1.1 协作者归属与角色

| 类 | 头文件 | 角色 | 数据来源 |
| --- | --- | --- | --- |
| `OutputConfigManager` | `include/UI/OutputConfigManager.h` | 读写节点输出开关配置，走 UndoCommand，同步变量 | 节点 `outputConfig` 字段 |
| `PortBindingManager` | `include/UI/PortBindingManager.h` | 端口级绑定语义查询与校验（多输入/多输出） | `m_connections` |
| `OutputConflictDetector` | `include/UI/OutputConflictDetector.h` | 三类冲突即时扫描 | `m_currentNodes` + `m_connections` + `PortBindingManager` |
| `OperatorRecommender` | `include/UI/OperatorRecommender.h` | Top3 推荐 + 权重持久化 | `m_useCounts` / `m_recents` / 连接结构 |
| `ToolChainExecutor`（扩展） | `include/Vision/ToolChainExecutor.h` | 端口级多输入数据流执行 | `setFlowBindings` 注入的绑定 |

### 1.2 协作关系

- **数据源头**始终是 `m_currentNodes` / `m_connections`（`EditViewBridge` 维护），各协作者只提供**语义化视图**，不复制数据，避免双写不一致。
- `OutputConflictDetector` **组合复用** `PortBindingManager::bindingsForInput()` 做多输入语义查询。
- `OutputConfigManager` 与 `PortBindingManager` 都通过 `getOutputConfig()` 读取同一份 `outputConfig`，保证「禁用输出」能被「建连校验」即时感知。
- friend 声明：`PortBindingManager` / `OutputConflictDetector` / `OperatorRecommender` 均为 `EditViewBridge` 的 friend，以便复用其私有数据与端口校验方法。

## 二、各组件接口说明

### 2.1 PortBindingManager（端口绑定数据模型）

路径：`include/UI/PortBindingManager.h` / `src/UI/PortBindingManager.cpp`

**结构体 `Binding`**（一条端口绑定的语义化视图）：

```cpp
struct Binding {
    QString upstreamToolId;   // 上游算子 ID
    QString upstreamPort;     // 上游输出端口名
    QString downstreamToolId; // 下游算子 ID
    QString downstreamPort;   // 下游输入端口名
    bool    upstreamEnabled;  // 上游该输出是否已勾选（enabled）
};
```

**公开接口：**

| 方法 | 说明 |
| --- | --- |
| `bindingsForInput(downstreamId, downstreamPort)` | 查询下游某输入端口绑定的所有上游输出（多输入） |
| `consumersOfOutput(upstreamId, upstreamPort)` | 查询上游某输出端口被哪些下游消费（多输出扇出） |
| `allInputBindings(downstreamId)` | 查询某节点全部输入绑定（跨所有输入端口） |
| `allOutputFans(upstreamId)` | 查询某节点全部输出扇出（跨所有输出端口） |
| `validateBinding(fromId, fromPort, toId, toPort, outReason)` | 校验一条绑定是否合法（端口类型兼容 + 上游输出已勾选） |
| `isOutputEnabled(upstreamId, upstreamPort)` | 上游某输出是否已勾选 |

**实现要点：**
- 遍历 `m_bridge->connections()`（格式 `{fromId, fromPort, toId, toPort}`），按维度过滤。
- `isOutputEnabled` 读取 `getOutputConfig(upstreamId)` 中的 `{outputName: {enabled}}`，配置缺失时回退 `enabled=true`（向后兼容）。
- `validateBinding` 依次校验：端点非空 → 非自连接 → 上游输出已启用 → 端口类型兼容（复用 `EditViewBridge::checkPortCompatible`）。

### 2.2 ToolChainExecutor::executeWithFlow（端口级多输入执行）

路径：`include/Vision/ToolChainExecutor.h` / `src/Vision/ToolChainExecutor.cpp`

**结构体 `FlowBinding`：**

```cpp
struct FlowBinding {
    QString upstreamToolId;   // 上游算子 ID
    QString upstreamPort;     // 上游输出端口名
    QString downstreamToolId; // 下游算子 ID
    QString downstreamPort;   // 下游输入端口名
};
```

**公开接口：**

| 方法 | 说明 |
| --- | --- |
| `setFlowBindings(bindings)` | 执行前注入端口绑定；按 `downstreamToolId` 分组存入 `m_flowBindings` |
| `executeWithFlow(primaryInput)` | 按端口绑定执行多输入数据流（拓扑序） |
| `flowInputsFor(toolId)` | 查询某算子在 flow 模式下合并到的上游输入数据（key=下游端口名） |
| `topoSortFlow()`（私有） | Kahn 算法拓扑排序，返回顺序 toolId 列表；存在环返回空 |

**执行流程（`executeWithFlow`）：**
1. 校验 `primaryInput` 非空、未重入（`m_running.exchange(true)`）。
2. 清空 `m_results` / `m_flowInputs`。
3. `topoSortFlow()` 求拓扑序；存在环 → 记日志并 `chainCompleted(false)`。
4. 若无绑定（纯线性），退化为原有 `execute()` 语义。
5. 按拓扑序逐个 `executeFlowNode`，失败累计 `failCount` 并发 `toolFailed`。

**`executeFlowNode` 的组装逻辑：**
- 主输入图像：优先取第一个提供 `overlayImage` 的上游结果，否则用 `primaryInput`。
- typed 数据合并：遍历该算子的全部绑定，从上游 `ToolResult.ports`（或 `data`）按 `upstreamPort` 取值，写入 `merged[downstreamPort]`，最终存入 `m_flowInputs[toolId]`。

> 约束：端口绑定以 `upstreamPort`/`downstreamPort`（即 outputName）为主键，与 `OutputConfigManager` 的 `outputConfig` 键一致。

### 2.3 OutputConflictDetector（输入/输出项冲突检测引擎）

路径：`include/UI/OutputConflictDetector.h` / `src/UI/OutputConflictDetector.cpp`

**结构体 `Conflict`：**

```cpp
struct Conflict {
    QString kind;          // "dupAlias" | "typeMismatch" | "multiInputAmbiguity"
    QString nodeId;        // 主节点 ID（歧义指向下游节点）
    QString portName;      // 冲突端口名（下游输入端口或上游重复别名）
    QString detail;        // 冲突描述
    QStringList candidates; // 候选（重复别名端口 / 多上游候选）
};
```

**Q_INVOKABLE 接口（QML 可直接调用）：**

| 方法 | 说明 |
| --- | --- |
| `detectAll()` | 扫描全部冲突，返回 `QVariantList`（元素含 kind/nodeId/portName/detail/candidates） |
| `detectForNode(nodeId)` | 扫描指定节点的冲突（对 detectAll 结果按 nodeId 过滤） |
| `hasConflicts()` | 是否存在任意冲突 |

**信号：** `conflictsChanged()` —— 冲突集合变化（nodes/connections 变化时触发）。

**三类冲突检测规则（`detectAll`）：**
1. **dupAlias**：同一节点多处输出端口 `alias` 相同（`aliasMap.size() > 1`）。
2. **typeMismatch**：逐条连接调用 `checkPortCompatible`，不兼容即上报（nodeId 指向下游）。
3. **multiInputAmbiguity**：对每个下游输入端口，用 `PortBindingManager::bindingsForInput` 取绑定；若绑定数 ≥ 2 且（非通配类型集合 > 1，即类型能力冲突）或（所有上游别名相同，即语义歧义），上报。

**辅助方法：** `nodeTypeById` / `outputMetaForNode` / `inputMetaForNode` / `findOutputMeta` / `outputTypeFor` / `outputAliasFor` / `isWildcardType`（Any 或空视为通配）。

### 2.4 OperatorRecommender（智能算子推荐引擎）

路径：`include/UI/OperatorRecommender.h` / `src/UI/OperatorRecommender.cpp`

**Q_INVOKABLE 接口：**

| 方法 | 说明 |
| --- | --- |
| `recommend(nodeId)` | 给定选中节点，返回 Top3 候选 `[{type, confidence, reason}]` |
| `recommendRecent(nodeType)` | 基于最近使用返回 Top3（排除 nodeType 自身），reason="最近使用" |
| `setWeight(key, v)` | 设置权重并持久化（key ∈ `typeCompat`/`structure`/`frequency`） |
| `getWeight(key)` | 读取当前权重 |

**推荐打分（`recommend`）：**
- 排除当前算子自身。
- **类型兼容分（typeScore）**：候选算子任一输入与当前算子某输出端口类型兼容 → 1.0；当前算子未声明端口（旧算子）→ 0.5 未知分；不兼容 → 0。
- **结构分（structScore）**：当前算子某类下游的归一化频次（`dc / totalDownstream`）。
- **频率分（freqScore）**：`0.7*使用频次归一化 + 0.3*最近位置加成`（位置越靠前越高）。
- **线性加权**：`score = w_typeCompat*typeScore + w_structure*structScore + w_frequency*freqScore`。
- 仅保留 `score > 0` 的候选，按分数降序取 Top3；`confidence = score / maxScore`。

**权重持久化：**
- 路径：`QCoreApplication::applicationDirPath() + "/config/recommender.json"`。
- 加载（`loadWeights`）：仅覆盖存在的键；保存（`saveWeights`）：`mkpath` + 写整型 JSON（Indented）。
- 默认权重：typeCompat=0.5、structure=0.3、frequency=0.2。

**端口类型兼容（`portTypesCompatible`，字符串版）：** 镜像 `QDV::PortDescriptor::compatible` —— Any 兼容一切；同类型兼容；Region/Contour/Points 三类点集互相兼容。

## 三、关键设计决策与约束

### 3.1 端口绑定以 outputName 为主键

- 连线数据结构为 `{fromId, fromPort, toId, toPort}`，`fromPort`/`toPort` 即算子的端口名（outputName）。
- `OutputConfigManager` 的 `outputConfig` 为 `{outputName: {enabled: bool}}`，键与 `fromPort` 完全一致，保证「禁用输出」与「建连校验/多输入执行」读同一主键，无 key 错位。

### 3.2 多输入拓扑排序

- `executeWithFlow` 用 Kahn 算法对算子集做依赖拓扑排序（依赖 = 端口绑定上游），保证每个算子仅在其全部上游执行后运行。
- 检测到环时返回空列表并记 error，`executeWithFlow` 直接失败（`chainCompleted(false)`）。
- 无绑定场景退化为原有线性 `execute()`，向后兼容。

### 3.3 权重持久化

- 仅命中的三个键（typeCompat/structure/frequency）会被写入/读取 `config/recommender.json`，未知 key 的 `setWeight` 直接忽略不持久化。
- 权重总和无强制约束，仅用于线性加权。

### 3.4 资源注册方式

- 算子元数据（含输出项 `group`/`alias`/`priority` 字段）在 `OperatorDescriptors`（`include/UI/OperatorDescriptors.h`）中归一化：`toMap`/`fromMap` 对缺失字段回退默认值（group 取 typeName、alias 取 cnName、priority 默认 100）。
- 元数据可外部化到 `config/operators.json`（`loadFromJson`/`exportToJson`），失败回退 `buildRegistry()`。
- 推荐引擎不新增算子元数据存储，端口类型直接复用 `getOperatorPorts` 返回结构。

## 四、扩展指南

### 4.1 如何新增算子端口

1. 在 `OperatorDescriptors` 的算子元数据 `outputs` / `inputs` 列表中声明端口，字段至少含 `name`（内部名）、`typeName`（类型名）、`cnName`（中文名）。
2. 需要分组/别名/消歧优先级时补充 `group`、`alias`、`priority`（缺省会自动归一化）。
3. 若为外部动态算子，通过 `registerExternalOperator(meta)` 注册（由 `OperatorPluginLoader` 调用）。
4. 端口类型兼容性由 `PortDescriptor::compatible`（C++）与 `OperatorRecommender::portTypesCompatible`（推荐）共同维护，新增类型时需两处同步。

### 4.2 如何接入新冲突类型

1. 在 `OutputConflictDetector::detectAll()` 中新增检测分支，按三个已知字段（`kind`/`nodeId`/`portName`/`detail`/`candidates`）构造 `Conflict` 并 `appendConflict`。
2. 如需新的 `kind` 字符串，在 `ConflictPanel.qml` 的 `kindMeta` 中补充标题与颜色。
3. 如需在「应用」时新增处理逻辑，在 `ConflictPanel.qml::apply()` 中按 `kind` 分支扩展（复用 `updateOutputConfig` / `disconnectEdge` 保证可撤销）。

### 4.3 如何调整推荐权重

- 运行时：在「智能推荐」面板底部拖动三个滑杆，实时调用 `recommender.setWeight(key, value)`，自动持久化。
- 手工：直接编辑可执行目录下 `config/recommender.json`：
  ```json
  {
      "typeCompat": 0.5,
      "structure": 0.3,
      "frequency": 0.2
  }
  ```
  重启后 `loadWeights` 会读取生效。

### 4.4 如何接入新的多输入执行

- 在 `ToolChainExecutor` 上通过 `setFlowBindings` 注入 `FlowBinding` 列表，再调用 `executeWithFlow(primaryInput)`。
- 需要某算子的上游 typed 输入时，在执行后调用 `flowInputsFor(toolId)`（key=下游端口名）。

## 五、与现有 EditViewBridge 的集成点

### 5.1 Q_PROPERTY 暴露（QML 端访问）

```cpp
Q_PROPERTY(QObject* portBindingManager  READ portBindingManager  CONSTANT)  // 端口绑定模型
Q_PROPERTY(QObject* conflictDetector    READ conflictDetector    CONSTANT)  // 冲突检测引擎
Q_PROPERTY(QObject* recommender         READ recommender         CONSTANT)  // 智能推荐引擎
```

- 对应 getter：`portBindingManager()` / `conflictDetector()` / `recommender()`，返回相应协作者实例。
- QML 端通过 `bridge.portBindingManager` / `bridge.conflictDetector` / `bridge.recommender` 访问。

### 5.2 信号转发

- `conflictsChanged()` 由 `EditViewBridge` 追加声明，转发自 `OutputConflictDetector::conflictsChanged()`，供 QML 刷新冲突角标 + `ConflictPanel`。
- `OutputConfigManager` 的 `errorRaised` / `currentNodesChanged` 通过 Qt 信号转发机制回传 `EditViewBridge`，保持其信号契约不变（errorRaised 的 phase 固定为 `"updateOutputConfig"`）。

### 5.3 friend 与数据复用

- `PortBindingManager` / `OutputConflictDetector` / `OperatorRecommender` 均为 `EditViewBridge` 的 friend，可访问 `m_currentNodes` / `m_connections` / `m_useCounts` / `m_recents` / `nodeTypeById` 等私有成员。
- 复用公开方法：`getOutputConfig()` / `updateOutputConfig()` / `checkPortCompatible()` / `getOperatorPorts()` / `getOperatorMeta()` / `getShortDesc()` / `operatorTypes()`。

### 5.4 撤销栈协作

- `OutputConfigManager::updateOutputConfig` 复用 `PropertyChangeCommand`（属性键 `"outputConfig"`），push 进 `undoStack`；无栈时 fallback 直接 `updateParamInternal` 并手动发 `currentNodesChanged`。
- 冲突面板与连接管理面板的删除/建连均走 `disconnectEdge` → `DisconnectNodesCommand`（可撤销）。

### 5.5 QML 面板入口映射

| QML 面板 | 文件 | 桥接调用 |
| --- | --- | --- |
| 算子输出项配置 | `qml/EditView/OperatorEditorDialog.qml` | `bridge.getOutputConfig` / `bridge.updateOutputConfig` |
| 连接管理 | `qml/EditView/ConnectionManagerPanel.qml` | `bridge.connections` / `bridge.disconnectEdge` |
| 冲突指定 | `qml/EditView/ConflictPanel.qml` | `bridge.conflictDetector.detectAll` / `updateOutputConfig` / `disconnectEdge` |
| 智能推荐 | `qml/EditView/RecommendationPanel.qml` | `bridge.recommender.recommend` / `recommendRecent` / `setWeight` / `getWeight` / `addOperator` / `connectNodes` |

`Main.qml` 中：
- 「连」按钮 → `connectionManagerPanel.open()`（`onDeleted` → toast「已删除连接」）。
- 「冲」按钮 → `conflictPanel.open()`（带冲突角标，`onApplied` → toast「已消除 N 处冲突」）。
- `RecommendationPanel` 锚定画布右上角（`anchors.top/right`，`topMargin:44`），`selectedNodeId` 绑定 `currentSelectedNodeId`。
