# Q-DetectVision 测试计划

## 1. 测试目标

确保Q-DetectVision工业视觉检测系统满足需求文档中的所有功能和性能要求，验证系统的正确性、稳定性和安全性，为正式上线提供质量保障。

## 2. 测试范围

### 2.1 功能模块覆盖

| 模块 | 测试重点 |
|------|----------|
| **认证服务** | 用户登录/登出、密码验证、会话管理 |
| **方案管理** | 方案创建、修改、删除、序列化/反序列化 |
| **视觉工具** | 模板匹配、边缘检测、Blob检测、阈值处理等 |
| **工具链执行器** | 多工具串联执行、结果传递 |
| **数据库** | 结果存储、查询、删除、数据完整性 |
| **AI推理** | 模型加载、推理执行、结果解析 |
| **通信模块** | TCP/串口数据输出 |
| **相机管理** | GigE Vision相机配置和图像采集 |
| **UI界面** | 用户交互、状态显示、操作反馈 |

### 2.2 测试层级

| 层级 | 覆盖范围 | 覆盖率要求 |
|------|----------|------------|
| 单元测试 | 核心类和方法 | ≥80% |
| 集成测试 | 模块间接口和交互 | 关键路径全覆盖 |
| 系统测试 | 端到端业务流程 | 核心场景全覆盖 |
| 用户验收测试 | 实际业务场景验证 | 按验收标准 |

## 3. 测试环境配置

### 3.3 测试数据

- 测试图像库：包含正常/缺陷样本的工业图像集

- 测试方案：预设的检测方案配置文件

## 4. 测试用例设计标准

### 4.1 用例分类

1. **正常流程测试**：验证功能在正常输入下的正确性
2. **边界条件测试**：验证边界值和极限情况
3. **异常输入测试**：验证对非法输入的处理能力
4. **性能测试**：验证系统响应时间和吞吐量
5. **安全测试**：验证认证、授权和数据保护

### 4.2 用例编写规范

每个测试用例应包含：
- 用例ID：唯一标识
- 测试目标：明确测试内容
- 前置条件：执行测试前的准备
- 测试步骤：详细操作流程
- 预期结果：期望的输出或行为
- 优先级：P0（关键）、P1（重要）、P2（一般）

### 4.3 优先级定义

| 优先级 | 定义 | 示例 |
|--------|------|------|
| P0 | 关键功能，不通过则无法发布 | 登录认证、核心检测功能 |
| P1 | 重要功能，影响用户体验 | UI交互、数据导出 |
| P2 | 一般功能，不影响核心流程 | 日志记录、辅助功能 |

## 6. 缺陷跟踪机制

### 6.1 缺陷分类

| 类型 | 定义 |
|------|------|
| 功能缺陷 | 功能未实现或实现错误 |
| 性能缺陷 | 响应时间过长或资源占用过高 |
| 安全缺陷 | 存在安全漏洞或数据泄露风险 |
| 界面缺陷 | UI显示或交互问题 |
| 兼容性缺陷 | 环境或设备兼容性问题 |

### 6.2 缺陷优先级

| 优先级 | 定义 | 处理时限 |
|--------|------|----------|
| P0 | 致命缺陷，导致系统崩溃或数据丢失 | 立即修复 |
| P1 | 严重缺陷，影响核心功能使用 | 24小时内 |
| P2 | 一般缺陷，影响部分功能 | 3个工作日 |
| P3 | 轻微缺陷，不影响使用 | 下个版本 |

### 6.3 缺陷状态

```
新建 → 确认 → 分配 → 修复中 → 待验证 → 已验证 → 关闭
           ↓                              ↑
          拒绝 ←───────────────────────────┘
```

### 6.4 缺陷记录格式

| 字段 | 说明 |
|------|------|
| 缺陷ID | 自动生成唯一标识 |
| 标题 | 简洁描述问题 |
| 描述 | 详细复现步骤 |
| 类型 | 功能/性能/安全/界面/兼容性 |
| 优先级 | P0/P1/P2/P3 |
| 状态 | 新建/确认/分配/修复中/待验证/已验证/关闭 |
| 发现人 | 测试人员姓名 |
| 发现时间 | 日期时间 |
| 修复人 | 开发人员姓名 |
| 修复时间 | 日期时间 |
| 测试版本 | 发现缺陷的版本 |
