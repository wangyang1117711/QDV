## 1. 背景与原始需求

用户反馈了三个问题，需要排查并解决：

1. **模型库内的模型不支持多选**，需支持 Shift/Ctrl 多选并做批量操作。
2. **有些模型可以注册，但不能加载**，需排查原因。
3. **模型选择下拉菜单中显示 6 个可选模型，实际模型库已注册 9 个**，需解决数量不一致问题。

## 2. 已完成的改动与验证结果

### 2.1 模型库多选（已通过）

- 文件：`src/TrainingInference/ModelLibraryDialog.cpp`
- 内容：四个 `QListWidget` 全部设为 `ExtendedSelection`，支持 Ctrl/Shift 多选；新增批量注册/删除/验证按钮与多选汇总逻辑（`onModelSelectionChanged`、`showMultiSelectionSummary`）。

### 2.2 下拉菜单数量一致性（已通过）

- 根因：开发环境 `models/` 与运行环境 `build/bin/models/` 目录不一致；`EditViewBridge::getRegisteredModels` 字段映射错误。
- 修复：
  - `apps/SmartVision/CMakeLists.txt`：POST_BUILD 自动部署 `.onnx` 与标签文件到 `build/bin/models/`。
  - `src/AI/ModelManager.cpp`：构造函数无条件调用 `syncManifestWithDirectory()`，启动时扫描目录自动注册新模型。
  - `src/UI/EditViewBridge.cpp`：修正字段映射，正确提取 `file_name/display_name`。
- 验证：启动日志显示 `getRegisteredModels: returning 11 models`，与 `build/bin/models` 下 11 个 `.onnx` 及 manifest 记录完全一致。

### 2.3 best_model 系列无法加载（已通过）

- 根因：`best_model.onnx` 与 `best_model_20260715_174933.onnx` **实为 PyTorch 检查点（ZIP 格式）被错误重命名为 `.onnx`**，不是 ONNX 文件，OpenCV DNN 无法解析。
- 修复：用 `models/classifier.py` 的 `build_classifier('resnet18', num_classes=2)` 重新导出为合法 ONNX（IR 7 / opset 14），已通过 `cv2.dnn.readNetFromONNX` 验证可加载。
- 备份：原检查点保留为
  - `build/bin/models/best_model.onnx.pth.bak`
  - `build/bin/models/best_model_20260715_174933.onnx.pth.bak`
- manifest 最终状态：

```json
{
    "file_name": "best_model.onnx",
    "display_name": "best_model",
    "expected_size": 44700681,
    "loadable": true,
    "load_error": "",
    "sha256": "1027b6255dd7dc17a5a46414e1bfe5a20c70493483c059381aa2f202220a0914"
}
```

### 2.4 非 ONNX 文件注册防御（已通过）

- 文件：`src/AI/ModelManager.cpp`
- 内容：新增 `isValidOnnxFileHeader()`，在 `probeModelLoadability()` 与 `addCustomModel()` 中拦截 ZIP(`PK`) / Pickle(`\x80`) 头的假 `.onnx` 文件，注册时直接报“文件不是有效的 ONNX 格式”。
- 说明：合法 ONNX 文件头以 `\x08\x12`（IR version 字段）或 `\x08:\xe9` 等 protobuf 变长字段开头，不会命中上述黑名单。

## 3. 待办事项（下一步）

### 3.1 resnet50.onnx 仍无法加载（未解决，优先级最高）

- manifest 状态：`loadable=false`。
- 错误：`MatMul` 节点维度不匹配，`K_A=64` 必须等于 `K_B=1000`。
- 说明：这是**合法 ONNX**，并非格式问题，属于模型导出结构问题（`ReduceMean → MatMul` 的维度在 OpenCV DNN 当前实现下不匹配）。
- 可选方案：
  1. 修正导出脚本，将尾部 `ReduceMean + MatMul` 替换为 `GlobalAveragePool + Flatten + Linear/Gemm`。
  2. 引入 ONNX Runtime 后端替代 OpenCV DNN，以支持更多算子与维度组合。
- 参考连接：`src/AI/InferenceEngine.cpp`（当前推理后端封装）。

### 3.2 清理备份（可选）

- 两个 `.pth.bak` 备份共约 268 MB，确认不再需要后可删除以释放空间。

### 3.3 回归验证

- 建议在应用中实际打开模型库，验证多选 + 批量操作交互；在模型下拉菜单中核对数量与 `[不兼容OpenCV]` 标记显示。
