# 插件模块设计文档

> 版本：v2.8.0 | 更新日期：2026-07-22

## 1. 架构概述

插件模块是 QDetectVision 系统的可扩展性基础，允许第三方在不修改主程序源码的前提下，通过动态链接库（DLL）扩展系统能力。模块以静态库 `Plugins` 形式构建，定义统一的插件接口 `IPlugin`，提供基于 `QLibrary` 的动态加载机制，并通过 SHA256 白名单实现签名校验。

### 1.1 模块定位

- **所属层级**：基础设施层（位于 `Core` 之上，被主程序与 UI 调用）
- **构建产物**：`Plugins` 静态库（`src/Plugins/CMakeLists.txt`）
- **运行时依赖**：Qt6 Core（QObject、QLibrary、QCryptographicHash）

### 1.2 子系统组成

| 子系统 | 核心类 | 职责 |
| --- | --- | --- |
| 插件接口 | `IPlugin` | 抽象基类，定义插件生命周期与钩子 |
| 插件管理器 | `PluginManager` | 单例，加载/卸载/枚举插件，SHA256 白名单校验 |
| 插件校验器 | `PluginVerifier` | 插件系统可用性自检 |
| 测试插件 | `TestPlugin` | 示例插件实现，验证插件架构 |

### 1.3 设计原则

1. **Qt 元对象系统兼容**：`IPlugin` 继承 `QObject`，插件可直接使用 signals/slots（P1-C9 + P1-C12 修复）。
2. **C 接口导出**：插件 DLL 通过 `extern "C" Q_DECL_EXPORT` 导出 `createPlugin()` 工厂函数，避免 C++ 名称修饰。
3. **SHA256 白名单**（S3 修复）：加载前校验 DLL 哈希，防止恶意/篡改插件加载。
4. **fail-open 兼容模式**：白名单配置缺失时默认允许加载（兼容旧部署），可通过环境变量强制严格模式。
5. **生命周期完整**：`initialize → enable → 钩子响应 → disable → cleanup` 五阶段管理。

## 2. 核心类与接口

### 2.1 IPlugin（插件接口）

抽象基类，定义插件生命周期与事件钩子。

```cpp
class IPlugin : public QObject {
    Q_OBJECT
public:
    virtual ~IPlugin() = default;

    // 元信息
    virtual QString name() const = 0;
    virtual QString version() const = 0;
    virtual QString description() const { return QString(); }

    // 生命周期
    virtual bool initialize() = 0;     // 初始化内部资源
    virtual bool enable() = 0;          // 启用（开始响应钩子）
    virtual bool disable() = 0;         // 禁用（停止响应钩子，保留资源）
    virtual void cleanup() = 0;         // 释放所有资源

    virtual bool isEnabled() const = 0;

    // 事件钩子（默认空实现，插件按需重写）
    virtual void onSchemeLoaded(Scheme* scheme);
    virtual void onFrameAcquired(const cv::Mat& frame);
    virtual void onToolResult(const ToolResult& result);
};

#define IPlugin_IID "com.qdetectvision.plugin.IPlugin"
Q_DECLARE_INTERFACE(IPlugin, IPlugin_IID)
```

**关键设计要点**（P1-C9 + P1-C12 修复）：

- `IPlugin` 继承 `QObject`，插件无需多继承即可使用 signals/slots。
- `initialize()` 返回 `bool`（原 `void`），与实际语义一致。
- 移除 `QWidget* parent` 参数（从未被任何插件使用）。
- 通过 `Q_DECLARE_INTERFACE` 注册接口 IID，支持 `qobject_cast<IPlugin*>` 类型识别。

### 2.2 PluginManager（插件管理器）

单例管理器，负责插件加载、卸载、枚举与签名校验。

```cpp
class PluginManager : public QObject {
    Q_OBJECT
public:
    static PluginManager* instance();

    bool loadPlugins(const QString& directory);   // 批量加载目录下所有 *.dll
    bool loadPlugin(const QString& filePath);      // 加载单个插件
    void unloadPlugins();                          // 卸载所有插件

    IPlugin* getPlugin(const QString& name);       // 按名称获取插件
    QStringList loadedPlugins() const;             // 已加载插件名列表

signals:
    void pluginLoaded(const QString& name);
    void pluginUnloaded(const QString& name);

private:
    bool verifyPluginHash(const QString& filePath);                 // SHA256 校验
    static QString computeFileSha256(const QString& filePath);      // 分块哈希
    static QString locateTrustedPluginsConfig();                   // 定位白名单配置

    QMap<QString, IPlugin*> m_plugins;
    QMap<QString, QLibrary*> m_libraries;
    static PluginManager* s_instance;
};
```

### 2.3 PluginVerifier（插件校验器）

提供插件系统可用性自检能力。

```cpp
class PluginVerifier : public QObject {
    Q_OBJECT
public:
    QList<PluginVerifyResult> verifyAll();
    PluginVerifyResult verifyTestPluginCreation();       // 插件实例化
    PluginVerifyResult verifyPluginLifecycle();          // 生命周期
    PluginVerifyResult verifyPluginExecution();          // 执行能力
    PluginVerifyResult verifyPluginManagerEnumeration(); // 管理器枚举

    int passedCount() const;
    int totalCount() const;
};
```

### 2.4 TestPlugin（示例插件）

参考实现，演示如何编写一个完整的插件。

```cpp
class TestPlugin : public IPlugin {
    Q_OBJECT
    Q_INTERFACES(IPlugin)
public:
    TestPlugin();

    QString name() const override { return "TestPlugin"; }
    QString version() const override { return "1.0.0"; }
    QString description() const override { return "测试插件 - 验证插件架构"; }

    bool initialize() override;
    bool enable() override;
    bool disable() override;
    void cleanup() override;
    bool isEnabled() const override { return m_enabled; }

    QString executeTest(const QString& input);    // 自定义业务方法

signals:
    void testCompleted(const QString& result);
};

// C 接口工厂函数（必须导出）
extern "C" {
    Q_DECL_EXPORT IPlugin* createPlugin();
}
```

## 3. 数据流

### 3.1 插件加载流程

```
[主程序启动]
      │
      ▼
[PluginManager::loadPlugins(directory)]
      │
      ▼
[检查目录存在性] ── 不存在 ──► Logger::warn ──► return false
      │ 存在
      ▼
[扫描 *.dll 文件]
      │
      ▼
[对每个 DLL 文件调用 loadPlugin()]
      │
      ▼
[verifyPluginHash(filePath)]  ── S3 修复：SHA256 校验
      │
      ├── 校验失败 ──► return false（详细日志已记录）
      │
      └── 校验通过
            │
            ▼
      [QLibrary::load] ── 失败 ──► Logger::error + delete library ──► return false
            │
            ▼
      [library->resolve("createPlugin")] ── 失败 ──► Logger::error ──► return false
            │
            ▼
      [createPlugin() 实例化] ── 返回 null ──► Logger::error ──► return false
            │
            ▼
      [plugin->initialize()] ── 失败 ──► Logger::warn（不阻断加载）
            │
            ▼
      [m_plugins[name] = plugin, m_libraries[name] = library]
            │
            ▼
      [Logger::info + emit pluginLoaded(name)] ──► return true
```

### 3.2 SHA256 校验流程（S3 修复）

```
[verifyPluginHash(filePath)]
      │
      ▼
[locateTrustedPluginsConfig()]
  - <appdir>/config/trusted_plugins.json
  - <appdir>/trusted_plugins.json
      │
      ├── 配置缺失
      │     │
      │     ▼
      │     [检查环境变量 QDV_STRICT_PLUGIN_VERIFY]
      │     │
      │     ├── =1/true/yes ──► Logger::error + return false（严格模式 fail-closed）
      │     │
      │     └── 其他 ──► Logger::warn + return true（兼容模式 fail-open）
      │
      └── 配置存在
            │
            ▼
      [解析 JSON：trusted_plugins 数组]
            │
            ▼
      [computeFileSha256(filePath)]  分块 64KB 读取
            │
            ▼
      [遍历白名单匹配 fileName + sha256]
            │
            ├── 哈希匹配 ──► Logger::info + return true
            │
            ├── 文件名匹配但哈希不匹配 ──► Logger::error "HASH MISMATCH" + return false
            │         （篡改嫌疑）
            │
            └── 文件名不在白名单 ──► Logger::error + return false（fail-closed）
```

### 3.3 插件生命周期流程

```
[loadPlugin() 完成] ──► initialize() 已自动调用
      │
      ▼
[业务模块按需 enable()]
      │
      ▼
[钩子触发（按需）]
  ├── onSchemeLoaded(scheme)      方案加载完成
  ├── onFrameAcquired(frame)      新帧采集
  └── onToolResult(result)        工具执行结果
      │
      ▼
[业务模块按需 disable()]
      │
      ▼
[unloadPlugins()] ──► cleanup() + delete plugin + library->unload()
```

## 4. 配置项

### 4.1 CMake 配置

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| 链接库 | `Qt6::Core` / `Core` | Qt Core + Logger |
| C++ 标准 | `cxx_std_17` | 强制 C++17 |
| 头文件安装 | `include/Plugins/` | IPlugin.h / PluginManager.h |

### 4.2 运行时配置

#### 4.2.1 插件目录

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 插件扫描过滤 | `*.dll` | Windows 动态库 |
| 目录不存在处理 | 警告 + 返回 false | 不创建目录 |
| 空目录处理 | 返回 true | 不视为失败 |

#### 4.2.2 SHA256 白名单配置

**配置文件路径搜索顺序**：

1. `<appdir>/config/trusted_plugins.json`（推荐）
2. `<appdir>/trusted_plugins.json`（兼容）

**配置文件格式**：

```json
{
  "trusted_plugins": [
    {
      "name": "TestPlugin.dll",
      "sha256": "a3f5e8d2c1b9..."
    },
    {
      "name": "MyCustomPlugin.dll",
      "sha256": "f7e4d1c8b2a6..."
    }
  ]
}
```

**校验模式**：

| 模式 | 触发条件 | 行为 |
| --- | --- | --- |
| 严格白名单 | 配置文件存在 | 哈希必须在白名单内，否则拒绝（fail-closed） |
| 兼容模式 | 配置文件缺失 | 记录 CRITICAL 警告但允许加载（fail-open） |
| 强制严格模式 | 环境变量 `QDV_STRICT_PLUGIN_VERIFY=1` | 即使配置缺失也拒绝加载 |

#### 4.2.3 环境变量

| 变量名 | 取值 | 说明 |
| --- | --- | --- |
| `QDV_STRICT_PLUGIN_VERIFY` | `1` / `true` / `yes` | 强制严格模式，配置缺失时拒绝所有插件 |

#### 4.2.4 SHA256 计算参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 分块大小 | 64 KB | `kChunkSize`，避免一次性加载大 DLL 到内存 |
| 哈希算法 | SHA-256 | `QCryptographicHash::Sha256` |
| 输出格式 | 十六进制小写 | `hash.result().toHex()` |

### 5.3 插件运行时依赖

- 插件与主程序的 ABI 兼容性需保证（编译器版本、Qt 版本、STL 实现一致）。

## 6. 安全考虑

### 6.1 SHA256 白名单校验（S3 修复）

- **加载前校验**：在 `QLibrary::load` 之前进行哈希校验，避免恶意 DLL 在内存中执行代码。
- **分块计算**：使用 64 KB 分块读取，避免一次性加载大 DLL 到内存导致内存峰值。
- **篡改检测**：文件名匹配但哈希不匹配时记录 `HASH MISMATCH` 警告，识别可能的篡改行为。
- **fail-closed 默认**：配置文件存在时，未在白名单中的插件一律拒绝加载。

### 6.2 兼容模式安全降级

- 配置文件缺失时默认 fail-open（兼容旧部署），但记录 CRITICAL 警告提示部署方迁移到严格模式。
- 通过环境变量 `QDV_STRICT_PLUGIN_VERIFY=1` 可在配置缺失时强制严格模式。

### 6.3 资源释放

- `unloadPlugins()` 严格按顺序释放：先 `plugin->cleanup()` → `delete plugin` → `library->unload()` → `delete library`。
- 析构函数自动调用 `unloadPlugins()`，避免插件资源泄漏。

### 6.4 加载失败容错

- 单个插件加载失败不阻断其他插件加载（`loadPlugins` 返回 `allLoaded` 聚合结果）。
- `initialize()` 失败不阻断插件注册（仅记录警告），允许后续手动重试。

### 6.5 接口兼容性（P1-C9 + P1-C12 修复）

- `IPlugin` 继承 `QObject` 并通过 `Q_DECLARE_INTERFACE` 注册 IID，支持 `qobject_cast` 安全类型识别。
- 接口变更需要外部插件重新编译，建议通过 `version()` 字段标记兼容性。

### 6.6 已知风险

- **ABI 兼容性**：插件与主程序编译器版本、Qt 版本必须一致，否则可能崩溃。建议在白名单配置中加入 `compiler` / `qt_version` 字段。
- **DLL 劫持**：若插件目录可写，攻击者可能替换合法插件。建议插件目录设置只读权限。
- **钩子异常传播**：插件钩子（`onSchemeLoaded` 等）抛出异常未捕获时可能影响主流程。建议在 `PluginManager` 调用钩子时包裹 try-catch。

## 7. 后续改进计划

### 7.1 已识别的待改进项

1. **插件热加载**：当前插件在启动时一次性加载，不支持运行时动态加载/卸载。可通过文件系统监视器（`QFileSystemWatcher`）监听插件目录变化实现热加载。
2. **插件依赖管理**：当前插件相互独立，缺少插件间依赖声明机制。可在 manifest 中加入 `dependencies` 字段。
3. **插件元信息扩展**：当前 `IPlugin` 仅暴露 `name/version/description`，建议扩展 `author/license/homepage/minQdvVersion` 等字段。
4. **插件配置 UI**：缺少插件配置界面，用户无法在主程序内启用/禁用/配置插件。
5. **插件市场**：当前插件通过文件分发，可建设插件市场支持在线安装与更新。
6. **跨平台支持**：当前仅扫描 `*.dll`，Linux 应扫描 `*.so`，macOS 应扫描 `*.dylib`。
7. **沙箱隔离**：当前插件与主程序同进程运行，恶意插件可访问全部内存。可考虑进程级沙箱隔离。
8. **签名链验证**：当前仅校验 SHA256 哈希，可扩展为代码签名证书验证（如 Authenticode）。
9. **钩子异常捕获**：建议在 `PluginManager` 调用钩子时包裹 try-catch，避免插件异常影响主流程。
10. **插件统计**：缺少插件调用次数、执行时长等统计，便于性能优化。

### 7.2 建议的演进方向

- **插件 manifest.json**：每个插件附带 manifest，声明依赖、版本、权限需求、钩子订阅列表。
- **权限系统**：插件在 manifest 中声明所需权限（文件访问、网络访问、相机访问），主程序按需授权。
- **插件 SDK 独立发布**：将 `IPlugin.h` 与开发文档打包为独立 SDK，降低第三方开发门槛。
- **Lua/Python 脚本插件**：除 C++ DLL 插件外，支持脚本插件降低开发门槛（与 `ScriptTool` 模块协同）。
- **插件性能监控**：集成 `Monitoring` 模块，统计每个插件的钩子执行时长，识别性能瓶颈。
