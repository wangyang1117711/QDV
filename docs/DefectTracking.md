# Q-DetectVision 缺陷跟踪机制

## 1. 缺陷跟踪流程

### 1.1 流程概述

```
新建 → 确认 → 分配 → 修复中 → 待验证 → 已验证 → 关闭
           ↓                              ↑
          拒绝 ←───────────────────────────┘
```

### 1.2 状态定义

| 状态 | 说明 | 操作 |
|------|------|------|
| 新建 | 发现缺陷，待确认 | 验证缺陷是否存在 |
| 确认 | 缺陷已确认存在 | 分配给开发人员 |
| 分配 | 已分配给开发人员 | 开始修复 |
| 修复中 | 开发人员正在修复 | 提交修复代码 |
| 待验证 | 修复完成，等待测试验证 | 执行回归测试 |
| 已验证 | 测试验证通过 | 关闭缺陷 |
| 关闭 | 缺陷已修复并验证 | 归档 |
| 拒绝 | 缺陷不成立或无法复现 | 记录拒绝原因 |

## 2. 缺陷分类标准

### 2.1 缺陷类型

| 类型 | 定义 | 示例 |
|------|------|------|
| 功能缺陷 | 功能未实现或实现错误 | 登录失败、检测结果错误 |
| 性能缺陷 | 响应时间过长或资源占用过高 | 图像处理卡顿、内存泄漏 |
| 安全缺陷 | 存在安全漏洞或数据泄露风险 | 密码明文存储、SQL注入 |
| 界面缺陷 | UI显示或交互问题 | 按钮失效、布局错乱 |
| 兼容性缺陷 | 环境或设备兼容性问题 | 特定相机不识别 |

### 2.2 缺陷优先级

| 优先级 | 定义 | 处理时限 | 示例 |
|--------|------|----------|------|
| P0 | 致命缺陷，导致系统崩溃或数据丢失 | 立即修复 | 认证失败、数据库连接失败 |
| P1 | 严重缺陷，影响核心功能使用 | 24小时内 | 检测工具执行失败 |
| P2 | 一般缺陷，影响部分功能 | 3个工作日 | UI布局问题 |
| P3 | 轻微缺陷，不影响使用 | 下个版本 | 日志格式问题 |

## 3. 缺陷记录模板

### 3.1 缺陷报告格式

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 缺陷ID | 自动生成 | 是 | 唯一标识 |
| 标题 | 字符串 | 是 | 简洁描述问题 |
| 描述 | 文本 | 是 | 详细复现步骤 |
| 类型 | 下拉选择 | 是 | 功能/性能/安全/界面/兼容性 |
| 优先级 | 下拉选择 | 是 | P0/P1/P2/P3 |
| 状态 | 自动更新 | 是 | 新建/确认/分配/修复中/待验证/已验证/关闭 |
| 发现人 | 字符串 | 是 | 测试人员姓名 |
| 发现时间 | 日期时间 | 是 | 自动记录 |
| 修复人 | 字符串 | 否 | 开发人员姓名 |
| 修复时间 | 日期时间 | 否 | 修复完成时间 |
| 测试版本 | 字符串 | 是 | 发现缺陷的版本号 |
| 复现步骤 | 文本 | 是 | 详细操作步骤 |
| 预期结果 | 文本 | 是 | 期望的行为 |
| 实际结果 | 文本 | 是 | 实际发生的行为 |
| 截图/日志 | 附件 | 否 | 辅助信息 |
| 拒绝原因 | 文本 | 否 | 拒绝时填写 |

### 3.2 缺陷报告示例

```
缺陷ID: DEF-001
标题: 登录功能使用空密码可成功登录
描述: 在登录界面输入用户名但密码为空时，系统允许登录成功
类型: 安全缺陷
优先级: P0
状态: 确认
发现人: 张三
发现时间: 2026-05-19 10:30:00
测试版本: v1.0.0
复现步骤:
    1. 打开登录界面
    2. 输入用户名"admin"
    3. 密码输入框留空
    4. 点击登录按钮
预期结果: 登录失败，提示密码不能为空
实际结果: 登录成功，进入主界面
```

## 4. 缺陷统计与分析

### 4.1 统计指标

| 指标 | 说明 | 计算公式 |
|------|------|----------|
| 缺陷密度 | 每千行代码的缺陷数 | 缺陷总数 / 代码行数 × 1000 |
| 修复率 | 已修复缺陷占总缺陷的比例 | 已修复数 / 总缺陷数 × 100% |
| 平均修复时间 | 缺陷从发现到修复的平均时长 | 总修复时间 / 已修复数 |
| P0缺陷清零率 | P0缺陷修复完成的比例 | 已修复P0数 / 总P0数 × 100% |

### 4.2 趋势分析

- 按周统计新增缺陷数量
- 按模块统计缺陷分布
- 按优先级统计缺陷处理进度
- 分析缺陷发现率与测试进度的关系

## 5. 缺陷跟踪工具

### 5.1 工具选择

推荐使用以下工具之一进行缺陷跟踪：

1. **Jira** - 企业级项目管理工具，支持自定义工作流
2. **GitHub Issues** - 轻量级缺陷跟踪，适合开源项目
3. **Trello** - 看板式管理，适合小型团队
4. **Excel/Google Sheets** - 简单表格记录，适合小型项目

### 5.2 自定义字段

根据项目需求，可添加以下自定义字段：

- 所属模块
- 关联测试用例
- 关联代码提交
- 影响范围
- 回归测试状态

## 6. 缺陷管理策略

### 6.1 P0缺陷处理流程

1. 发现P0缺陷立即通知技术负责人
2. 开发人员暂停当前工作，优先修复P0缺陷
3. 修复完成后立即进行回归测试
4. 验证通过后更新缺陷状态为"已验证"

### 6.2 缺陷复盘

定期（如每周）召开缺陷复盘会议：

- 分析高优先级缺陷的根本原因
- 总结预防措施
- 优化测试用例覆盖
- 更新开发规范

### 6.3 缺陷关闭标准

缺陷关闭需满足以下条件：

- 缺陷已修复并通过回归测试
- 相关测试用例已更新
- 修复代码已提交并经过代码审查
- 文档已更新（如需要）
