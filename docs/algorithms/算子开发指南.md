# 算子开发指南

**版本**: 1.0 · 适用于 Q-DetectVision v2.6.0+ OperatorSDK

本指南介绍如何基于 OperatorSDK 开发视觉算子，包括架构总览、manifest 规范、开发步骤、模板脚本使用、参考实现解读与测试编写。

---

## 1. OperatorSDK 架构总览

OperatorSDK 采用**接口+插件**架构，核心组件如下：

| 组件 | 头文件 | 职责 |
|------|--------|------|
| `IOperator` | `OperatorSDK/IOperator.h` | 算子接口，定义 `execute/configure/clone/type/version` 等纯虚函数 |
| `IInferenceEngine` | `OperatorSDK/IInferenceEngine.h` | 推理引擎接口（深度学习算子用） |
| `IOperatorRegistry` | `OperatorSDK/IOperatorRegistry.h` | 算子注册表单例，管理 type→creator 映射 |
| `OperatorManifest` | `OperatorSDK/OperatorManifest.h` | manifest.json 解析结构 + `loadPlugin/loadAndRegister` 自由函数 |
| `MockOperatorBase` | `OperatorSDK/MockOperatorBase.h` | mock 算子共享基类，封装占位输出逻辑 |

### 1.1 继承体系

```
VisionTool (include/Core/VisionTool.h)
    └── IOperator (OperatorSDK/IOperator.h)
            ├── MockOperatorBase  (mock 算子基类)
            │   ├── MockGaussFilterOperator
            │   ├── MockClassifyOperator
            │   └── ... (37 个 mock)
            └── HistogramOperator (真实算子参考实现)
```

> **注意**: `VisionTool` 不继承 `QObject`，因此算子无 `setObjectName` 等方法。`ToolResult` 是 POD 结构体，定义在 `VisionTool.h` 中。

### 1.2 核心接口 IOperator

```cpp
class IOperator : public VisionTool {
public:
    virtual ~IOperator() = default;
    virtual QString type() const = 0;       // 算子类型名（与 manifest.type 一致）
    virtual QString version() const = 0;    // 接口版本（与 manifest.version 一致）
    virtual bool execute(const cv::Mat& input, ToolResult& result) = 0;
    virtual bool configure(const QJsonObject& params) = 0;
    virtual IOperator* clone() const = 0;
    virtual void setInferenceEngine(IInferenceEngine* engine) { Q_UNUSED(engine) }
};
```

### 1.3 算子加载流程

```
主程序启动
  └── OperatorPluginLoader::loadAndRegister(libPath)
        ├── LoadLibraryA(libPath)                       # 加载 .dll
        ├── 解析 operator_type/operator_version/create_operator 符号
        ├── 读取同目录 manifest.json                     # 元数据
        ├── 校验 dll version == manifest.version         # RT-003 版本匹配
        └── IOperatorRegistry::registerOperator(type, version, creator)
              └── 后续可通过 createOperator(type) 创建实例
```

## 2. manifest.json 字段规范

每个算子目录下必须有 `manifest.json`，字段如下：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 算子类型名（与 `IOperator::type()` 一致，如 `"GaussFilter"`） |
| `version` | string | 是 | 接口版本（如 `"1.0.0"`，必须与 dll 导出的 `operator_version()` 一致） |
| `cnName` | string | 是 | 中文显示名 |
| `category` | string | 是 | 分类（如 `"预处理"`、`"形态学"`） |
| `iconPath` | string | 否 | 图标资源路径（如 `"qrc:/icons/foo.svg"`） |
| `description` | string | 否 | 简要描述 |
| `library` | string | 是 | 动态库文件名（如 `"MockGaussFilter.dll"`） |
| `params` | array | 否 | 参数列表（见下） |
| `isMock` | bool | 否 | 是否为 mock 算子（默认 false） |
| `agentRole` | string | 否 | 对应的 Agent 角色（仅 mock 算子用，如 `"Reviewer"`） |

### 2.1 params 数组元素结构

```json
{
    "name": "kernelSize",
    "cnName": "核大小",
    "type": 0,
    "defaultValue": 5,
    "minValue": 1,
    "maxValue": 31,
    "step": null,
    "unit": "",
    "options": [],
    "optionKeys": [],
    "help": "奇数，1~31"
}
```

`type` 字段含义（与 `UI::ParamSpec::Type` 对应）：
- `0` = 整数（int）
- `2` = 枚举（enum，配合 `options`/`optionKeys`）
- `4` = 字符串（string）
- 其他类型见 `include/UI/OperatorDescriptors.h`

## 3. 独立 dll 开发步骤

每个算子编译为独立 `.dll`，部署到 `bin/operators/` 目录。

### 3.1 目录结构

```
src/operators/extensions/<OperatorName>/
├── CMakeLists.txt          # 编译为 SHARED 库
├── manifest.json           # 元数据
├── <OperatorName>Operator.h   # 头文件
└── <OperatorName>Operator.cpp # 实现文件
```

### 3.2 开发流程

1. **创建目录**: `src/operators/extensions/<OperatorName>/`
2. **编写 manifest.json**: 按 §2 规范填写
3. **编写头文件**: 继承 `IOperator`（真实算子）或 `MockOperatorBase`（mock 算子）
4. **编写实现文件**: 实现 `execute()` + 导出 C API（`operator_type`/`operator_version`/`create_operator`）
5. **编写 CMakeLists.txt**: 编译为 SHARED，链接 `OperatorSDK` + `Qt6::Core` + `OpenCV`
6. **注册到主 CMakeLists.txt**: 添加 `add_subdirectory(src/operators/extensions/<OperatorName>)`
7. **编译部署**: 构建后 dll 自动输出到 `bin/operators/`，manifest.json 复制为 `<OperatorName>.json`

### 3.3 C API 导出规范

每个算子 dll 必须导出以下 3 个 C 函数：

```cpp
extern "C" {
    QDV_EXPORT const char* operator_type();      // 返回算子 type 名
    QDV_EXPORT const char* operator_version();   // 返回接口版本
    QDV_EXPORT QDV::IOperator* create_operator(); // 创建算子实例
}
```

## 4. 模板脚本使用

推荐使用 `tools/operator_template_gen.py` 一键生成算子骨架，避免手写样板代码。

### 4.1 生成 mock 算子

```bash
python tools/operator_template_gen.py \
    --type MockNewOp \
    --cn-name "新mock算子" \
    --category "预处理" \
    --mock \
    --description "测试用 mock"
```

### 4.2 生成真实算子

```bash
python tools/operator_template_gen.py \
    --type NewFilter \
    --cn-name "新滤波器" \
    --category "预处理" \
    --real \
    --params '[{"name":"ksize","type":0,"defaultValue":5,"minValue":1,"maxValue":31}]'
```

### 4.3 生成 Agent 角色 mock 算子

```bash
python tools/operator_template_gen.py \
    --type MockNewAgent \
    --cn-name "新Agent算子" \
    --category "Agent协作" \
    --mock \
    --agent-role Reviewer \
    --description "模拟评审判定"
```

### 4.4 生成后步骤

1. 将 `add_subdirectory(src/operators/extensions/<OperatorName>)` 添加到根 `CMakeLists.txt`
2. (real 模式) 在 `<OperatorName>Operator.cpp` 中实现 `execute()` 方法
3. 重新编译项目

## 6. MockOperatorBase 使用

mock 算子继承 `MockOperatorBase`，只需实现 `mockTag()` 和 `clone()`，基类封装了通用逻辑。

### 6.1 基类行为

```cpp
bool MockOperatorBase::execute(const cv::Mat& input, ToolResult& result) {
    validateParams(m_params);              // 子类可重写校验逻辑
    cv::Mat placeholder = generatePlaceholder(input);  // 输入非空则克隆，否则生成 64x64 占位图
    QString outPath = savePlaceholder(placeholder);    // 保存到临时目录
    result.ok = true;
    result.data = buildMockResult(outPath, input);     // 构造 [MOCK] 标注的 data
    result.score = 1.0;
    result.overlayImage = placeholder;
    return true;
}
```

### 6.2 子类最小实现

```cpp
// MockGaussFilterOperator.h
class MockGaussFilterOperator : public MockOperatorBase {
public:
    QString type() const override { return "GaussFilter"; }
    IOperator* clone() const override { return new MockGaussFilterOperator(*this); }
protected:
    QString mockTag() const override { return "GaussFilter"; }
};
```

### 6.3 Agent 角色 mock 算子

Agent 角色 mock 算子需重写 `buildMockResult` 以携带 `agentRole` 字段：

```cpp
QJsonObject buildMockResult(const QString& outPath, const cv::Mat& input) const override {
    QJsonObject data = MockOperatorBase::buildMockResult(outPath, input);
    data["agentRole"] = "Reviewer";
    data["description"] = "模拟评审判定";
    return data;
}
```

## 7. 测试编写指南

### 7.1 C++ 测试（Catch2）

参考 `tests/Operators/test_histogram.cpp` 和 `test_mock_base.cpp`。

**关键要点**：
- 使用 `tests/catch2/catch2_minimal.hpp`
- `TEST_CASE` 宏需要**两个参数**: `(name, tag)`，如 `TEST_CASE("test foo", "[mock]")`
- 测试算子加载用 `QDV::loadPlugin(libPath, manifest, &err)` + `QDV::IOperatorRegistry::instance().createOperator(type)`
- `OperatorPluginLoader` 不是类，是 `QDV` 命名空间内的自由函数

### 7.2 Python 脚本测试（pytest）

参考 `tests/tools/test_template_gen.py`。

- 测试 `generate_operator()` 函数时传入 `ext_dir=tmp_path` 避免污染真实目录
- 测试 `generate_docs()` 函数时传入 `root_dir=tmp_path` 构造最小化项目结构

### 7.3 测试注册

C++ 测试需在 `tests/CMakeLists.txt` 中注册：

```cmake
add_executable(QDV_tests
    # ...
    tests/Operators/test_your_operator.cpp
)
target_link_libraries(QDV_tests PRIVATE YourOperatorLib)
```

## 8. 常见问题与调试技巧

### 8.1 Unicode 路径问题

**问题**: `cv::imread` 在 Windows 下无法读取含中文的路径。

**解决**: 使用 `QFile` + `cv::imdecode` 替代：

```cpp
QFile f(path);
f.open(QIODevice::ReadOnly);
QByteArray data = f.readAll();
std::vector<uchar> buf(data.begin(), data.end());
cv::Mat img = cv::imdecode(buf, cv::IMREAD_COLOR);
```

### 8.2 算子 dll 加载失败

**排查步骤**:
1. 确认 dll 存在于 `bin/operators/` 目录
2. 确认同目录存在 `<OperatorName>.json`（构建时由 `add_custom_command` 自动复制）
3. 检查 dll 导出的 `operator_version()` 与 manifest.json 的 `version` 字段是否一致（RT-003）
4. 用 `dumpbin /exports`（MSVC）或 `objdump -p`（MinGW）确认导出符号

### 8.3 mock 算子与真实算子混淆

**规范**:
- mock 算子的 `manifest.json` 必须设 `isMock: true`
- mock 算子的 `ToolResult.reason` 必须含 `[MOCK]` 前缀
- UI 可根据 `isMock` 字段标注算子为"模拟"

### 8.4 重复注册问题（RT-001）

`IOperatorRegistry::registerOperator` 对重复 type 返回 false。若需重新加载同一算子，需先清理注册表或重启程序。

### 8.5 ImagePreprocessTool 参数校验

`kernelSize` 参数需校验：`<1` 钳制为 1，`>31` 钳制为 31，偶数调整为奇数（高斯滤波要求）。
