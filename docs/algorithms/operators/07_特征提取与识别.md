## PointsHarris（Harris 角点）

### 核心含义
Harris 角点检测算子提取图像中的角点特征，角点是两条或多条边缘交汇的点，具有局部灰度变化剧烈的特性。Harris 角点是计算机视觉中最经典的特征点之一，广泛应用于图像配准、目标跟踪、三维重建等场景。

该算子对旋转不变，对光照变化有一定鲁棒性，但对尺度变化敏感。

### 原理简述
算子调用 OpenCV `cv::cornerHarris` 函数，计算每个像素的 Harris 角点响应值。算法核心步骤：

1. 计算图像在 x、y 方向的梯度 `Ix`、`Iy`。
2. 在窗口大小 `blockSize` 内计算梯度自相关矩阵 `M = [[ΣIx², ΣIxIy], [ΣIxIy, ΣIy²]]`。
3. 计算角点响应 `R = det(M) - k·trace(M)²`，其中 `k` 为自由参数。
4. 对响应图进行阈值化（`threshold`），响应值大于阈值的像素为角点。

`blockSize` 决定邻域窗口大小，`ksize` 为 Sobel 梯度算子大小，`k` 通常取 0.04~0.06。

### 适用场景
- 场景1：图像配准与拼接，提取角点作为匹配特征。
- 场景2：目标跟踪，角点作为稳定的跟踪点。
- 场景3：标定板角点提取，用于相机标定。

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| blockSize | 邻域大小 | Int | 3 | 2 ~ 15 | px | Harris 窗口大小，步长 2 |
| ksize | Sobel 核 | Int | 3 | 3 ~ 7 | - | 梯度计算核大小，步长 2 |
| k | k 参数 | Double | 0.04 | 0.01 ~ 0.25 | - | Harris 方程自由参数，步长 0.01 |
| threshold | 阈值 | Double | 100 | 1 ~ 10000 | - | 角点响应阈值，步长 10 |

### 输入输出
- **输入**：单通道灰度图像（Mat）。建议输入清晰、边缘锐利的图像。
- **输出**：
  - `points`（Point[]）：角点，类型为 Point 数组，描述为"Harris角点检测结果"。

### 使用示例
提取标定板角点：
```json
{
  "type": "PointsHarris",
  "params": {
    "blockSize": 3,
    "ksize": 3,
    "k": 0.04,
    "threshold": 200
  }
}
```
步骤说明：使用默认邻域大小 3 和 Sobel 核 3，`k=0.04` 为标准值，`threshold=200` 提高阈值只保留响应最强的角点，适用于标定板角点提取。

### 注意事项
- `threshold` 过低会产生大量弱角点，过高则漏检，需根据图像对比度调整。
- `k` 参数取值范围通常为 0.04~0.06，过大会减少角点数量，过小会增加误检。
- Harris 角点对尺度变化敏感，若目标尺度变化大建议改用 SIFT 或 SURF（若项目支持）。
- `blockSize` 和 `ksize` 必须为奇数（步长为 2 保证奇数）。

### 关联算子
- [EdgesSubPix](#edgessubpix亚像素边缘)：边缘检测可与角点检测配合提取完整特征。
- [LineCircleDetect](#linecircledetect线圆检测)：角点可用于辅助直线/圆的拟合。
- [FindNccModel](08_匹配定位.md#findnccmodelncc匹配)：角点可作为匹配的预处理特征。

## LineCircleDetect（线圆检测）

### 核心含义
线圆检测算子基于 Hough 变换检测图像中的直线、直线段或圆。支持三种检测模式：标准直线（HoughLines）、概率直线（HoughLinesP）、圆（HoughCircles），能够适应不同的几何特征提取需求。

该算子是几何测量的基础工具，常用于提取工件的边缘直线或圆形特征用于尺寸测量。

### 原理简述
Hough 变换将图像空间中的几何形状检测转换为参数空间的投票问题：

- **标准直线（HoughLines）**：使用 `(ρ, θ)` 参数空间，`ρ = x·cos(θ) + y·sin(θ)`。每个边缘点在参数空间投票，峰值对应检测到的直线。`rho` 为距离分辨率，`theta` 为角度分辨率。
- **概率直线（HoughLinesP）**：标准直线的概率变体，直接输出线段端点。`minLineLength` 为最短线长，`maxLineGap` 为允许的最大断裂间隙。
- **圆（HoughCircles）**：使用 `(cx, cy, r)` 参数空间。`dp` 为累加器分辨率比，`minDist` 为圆心最小距离，`param1` 为 Canny 高阈值，`param2` 为圆心累加阈值。`minRadius`/`maxRadius` 限制半径范围。

### 适用场景
- 场景1：工件边缘直线提取，用于尺寸测量或角度计算。
- 场景2：圆形零件（如孔、轴）的中心定位与半径测量。
- 场景3：道路或车道线检测（概率直线模式）。

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| detectType | 检测类型 | Enum | lineP | line / lineP / circle | - | line=HoughLines，lineP=HoughLinesP，circle=HoughCircles |
| rho | rho（像素） | Double | 1 | 0.1 ~ 10 | px | 距离分辨率（像素），步长 0.1 |
| theta | theta（弧度） | Double | 0.0174532925 | 0.001 ~ 3.14159 | rad | 角度分辨率（弧度），步长 0.001 |
| threshold | 累加器阈值 | Int | 100 | 1 ~ 1000 | - | 最小投票数，步长 10 |
| minLineLength | 最小线长 | Double | 50 | 0 ~ 10000 | px | lineP 专用，步长 10 |
| maxLineGap | 最大线段间隙 | Double | 10 | 0 ~ 1000 | px | lineP 专用，步长 1 |
| minRadius | 最小半径 | Double | 20 | 1 ~ 10000 | px | circle 专用，步长 1 |
| maxRadius | 最大半径 | Double | 200 | 1 ~ 10000 | px | circle 专用，步长 1 |
| dp | 累加器分辨率比 | Double | 1 | 0.1 ~ 10 | - | circle 专用（HoughCircles 的 dp），步长 0.1 |
| minDist | 圆心最小距离 | Double | 50 | 1 ~ 10000 | px | circle 专用，步长 1 |
| param1 | Canny 高阈值 | Double | 150 | 1 ~ 1000 | - | circle 专用，步长 1 |
| param2 | 圆心累加阈值 | Double | 30 | 1 ~ 1000 | - | circle 专用，步长 1 |

### 输入输出
- **输入**：单通道灰度图像（Mat）。建议先做边缘检测（Canny）或阈值化以提升检测精度。
- **输出**：
  - `shapes`（Shape[]）：检测图形，类型为 Shape 数组，描述为"直线/圆检测结果"。

### 使用示例
检测直线段：
```json
{
  "type": "LineCircleDetect",
  "params": {
    "detectType": "lineP",
    "rho": 1,
    "theta": 0.0174532925,
    "threshold": 80,
    "minLineLength": 100,
    "maxLineGap": 15
  }
}
```
步骤说明：使用概率直线模式，`minLineLength=100` 过滤短线段，`maxLineGap=15` 允许连接有断裂的线段。

检测圆形目标：
```json
{
  "type": "LineCircleDetect",
  "params": {
    "detectType": "circle",
    "dp": 1,
    "minDist": 50,
    "param1": 150,
    "param2": 30,
    "minRadius": 30,
    "maxRadius": 100
  }
}
```

### 注意事项
- `detectType` 不同时，参数生效范围不同：`minLineLength`/`maxLineGap` 仅对 `lineP` 有效，`minRadius`/`maxRadius`/`dp`/`minDist`/`param1`/`param2` 仅对 `circle` 有效。
- `param2`（圆心累加阈值）越小越容易检测到圆，但误检也会增加，建议从 30 开始调整。
- Hough 变换计算量较大，对大图像建议先缩小或限定 ROI 区域。
- 输入图像应先做边缘检测，否则检测效果会显著下降。

### 关联算子
- [EdgesSubPix](#edgessubpix亚像素边缘)：提供高质量边缘作为 Hough 输入。
- [GeometryMeasure](09_几何测量.md#geometrymeasure几何测量)：基于检测到的直线/圆进行尺寸测量。
- [AngleLl](09_几何测量.md#anglell线到线角度)：基于检测到的直线计算夹角。
- [ContourAnalyze](06_Blob与轮廓分析.md#contouranalyze轮廓分析)：轮廓提取后配合线圆检测进行拟合。

## EdgesSubPix（亚像素边缘）

### 核心含义
亚像素边缘检测算子提取图像中精度高于像素级别的边缘轮廓。与传统像素级边缘检测（如 Canny）不同，亚像素边缘检测能够将边缘定位精度提升至 0.1 像素以下，适用于高精度测量场景。

该算子类似 HALCON 的 `edges_sub_pix`，输出连续的边缘轮廓而非离散的边缘点。

### 原理简述
算子基于 Canny 边缘检测框架，结合亚像素插值实现高精度边缘定位：

1. 对图像进行高斯平滑（`alpha` 为标准差），抑制噪声。
2. 计算梯度幅值和方向。
3. 使用双阈值（`lowThreshold`、`highThreshold`）进行滞后阈值化，`lowThreshold` 与 `highThreshold` 比例通常为 1:2 或 1:3。
4. 对边缘点沿梯度方向进行亚像素插值（如抛物线拟合或零交叉定位），将边缘位置精确到亚像素级别。

`alpha` 控制平滑程度，值越大平滑越强但边缘细节丢失越多。

### 适用场景
- 场景1：高精度尺寸测量，需要亚像素级边缘定位。
- 场景2：精密零件边缘提取，用于对位对齐。
- 场景3：圆形或椭圆形目标的精确轮廓提取，配合拟合算法。

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| lowThreshold | 低阈值 | Int | 20 | 1 ~ 255 | - | Canny 低阈值，步长 1 |
| highThreshold | 高阈值 | Int | 60 | 1 ~ 255 | - | Canny 高阈值，步长 1 |
| alpha | 平滑系数 | Double | 0.7 | 0.1 ~ 100 | - | 高斯平滑标准差（alpha），步长 0.1 |

### 输入输出
- **输入**：单通道灰度图像（Mat）。建议输入对比度较高、噪声较低的图像。
- **输出**：
  - `edges`（Contour[]）：亚像素边缘，类型为 Contour 数组，描述为"亚像素精度边缘轮廓"。

### 使用示例
高精度边缘提取：
```json
{
  "type": "EdgesSubPix",
  "params": {
    "lowThreshold": 30,
    "highThreshold": 60,
    "alpha": 1.0
  }
}
```
步骤说明：低阈值 30、高阈值 60（比例 1:2），`alpha=1.0` 适度平滑，输出亚像素级边缘轮廓用于精密测量。

### 注意事项
- `highThreshold` 应大于 `lowThreshold`，推荐比例为 2:1 或 3:1。
- `alpha` 过大会导致边缘模糊，丢失细节；过小则对噪声敏感。典型取值 0.5~1.5。
- 亚像素精度依赖于图像质量，噪声较大时精度会下降。
- 输出为轮廓数组，每条轮廓为有序的点序列，可直接用于拟合。

### 关联算子
- [LineCircleDetect](#linecircledetect线圆检测)：亚像素边缘可作为 Hough 变换的高质量输入。
- [ContourAnalyze](06_Blob与轮廓分析.md#contouranalyze轮廓分析)：像素级轮廓提取，与亚像素边缘互补。
- [GeometryMeasure](09_几何测量.md#geometrymeasure几何测量)：基于亚像素边缘进行高精度测量。
- [FindShapeModel](08_匹配定位.md#findshapemodel形状匹配)：亚像素边缘可用于创建高精度形状模板。

## QrCodeDetect（二维码识别）

### 核心含义
二维码识别算子使用 OpenCV `cv::QRCodeDetector` 检测并解码图像中的二维码，输出解码文本和识别到的二维码数量。该算子无需任何参数配置，开箱即用。

支持常见的 QR 码格式，适用于产品追溯、物料识别、设备标识等场景。

### 原理简述
算子调用 OpenCV `cv::QRCodeDetector` 的 `detectAndDecode` 方法，内部流程：

1. **定位**：通过寻找三个定位图案（Finder Pattern，即二维码三个角的方块）确定二维码的位置和方向。
2. **校正**：根据定位图案计算透视变换矩阵，将倾斜的二维码校正为正方形。
3. **采样**：在校正后的图像中按网格采样模块数据。
4. **解码**：根据二维码编码规范（Reed-Solomon 纠错、掩码、数据编码模式）解码出文本内容。

### 适用场景
- 场景1：产品追溯，识别产品上的二维码获取生产信息。
- 场景2：物料管理，扫描物料标签二维码进行入库/出库登记。
- 场景3：设备标识，读取设备铭牌二维码获取配置信息。

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| （无参数） | - | - | - | - | - | 该算子无需配置参数，直接对输入图像进行检测 |

### 输入输出
- **输入**：灰度或彩色图像（Mat）。二维码应占据图像较大比例且清晰可见。
- **输出**：
  - `text`（string）：解码文本，类型为 string，描述为"二维码解码结果"。
  - `count`（int）：数量，类型为 int，描述为"识别到的二维码数量"。

### 使用示例
识别产品二维码：
```json
{
  "type": "QrCodeDetect",
  "params": {}
}
```
步骤说明：直接对输入图像调用二维码识别，无需任何参数。若图像中存在二维码，将输出解码文本和识别数量。

### 注意事项
- 二维码识别对图像清晰度要求较高，模糊或过小的二维码可能无法识别。
- 图像中存在多个二维码时，`count` 反映识别到的数量，`text` 包含解码结果。
- 光照不均或反光会干扰定位图案检测，建议保证均匀照明。
- 该算子仅支持 QR 码，不支持 DataMatrix、PDF417 等其他二维码格式。

### 关联算子
- [Barcode1d](#barcode1d一维码识别)：一维码识别，与二维码互补。
- [Ocr](#ocr字符识别)：当无二维码时可用 OCR 识别文字信息。
- [Threshold](05_图像分割.md#threshold阈值分割)：预处理提升二维码对比度。

## Barcode1d（一维码识别）

### 核心含义
一维码识别算子基于纯 OpenCV 实现线剖面解码，目前支持 EAN-13 格式的一维码自动解码。算子通过扫描图像中的条码线纹，提取黑白条宽度序列并按编码规范解码出数字内容。

适用于商品包装、物流标签等场景的条码读取。

### 原理简述
算子的解码流程：

1. **线剖面提取**：在图像中沿水平方向选取一行（或多行平均）像素，获取灰度剖面。
2. **二值化**：将剖面灰度二值化，区分黑条和白条。
3. **条宽测量**：统计连续黑/白像素的宽度，得到条宽度序列。
4. **格式匹配**：将条宽度序列与 EAN-13 编码规范匹配。EAN-13 由 13 位数字组成，包含起始符（3 模块）、左侧数据（6×7 模块）、中间分隔符（5 模块）、右侧数据（6×7 模块）、终止符（3 模块），共 95 模块。
5. **校验**：验证校验位是否正确，正确则输出解码数字。

`format` 参数目前为占位字段，仅尝试 EAN-13 自动解码。

### 适用场景
- 场景1：商品零售结算，读取 EAN-13 商品条码。
- 场景2：物流仓储管理，扫描包裹标签条码。
- 场景3：图书管理，读取 ISBN 条码。

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| format | 格式 | Enum | auto | auto / ean13 | - | 条码格式（占位，目前仅尝试 EAN-13 自动解码） |

### 输入输出
- **输入**：灰度或彩色图像（Mat）。条码应水平方向放置且清晰可见。
- **输出**：
  - `text`（string）：解码文本，类型为 string，描述为"一维码解码结果"。

### 使用示例
识别商品 EAN-13 条码：
```json
{
  "type": "Barcode1d",
  "params": {
    "format": "auto"
  }
}
```
步骤说明：设置 `format=auto` 自动识别条码格式（目前仅支持 EAN-13），对输入图像进行线剖面解码。

### 注意事项
- 条码应尽量水平放置，倾斜角度过大会导致条宽测量不准确。
- 目前仅支持 EAN-13 格式，不支持 Code128、Code39、UPC-A 等其他格式。
- 条码区域应清晰无污损，黑条和白条对比度不足时解码会失败。
- 图像分辨率过低（条码宽度小于 2 像素）时无法正确测量条宽。

### 关联算子
- [QrCodeDetect](#qrcodedetect二维码识别)：二维码识别，与一维码互补。
- [Ocr](#ocr字符识别)：当条码无法识别时可用 OCR 读取文字。
- [Threshold](05_图像分割.md#threshold阈值分割)：预处理增强条码对比度。

## Ocr（OCR 字符识别）

### 核心含义
OCR 字符识别算子基于 `cv::dnn` 模块加载 CRNN（卷积循环神经网络）模型，结合 CTC（连接时序分类）解码实现文字识别。当未配置模型时，算子会优雅降级而不报错。

该算子适用于工业场景中的字符识别，如 serial number、生产日期、批号等。

### 原理简述
算子的识别流程：

1. **预处理**：将输入图像转换为灰度图，缩放/填充至固定高度 `imgHeight`（CRNN 通常为 32 像素），宽度按比例缩放。
2. **前向推理**：将预处理后的图像输入 CRNN 模型。CRNN 由三部分组成：
   - **CNN 特征提取**：卷积层提取图像特征序列。
   - **RNN 序列建模**：双向 LSTM 处理特征序列，捕捉上下文依赖。
   - **CTC 解码**：将 RNN 输出解码为字符序列，处理变长序列对齐问题。
3. **后处理**：根据 `charsetPath` 字符集文件将模型输出的索引映射为字符，过滤置信度低于 `confThreshold` 的字符。

未配置 `modelPath` 时算子跳过推理，返回空结果。

### 适用场景
- 场景1：工业产品 serial number 识别。
- 场景2：生产日期和批号的自动读取。
- 场景3：仪表盘数字读数识别。

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| modelPath | 模型路径 | String | "" | - | - | ONNX CRNN 模型文件路径（留空则跳过推理） |
| charsetPath | 字符集路径 | String | "" | - | - | 字符集文件路径（每行一个字符，UTF8） |
| imgHeight | 输入高度 | Int | 32 | 16 ~ 64 | px | 网络输入高度（CRNN 通常为 32），步长 1 |
| confThreshold | 置信度阈值 | Double | 0.5 | 0.0 ~ 1.0 | - | 低于此阈值的字符将被过滤，步长 0.05 |

### 输入输出
- **输入**：灰度或彩色图像（Mat）。建议输入已裁剪到字符区域的图像以提升识别率。
- **输出**：
  - `text`（string）：识别文本，类型为 string，描述为"OCR 识别结果"。

### 使用示例
识别产品 serial number：
```json
{
  "type": "Ocr",
  "params": {
    "modelPath": "models/crnn.onnx",
    "charsetPath": "models/charset.txt",
    "imgHeight": 32,
    "confThreshold": 0.6
  }
}
```
步骤说明：加载 CRNN 模型和字符集，输入高度 32（CRNN 标准），置信度阈值 0.6 过滤低置信度字符，输出识别文本。

### 注意事项
- `modelPath` 留空时算子不报错但返回空结果，需确保模型路径正确。
- `charsetPath` 字符集文件的字符顺序必须与模型训练时的字符索引一致，否则解码错误。
- `imgHeight` 应与模型训练时的输入高度一致，CRNN 通常为 32，修改会导致精度下降。
- 输入图像建议先裁剪到字符区域（ROI），背景过多会干扰识别。
- CRNN 模型对水平排列的文字识别效果最佳，竖排或弯曲文字需额外处理。
