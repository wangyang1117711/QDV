> **对应版本**：operators.json v2.7.0  
> **算子数量**：3 个

## ReadImage（读图）

### 核心含义
从本地文件路径加载图像到当前方案的数据流中，是所有视觉处理流程的起点。算子支持常见的工业图像格式（png / jpg / bmp / tiff / webp 等），并在加载阶段即可完成颜色模式选择和通道分离，避免在后续流程中重复转换。

该算子面向"离线图像分析"场景：当不需要实时相机采集时，通过指定文件路径即可将样图送入后续算子，便于算法调试、参数验证和回归测试。

### 原理简述
底层调用 OpenCV 的 `cv::imread` 系列接口完成图像解码。`colorMode` 直接映射到 `cv::ImreadModes`：`unchanged` 对应 `IMREAD_UNCHANGED`（保留原始通道与位深），`grayscale` 对应 `IMREAD_GRAYSCALE`（强制转单通道），`color` 对应 `IMREAD_COLOR`（强制转 BGR 三通道）。

`channelMode` 在 `imread` 之后执行：RGB/HSV/Lab/YUV 等模式通过 `cv::cvtColor` 进行色彩空间转换，再通过 `cv::extractChannel` 提取指定单通道；`BGR_RGB / RGB_HSV / RGB_Lab / RGB_YUV` 仅做色彩空间整体转换而不抽通道。

### 适用场景
- 场景1：离线样图调试——在无相机环境下加载本地图片验证算子参数
- 场景2：回归测试——批量加载标准样图对算法效果进行一致性校验
- 场景3：多通道分析——加载彩色图像后直接提取 R/G/B 或 H/S/V 单通道送入后续检测

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| filePath | 文件路径 | String | "" | - | - | 支持 png/jpg/jpeg/bmp/tiff/tif/webp 等格式，最大 100MB |
| colorMode | 颜色模式 | Enum | color | unchanged / grayscale / color | - | IMREAD_UNCHANGED/GRAYSCALE/COLOR；原样 / 灰度 / 彩色 |
| channelMode | 通道分离 | Enum | none | none / R / G / B / H / S / V / L / a / b / Gray / BGR_RGB / RGB_HSV / RGB_Lab / RGB_YUV | - | v5.3：通道分离与色彩空间转换。none=不处理，R/G/B=提取RGB单通道，H/S/V=提取HSV通道，L/a/b=提取Lab通道，Gray=灰度图，BGR_RGB/RGB_HSV/RGB_Lab/RGB_YUV=色彩空间转换 |

### 输入输出
- **输入**：无（数据源算子，从文件系统读取）
- **输出**：`image`（输出图像，类型 Mat）——加载的图像数据

### 使用示例
典型配置——加载彩色样图并提取 HSV 的 H 通道用于颜色检测：

```json
{
  "type": "ReadImage",
  "params": {
    "filePath": "D:/samples/pcb_sample_01.png",
    "colorMode": "color",
    "channelMode": "H"
  }
}
```

步骤说明：
1. 在方案画布拖入 ReadImage 算子
2. 在属性面板 `filePath` 选择本地样图
3. `colorMode` 保持 `color`（默认 BGR 三通道）
4. `channelMode` 选择 `H`，输出即为 HSV 的 H 通道图，可直接送入 ColorDetect 或 Threshold

### 注意事项
- 文件路径支持绝对路径与相对路径，建议使用绝对路径避免工作目录切换导致找不到文件
- 单张图像大小限制 100MB，超大图像需先在外部切分
- `channelMode` 优先级高于 `colorMode`：若 `colorMode=grayscale` 又选择 `R` 通道，将以灰度图为基础进行通道操作，结果可能与预期不符，建议保持 `colorMode=color` 再做通道分离

### 关联算子
- **GrabImage**：当需要从相机实时采集而非读取本地文件时使用
- **ChannelSplit**：ReadImage 仅在加载时做单次通道提取；如需在流程中段反复切换通道，使用 ChannelSplit 更灵活
- **MeanImage / GaussFilter**：读入图像后通常先做平滑去噪再进入检测算子

## GrabImage（采集图像）

### 核心含义
从已打开的相机设备采集单帧图像，是"在线检测"场景的核心数据入口。算子通过相机句柄发起一次 `grab_image` 调用，等待相机返回当前帧并送入后续处理流程。

与 ReadImage 的离线加载不同，GrabImage 强调实时性：每次执行都会获取相机当前画面，适用于产线在线检测、动态目标跟踪等需要新鲜图像的场景。

### 原理简述
底层通过相机 SDK（DirectShow / GigE Vision / USB3 Vision 等）的抓帧接口获取一帧图像数据，并将其封装为 OpenCV `cv::Mat`。`timeout` 参数控制等待相机返回数据的最大时长，超时则报错并终止本次采集，避免相机掉线时整个流程阻塞。

采集到的图像数据格式由 OpenFramegrabber 中配置的 `pixelFormat` 决定（如 Mono8 / RGB8 / BGR8 等），GrabImage 本身不改变像素格式。

### 适用场景
- 场景1：产线在线检测——每次触发时采集当前产品图像进行缺陷判定
- 场景2：动态目标跟踪——连续采集多帧用于运动目标定位
- 场景3：软触发/硬触发采集——配合 OpenFramegrabber 的触发模式实现按需取像

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| acqHandle | 相机句柄 | String | "" | - | - | open_framegrabber 返回的相机句柄名称 |
| timeout | 超时 | Int | 5000 | 100 ~ 60000 | ms | 采集超时时间，步长 100ms |

### 输入输出
- **输入**：需要前置 OpenFramegrabber 算子已成功打开相机并输出有效句柄
- **输出**：`image`（采集图像，类型 Mat）——相机采集的帧图像

### 使用示例
典型配置——软触发模式下采集一帧图像：

```json
{
  "type": "GrabImage",
  "params": {
    "acqHandle": "cam_001",
    "timeout": 3000
  }
}
```

完整流程步骤：
1. 先放置 OpenFramegrabber 算子，`triggerMode` 设为 `Software`，输出句柄名如 `cam_001`
2. 在方案中放置 GrabImage，`acqHandle` 填入 `cam_001`
3. 每次执行 GrabImage 时，相机以软触发方式返回一帧图像
4. 后续连接预处理算子（如 GaussFilter）进行滤波

### 注意事项
- `acqHandle` 必须与上游 OpenFramegrabber 输出的句柄名严格一致，否则会因找不到相机而超时
- `timeout` 建议根据相机帧率和触发方式调整：连续采集可设为 1000~2000ms，硬触发需根据外部信号间隔适当加大（如 5000ms）
- 相机掉线或网络抖动（GigE）会导致超时报错，建议在方案层加入异常分支处理

### 关联算子
- **OpenFramegrabber**：必须前置，提供相机句柄
- **ReadImage**：离线调试时替代 GrabImage，无需相机硬件
- **ImageTransform**：采集到的图像分辨率不匹配时，可用 resize 调整尺寸

## OpenFramegrabber（打开相机）

### 核心含义
打开并初始化图像采集设备，是相机采集流程的第一步。算子根据用户配置的接口类型、设备编号、分辨率、帧率、曝光、增益、触发模式等参数完成设备打开，输出一个相机句柄供后续 GrabImage 使用。

该算子封装了不同相机接口（DirectShow / GigE Vision / USB3 Vision / File）的差异化初始化逻辑，使上层流程无需关心底层 SDK 细节。

### 原理简述
根据 `interfaceName` 选择对应的采集后端：
- **DirectShow**：调用 Windows DirectShow API 打开 USB 摄像头
- **GigEVision**：通过 GigE Vision 协议发现并连接千兆网相机，需配置 `ip`
- **USB3Vision**：通过 USB3 Vision 协议连接 USB3 工业相机
- **File**：从文件序列模拟相机采集，用于无相机环境调试

设备打开后，根据 `width / height / fps / exposure / gain / pixelFormat` 等参数配置相机属性，并按 `triggerMode` 设置触发方式。`useCameraConfig` 勾选时从全局 CameraConfig 读取默认参数，`useActiveCamera` 勾选时直接复用相机模块（CameraView）已打开的句柄，避免重复占用设备。

### 适用场景
- 场景1：产线在线检测——配置 GigE 工业相机进行连续采集
- 场景2：软触发检测——配置 Software 触发模式，由方案流程控制取像时机
- 场景3：调试复用——勾选 `useActiveCamera` 复用相机模块已打开的相机，避免方案运行时再次占用设备

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| interfaceName | 接口名称 | Enum | DirectShow | DirectShow / GigEVision / USB3Vision / File | - | 采集接口：DirectShow / GigEVision / USB3Vision 等 |
| deviceIndex | 设备编号 | Int | 0 | 0 ~ 16 | - | 相机设备索引（从 0 开始），步长 1 |
| width | 分辨率宽 | Int | 0 | 0 ~ 7680 | px | 图像宽度（0=使用相机默认分辨率） |
| height | 分辨率高 | Int | 0 | 0 ~ 4320 | px | 图像高度（0=使用相机默认分辨率） |
| fps | 帧率 | Int | 0 | 0 ~ 240 | fps | 采集帧率（0=使用相机默认帧率） |
| exposure | 曝光时间 | Int | 0 | 0 ~ 1000000 | us | 曝光时间（0=自动曝光；>0=手动曝光，单位微秒） |
| gain | 增益 | Double | -1 | -1 ~ 64 | dB | Gain 增益值（-1=自动；>=0=手动），步长 0.1 |
| triggerMode | 触发模式 | Enum | Continuous | Continuous / Software / Hardware | - | Continuous=连续采集；Software=软触发；Hardware=硬触发 |
| pixelFormat | 像素格式 | Enum | Mono8 | Mono8 / Mono16 / BayerRG8 / BayerGB8 / RGB8 / BGR8 | - | 像素格式 |
| ip | GigE IP 地址 | String | "" | - | - | GigE 相机 IP 地址（仅 GigEVision 接口使用，如 192.168.1.100） |
| useCameraConfig | 关联相机配置 | Bool | false | - | - | 勾选后从全局 CameraConfig 读取默认参数（分辨率/曝光/Gain/触发模式/像素格式/IP） |
| useActiveCamera | 使用已打开相机 | Bool | false | - | - | 勾选后直接复用相机模块（CameraView）已打开的相机句柄，不重复打开设备。需先在相机模块中打开相机 |

### 输入输出
- **输入**：无（设备初始化算子，从硬件/配置读取）
- **输出**：`camera`（相机句柄，类型 Handle）——打开的采集设备句柄

### 使用示例
典型配置 1——GigE 工业相机软触发模式：

```json
{
  "type": "OpenFramegrabber",
  "params": {
    "interfaceName": "GigEVision",
    "ip": "192.168.1.100",
    "triggerMode": "Software",
    "pixelFormat": "Mono8",
    "exposure": 5000,
    "gain": 0,
    "width": 1920,
    "height": 1080
  }
}
```

典型配置 2——复用相机模块已打开的相机：

```json
{
  "type": "OpenFramegrabber",
  "params": {
    "useActiveCamera": true
  }
}
```

步骤说明：
1. 先在相机模块（CameraView）中打开并调好相机参数
2. 方案中放置 OpenFramegrabber，勾选 `useActiveCamera`
3. 后续 GrabImage 即可直接采集，无需重复配置

### 注意事项
- GigE 相机的 `ip` 必须与相机实际 IP 在同一网段，且本机网卡已正确配置 IP，否则会枚举失败
- `exposure=0` 为自动曝光，此时 `gain` 的手动值可能被相机自动增益覆盖，需手动曝光时务必设 `exposure>0`
- 勾选 `useActiveCamera` 时，其余参数（分辨率/曝光等）以相机模块当前状态为准，本算子参数不再生效
- `width / height / fps` 设为 0 表示使用相机默认值，避免设置不支持的分辨率导致打开失败

### 关联算子
- **GrabImage**：直接下游，使用本算子输出的句柄进行抓帧
- **ReadImage**：无相机硬件时替代本算子 + GrabImage 组合
- **ImagePreprocess**：采集后的图像通常需先做去噪和形态学预处理
