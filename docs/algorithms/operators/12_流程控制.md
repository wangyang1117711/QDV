## Loop（循环遍历）

### 核心含义
循环遍历算子按网格/列表/检测/计数/条件五种模式生成 ROI 列表或控制迭代次数，实现对图像分块处理、多 ROI 批量分析、计数循环和条件循环等流程控制。它解决的是"如何对图像的多个区域或多次迭代执行相同算子链"的问题，是复杂视觉流程的编排基础。v2.7.0 新增的流程控制算子之一。

### 原理简述
根据 mode 选择生成策略：
- **grid（网格）**：将图像按 gridCols×gridRows 划分网格，gridOverlap 控制网格间重叠像素，生成 ROI 列表
- **list（列表）**：直接使用 roiList 参数配置的 ROI 列表
- **detection（检测）**：根据上游检测结果动态生成 ROI
- **count（计数）**：执行固定 count 次循环
- **while（条件）**：whileCondition 表达式为真时持续循环，maxWhileIterations 防死循环

startIndex 控制遍历起点，maxIterations 限制最大迭代次数避免死循环。

### 适用场景
- 场景1：大尺寸图像分块检测，网格遍历逐块分析
- 场景2：多 ROI 批量测量，列表模式遍历预设区域
- 场景3：迭代优化，while 模式根据条件动态循环

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| mode | 遍历模式 | Enum | grid | grid/list/detection/count/while | - | ROI遍历模式 |
| gridCols | 网格列数 | Int | 3 | - | - | 网格模式下的列数 |
| gridRows | 网格行数 | Int | 3 | - | - | 网格模式下的行数 |
| gridOverlap | 网格重叠 | Int | 0 | - | - | 网格重叠像素数 |
| roiList | ROI列表 | Vector | "" | - | - | 列表模式下的ROI配置 |
| startIndex | 起始索引 | Int | 0 | - | - | 遍历起始索引 |
| maxIterations | 最大迭代数 | Int | 100 | - | - | 最大循环迭代次数 |
| count | 计数循环次数 | Int | 1 | [1, ∞) | - | count模式下的循环次数 |
| whileCondition | 条件表达式 | String | "" | - | - | while模式下的条件表达式（为真则继续循环） |
| maxWhileIterations | while最大迭代数 | Int | 1000 | [1, ∞) | - | while模式下的最大迭代次数（防死循环） |

### 输入输出
- **输入**：上游图像或检测结果（detection 模式需要）
- **输出**：
  - `roiList`（ROI[]）：生成的ROI列表
  - `count`（int）：ROI数量

### 使用示例
3×3 网格分块遍历配置：
```json
{
  "mode": "grid",
  "gridCols": 3,
  "gridRows": 3,
  "gridOverlap": 20,
  "startIndex": 0,
  "maxIterations": 100
}
```
步骤说明：将图像划分为 3×3 共 9 块 → 每块间重叠 20 px → 生成 9 个 ROI → 下游算子对每个 ROI 逐一执行检测。

### 注意事项
- while 模式必须设置合理的 maxWhileIterations，否则可能死循环
- grid 模式的 gridOverlap 用于避免目标跨网格边界漏检
- count 模式的 count 必须 ≥ 1，否则不执行循环

### 关联算子
- [BranchControl]：循环体内根据条件决定是否提前终止
- [Variable]：循环计数器与索引变量管理
- [FlowJoin]：循环结束后合并多个分支结果

## Script（Python 脚本）

### 核心含义
Python 脚本算子执行自定义 Python 脚本，支持受限模块导入与超时控制。它解决的是"内置算子无法满足的定制逻辑如何实现"的问题，为高级用户提供灵活的编程扩展能力。v2.7.0 新增算子，可在沙箱环境中运行受限 Python 代码。

### 原理简述
算子在内置 Python 解释器中执行 script 参数中的代码：
1. 初始化隔离的执行环境（沙箱）
2. 按 allowedModules 白名单导入模块（默认 math/json/re）
3. 注入上游数据作为脚本输入变量
4. 执行脚本，超时（timeout）后强制终止
5. 收集脚本输出变量并传递给下游

pythonHome 指定 Python 解释器路径，允许使用系统已安装的 Python 环境。受限模块机制防止恶意代码访问文件系统或网络。

### 适用场景
- 场景1：复杂数学计算，如多检测结果融合决策
- 场景2：数据格式转换，将上游输出转为下游需要的格式
- 场景3：自定义算法原型验证，后续再固化为 C++ 算子

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| script | 脚本内容 | Vector | "" | - | - | Python脚本代码 |
| timeout | 超时时间 | Int | 5000 | - | ms | 脚本执行超时时间 |
| allowedModules | 允许模块 | Vector | math,json,re | - | - | 允许导入的Python模块列表（逗号分隔） |
| pythonHome | Python路径 | Vector | D:/Program Files/Python314 | - | - | Python解释器安装路径 |

### 输入输出
- **输入**：上游算子输出数据（作为脚本变量注入）
- **输出**：
  - `output`（Any）：脚本输出结果
  - `success`（bool）：脚本是否执行成功

### 使用示例
多检测结果融合决策脚本：
```python
# script 内容
import json

# 上游传入的检测结果
detections = upstream_data.get("detections", [])
count = len(detections)

# 决策逻辑：检测到 3-5 个为 OK，否则 NG
if 3 <= count <= 5:
    result = {"verdict": "OK", "count": count}
else:
    result = {"verdict": "NG", "count": count}

output = json.dumps(result)
```
```json
{
  "script": "import json\ndetections = upstream_data.get('detections', [])\n...",
  "timeout": 5000,
  "allowedModules": "math,json,re",
  "pythonHome": "D:/Program Files/Python314"
}
```

### 注意事项
- 脚本在沙箱中执行，仅允许白名单模块，无法访问文件系统/网络
- timeout 必须设置，避免死循环导致整个流程卡死
- pythonHome 路径需指向有效的 Python 安装目录，建议遵循 D 盘安装原则

### 关联算子
- [Variable]：脚本内可读写全局变量
- [BranchControl]：根据脚本 success 或 output 分支控制
- [Loop]：脚本可作为循环体内的处理节点

## Variable（变量运算）

### 核心含义
变量运算算子对变量进行算术、拼接、格式化等运算并输出结果，同时支持全局变量的定义、读取、写入和删除。它解决的是"流程中如何存储和加工中间数据"的问题，是流程编排的数据处理枢纽。v2.7.0 新增算子。

### 原理简述
根据 operation 选择运算类型：
- **算术运算**（add/sub/mul/div/mod）：对 operand1 和 operand2 执行对应运算
- **拼接**（concat）：将两个操作数作为字符串拼接
- **格式化**（format）：用 format 字符串（如 %.2f）格式化 operand1
- **变量管理**（get/set/define/delete）：对 variableName 指定的全局变量执行读取/写入/定义/删除

variableType 在 define 模式下指定变量类型（int/double/string/bool/roi/region/points）。结果写入 outputVar 指定的变量名。

### 适用场景
- 场景1：多测量结果聚合，如计算多个尺寸的平均值
- 场景2：字符串拼接，组合多个检测结果为报告文本
- 场景3：全局状态管理，跨算子传递和更新状态变量

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| operation | 运算类型 | Enum | add | add/sub/mul/div/mod/concat/format/get/set/define/delete | - | 变量运算类型 |
| operand1 | 操作数1 | Vector | "0" | - | - | 第一个操作数 |
| operand2 | 操作数2 | Vector | "0" | - | - | 第二个操作数 |
| format | 格式化字符串 | Vector | %.2f | - | - | 格式化模式下的格式字符串 |
| outputVar | 输出变量名 | Vector | result | - | - | 结果输出的变量名 |
| variableName | 全局变量名 | String | "" | - | - | get/set/define/delete操作的目标变量名 |
| variableType | 变量类型 | Enum | int | int/double/string/bool/roi/region/points | - | define模式下创建的变量类型 |

### 输入输出
- **输入**：操作数（operand1/operand2）或全局变量（variableName）
- **输出**：
  - `result`（Any）：变量运算结果

### 使用示例
计算两个测量结果平均值并格式化：
```json
{
  "operation": "add",
  "operand1": "${measure1.distance}",
  "operand2": "${measure2.distance}",
  "format": "%.2f",
  "outputVar": "avgDistance"
}
```
步骤说明：读取两个上游测量距离 → 相加 → 可再用 div 除以 2 → 格式化保留 2 位小数 → 写入 avgDistance 变量供下游使用。

定义全局计数器示例：
```json
{
  "operation": "define",
  "variableName": "defectCount",
  "variableType": "int",
  "outputVar": "defectCount"
}
```

### 注意事项
- 除法（div）时 operand2 不能为 0，取模（mod）同理
- get/set/define/delete 操作依赖 variableName，未指定则无效
- 格式化（format）遵循 Python/C 的 printf 格式规范（如 %.2f、%d）

### 关联算子
- [Loop]：循环体内使用 Variable 管理计数器与累加值
- [Script]：脚本可读写 Variable 管理的全局变量
- [BranchControl]：根据 Variable 运算结果分支控制

## FlowJoin（流程合并）

### 核心含义
流程合并算子同步多个并行执行的流程分支，等待所有前置分支完成后触发后续节点。它解决的是"多个并行流程如何同步汇合"的问题，是实现并行处理与流水线优化的关键算子。v2.7.0 新增算子。

### 原理简述
FlowJoin 维护一个分支完成状态表：
1. 启动时记录 waitBranches 中所有分支 ID 为"待完成"
2. 每个分支完成时回调通知 FlowJoin 标记为"已完成"
3. 当所有分支均完成时，触发下游节点执行
4. 若超过 timeoutMs 仍有分支未完成，超时退出并透传最后完成分支的结果

result 输出透传最后一个完成分支的结果，下游可据此获取汇合数据。

### 适用场景
- 场景1：多视角同步检测，等待所有相机流程完成后再决策
- 场景2：并行计算优化，多个独立算子并行执行后汇合
- 场景3：流水线节拍控制，确保前置工序全部完成才进入下一工序

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| waitBranches | 等待分支列表 | Mat | "" | - | - | 等待的分支ID列表（逗号分隔，如branch1,branch2,branch3） |
| timeoutMs | 超时时间 | Int | 5000 | [100, 600000] | ms | 等待所有分支完成的超时时间 |

### 输入输出
- **输入**：多个并行分支的完成信号
- **输出**：
  - `result`（Any）：透传最后一个完成分支的结果

### 使用示例
双相机并行检测同步配置：
```json
{
  "waitBranches": "camera1_branch,camera2_branch,camera3_branch",
  "timeoutMs": 10000
}
```
步骤说明：三个相机分支并行执行检测 → FlowJoin 等待三者全部完成 → 汇合后触发综合判定节点。若 10 秒内未全部完成则超时退出。

### 注意事项
- waitBranches 中的分支 ID 必须与实际分支节点 ID 一致，否则永久等待
- timeoutMs 应大于最慢分支的预期耗时，避免误超时
- 超时后仍会输出 result（最后完成分支的结果），但流程可能不完整

### 关联算子
- [BranchControl]：BranchControl 创建分支，FlowJoin 汇合分支
- [Loop]：循环体可与并行分支配合实现复杂流程
- [Variable]：汇合后用 Variable 聚合多分支结果

## BranchControl（分支控制）

### 核心含义
分支控制算子根据上游工具结果与条件判定，决定流程流向（真分支/假分支/switch 多分支）。它解决的是"根据检测结果如何动态选择后续处理路径"的问题，是视觉流程条件编排的核心算子。支持比较运算、逻辑运算（AND/OR/NOT/XOR）和多分支 switch 三种模式。

### 原理简述
根据 conditionOp 选择判定模式：
- **比较运算**（>/</==/!=/>=/<=）：将上游 score 与 conditionValue 比较，结果为真走 trueBranch，否则走 falseBranch
- **逻辑运算**（AND/OR/NOT/XOR）：根据 logicInputs（格式 nodeId1:expectedBool1,nodeId2:expectedBool2）聚合多个上游判定结果
- **switch 多分支**：根据 switchValue 匹配 branchCases（格式 case1:toolId1,toolId2;case2:toolId3）中的分支

verdict 输出布尔判定结果，trueBranch/falseBranch 为工具 ID 列表（逗号或换行分隔）。

### 适用场景
- 场景1：OK/NG 分流，检测合格走下料分支，不合格走复检分支
- 场景2：多条件聚合，AND 要求所有检测项均通过才放行
- 场景3：多型号切换，switch 根据产品型号选择对应检测流程

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| conditionOp | 条件运算符 | Enum | > | >/</ ==/!=/>=/<=/AND/OR/NOT/XOR/switch | - | 将上游 score 与 conditionValue 比较 |
| conditionValue | 条件值 | Double | 0.5 | [-1e9, 1e9] | - | 比较的阈值 |
| trueBranch | 真分支工具 ID 列表 | Mat | "" | - | - | 逗号或换行分隔的工具 ID |
| falseBranch | 假分支工具 ID 列表 | Mat | "" | - | - | 逗号或换行分隔的工具 ID |
| logicInputs | 逻辑运算输入 | String | "" | - | - | AND/OR/NOT/XOR模式下的输入，格式: nodeId1:expectedBool1,nodeId2:expectedBool2 |
| switchValue | switch输入值 | String | "0" | - | - | switch模式下匹配分支序号的输入值（支持${var}变量引用） |
| branchCases | 分支用例列表 | String | "" | - | - | switch模式下的分支映射，格式: case1:toolId1,toolId2;case2:toolId3 |

### 输入输出
- **输入**：上游算子的 score 或 bool 结果
- **输出**：
  - `verdict`（bool）：条件判定结果（True/False）

### 使用示例
置信度阈值分流配置：
```json
{
  "conditionOp": ">",
  "conditionValue": 0.85,
  "trueBranch": "pass_node,unload_node",
  "falseBranch": "recheck_node,alarm_node"
}
```
步骤说明：上游 AiClassify 输出 confidence → 与 0.85 比较 → ≥ 0.85 走 trueBranch（放行下料）→ < 0.85 走 falseBranch（复检报警）。

多条件 AND 聚合示例：
```json
{
  "conditionOp": "AND",
  "logicInputs": "size_check:true,color_check:true,defect_check:true",
  "trueBranch": "pass_node",
  "falseBranch": "reject_node"
}
```
步骤说明：三个检测项均期望为 true → AND 聚合 → 全部通过才走 trueBranch。

### 注意事项
- switch 模式下 switchValue 支持 ${var} 变量引用，需确保变量已定义
- logicInputs 格式必须严格为 nodeId:expectedBool，否则解析失败
- trueBranch/falseBranch 为空时表示该分支无后续节点，流程终止

### 关联算子
- [FlowJoin]：BranchControl 创建分支，FlowJoin 汇合分支
- [Variable]：提供分支判定所需的变量值
- [Loop]：循环体内可嵌套 BranchControl 实现复杂流程
