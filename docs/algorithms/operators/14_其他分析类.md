## Caliper（卡尺测量）

### 核心含义
卡尺测量算子在 ROI 区域内沿搜索方向检测边缘并测量距离，输出两边缘之间的距离和边缘点位置。它解决的是"如何高精度测量工件尺寸（宽度、高度、间距）"的问题，是工业视觉尺寸测量的基础算子。模拟物理卡尺的工作方式，在指定搜索区域内寻找边缘点对。

### 原理简述
卡尺测量流程：
1. **ROI 定义**：roiX/roiY/roiW/roiH 定义矩形感兴趣区域
2. **搜索区域**：searchLength 定义搜索长度，searchWidth 定义搜索宽度，构成卡尺搜索窗口
3. **高斯平滑**：用 smoothSigma 对图像做高斯平滑，抑制噪声
4. **边缘检测**：沿搜索方向计算梯度，edgeThreshold 为边缘强度阈值
5. **极性过滤**：polarity 决定接受的边缘类型（任意/暗到亮/亮到暗）
6. **距离计算**：找到一对边缘点 edgePos1/edgePos2，计算其欧氏距离

极性说明：dark_to_bright 表示从暗到亮的上升沿，bright_to_dark 表示从亮到暗的下降沿。

### 适用场景
- 场景1：零件宽度/高度测量，如螺栓直径、板厚
- 场景2：间距测量，如多孔间距、齿距
- 场景3：边缘定位，为后续对齐或拼接提供基准点

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| roiX | ROI左上X | Int | 0 | - | - | 感兴趣区域左上角X坐标 |
| roiY | ROI左上Y | Int | 0 | - | - | 感兴趣区域左上角Y坐标 |
| roiW | ROI宽度 | Int | 100 | - | - | 感兴趣区域宽度 |
| roiH | ROI高度 | Int | 100 | - | - | 感兴趣区域高度 |
| searchWidth | 搜索宽度 | Int | 20 | - | px | 卡尺搜索宽度 |
| searchLength | 搜索长度 | Int | 100 | - | px | 卡尺搜索长度 |
| edgeThreshold | 边缘阈值 | Double | 30 | - | - | 边缘检测阈值 |
| polarity | 极性 | Enum | any | any/dark_to_bright/bright_to_dark | - | 边缘极性选择 |
| smoothSigma | 平滑系数 | Double | 1 | - | - | 高斯平滑系数 |

### 输入输出
- **输入**：单张灰度或彩色图像（建议灰度图，边缘检测更稳定）
- **输出**：
  - `distance`（float）：两边缘之间的距离
  - `edgePos1`（Point）：第一个边缘点位置
  - `edgePos2`（Point）：第二个边缘点位置

### 使用示例
螺栓直径测量配置：
```json
{
  "roiX": 200,
  "roiY": 150,
  "roiW": 300,
  "roiH": 50,
  "searchWidth": 20,
  "searchLength": 300,
  "edgeThreshold": 50,
  "polarity": "any",
  "smoothSigma": 1.5
}
```
步骤说明：定义覆盖螺栓的 ROI → 沿水平方向搜索边缘 → 找到左右两个边缘点 → 计算距离即为直径（像素）→ 可用 UnitConvert 转为毫米。

### 注意事项
- ROI 应紧贴待测边缘区域，过大引入干扰，过小可能漏掉边缘
- edgeThreshold 过低会误检噪声边缘，过高会漏检弱边缘
- polarity 选择不当会导致找到错误的边缘对，建议先用 any 测试再针对性选择

### 关联算子
- [UnitConvert]：将像素距离换算为物理单位（mm）
- [ContourCompare]：卡尺用于局部尺寸测量，轮廓比对用于整体外形检验
- [Variable]：多次测量结果用 Variable 聚合计算均值/极差

## ColorMatch（颜色比对）

### 核心含义
颜色比对算子基于颜色直方图比对模板与目标区域的颜色相似度，输出相似度分数、是否匹配标志和颜色距离。它解决的是"目标区域颜色是否符合标准"的问题，适用于色差检测、颜色分类、配色验证等场景。支持 HSV/RGB/Lab 三种颜色空间和四种直方图比对方法。

### 原理简述
颜色比对流程：
1. **颜色空间转换**：根据 colorSpace 将图像转换到 HSV/RGB/Lab 空间
2. **直方图计算**：对模板和目标 ROI 计算颜色直方图，bins 为分箱数
3. **直方图比对**：用 histMethod 指定的方法计算直方图相似度：
   - **Correl（相关）**：相关性，越接近 1 越相似
   - **ChiSqr（卡方）**：卡方距离，越小越相似
   - **Intersect（相交）**：交集，越大越相似
   - **Bhattacharyya（巴氏）**：巴氏距离，越小越相似
4. **阈值判定**：score ≥ threshold 时 isMatch 为 true

ROI（roiX/roiY/roiW/roiH）限定比对区域，空 ROI 表示整图比对。

### 适用场景
- 场景1：产品色差检测，判断颜色是否在允差范围内
- 场景2：颜色分类，按颜色将工件分流到不同工位
- 场景3：配色验证，确认装配零件颜色一致性

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| templatePath | 模板路径 | String | "" | - | - | 颜色模板文件路径 |
| colorSpace | 颜色空间 | Enum | HSV | HSV/RGB/Lab | - | 颜色空间选择 |
| histMethod | 直方图方法 | Enum | Correl | Correl/ChiSqr/Intersect/Bhattacharyya | - | 直方图比对方法 |
| threshold | 匹配阈值 | Double | 0.8 | - | - | 颜色匹配阈值 |
| bins | 直方图箱数 | Int | 32 | - | - | 直方图分箱数量 |
| roiX | ROI左上X | Int | 0 | - | - | 感兴趣区域左上角X坐标 |
| roiY | ROI左上Y | Int | 0 | - | - | 感兴趣区域左上角Y坐标 |
| roiW | ROI宽度 | Int | 0 | - | - | 感兴趣区域宽度 |
| roiH | ROI高度 | Int | 0 | - | - | 感兴趣区域高度 |

### 输入输出
- **输入**：待测彩色图像 + 颜色模板文件
- **输出**：
  - `score`（float）：颜色相似度分数
  - `isMatch`（bool）：是否达到匹配阈值
  - `distance`（float）：颜色距离值

### 使用示例
塑料件色差检测配置：
```json
{
  "templatePath": "D:/templates/color_standard.png",
  "colorSpace": "Lab",
  "histMethod": "Bhattacharyya",
  "threshold": 0.85,
  "bins": 32,
  "roiX": 100,
  "roiY": 100,
  "roiW": 200,
  "roiH": 200
}
```
步骤说明：加载颜色模板 → 待测图转 Lab 空间 → 计算 ROI 区域直方图 → 巴氏距离比对 → 分数 ≥ 0.85 判定颜色合格。Lab 空间更贴近人眼色觉感知。

### 注意事项
- HSV 空间对光照变化更鲁棒，Lab 空间色差更符合人眼感知
- bins 过多导致直方图稀疏，过少丢失颜色细节，建议 16-64
- 模板与待测图需在同一光照条件下采集，否则色差误判

### 关联算子
- [LightControl]：颜色比对前用光源控制确保光照一致性
- [SurfaceDefect]：颜色比对用于色差，表面缺陷检测用于外观瑕疵，二者互补
- [BranchControl]：根据 isMatch 分支决定合格/不合格流向

## DLOCR（端到端 OCR）

### 核心含义
端到端 OCR 算子执行文字检测与识别，输出文本区域数量、文本区域列表和拼接后的完整文本。它解决的是"图中文字在哪里、是什么"的问题，适用于标签识别、序列号读取、铭牌信息提取等场景。采用检测+识别两阶段架构，支持多语言。

### 原理简述
端到端 OCR 分两阶段：
1. **文字检测**（detectionModelPath）：使用 DB/CTPN 等模型定位文字区域，输出文本框坐标。confThreshold 过滤低置信度框，nmsThreshold 去除重叠框。
2. **文字识别**（recognitionModelPath）：对每个文本框做透视校正后送入 CRNN/STAR-Net 等模型，输出字符序列。

inputWidth/inputHeight 为模型输入尺寸，language 指定识别语言（如 chi_sim 中文简体、eng 英文）。maxTextRegions 限制最大检测区域数以控制耗时。

### 适用场景
- 场景1：产品标签信息读取，如型号、批次号、生产日期
- 场景2：序列号/SN 码识别，用于产品追溯
- 场景3：铭牌信息提取，自动录入资产管理系统

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| detectionModelPath | 检测模型路径 | String | "" | - | - | 文字检测模型文件路径 |
| recognitionModelPath | 识别模型路径 | String | "" | - | - | 文字识别模型文件路径 |
| confThreshold | 置信度阈值 | Double | 0.5 | - | - | 文字检测置信度阈值 |
| nmsThreshold | NMS阈值 | Double | 0.4 | - | - | 非极大值抑制阈值 |
| inputWidth | 输入宽度 | Int | 320 | - | - | 模型输入图像宽度 |
| inputHeight | 输入高度 | Int | 320 | - | - | 模型输入图像高度 |
| language | 语言 | Vector | chi_sim | - | - | 识别语言 |
| maxTextRegions | 最大文本区域数 | Int | 20 | - | - | 最大检测文本区域数量 |

### 输入输出
- **输入**：包含文字的单张图像
- **输出**：
  - `textCount`（int）：检测到的文本区域数量
  - `texts`（TextRegion[]）：文本区域列表
  - `fullText`（string）：拼接后的完整文本

### 使用示例
产品标签识别配置：
```json
{
  "detectionModelPath": "D:/models/ocr_det.onnx",
  "recognitionModelPath": "D:/models/ocr_rec.onnx",
  "confThreshold": 0.5,
  "nmsThreshold": 0.4,
  "inputWidth": 320,
  "inputHeight": 320,
  "language": "chi_sim",
  "maxTextRegions": 20
}
```
步骤说明：加载检测+识别模型 → 检测阶段定位所有文本框 → 识别阶段逐框识别文字 → 输出文本区域列表与拼接全文。

### 注意事项
- 检测模型与识别模型需配套使用，不可混用不同框架的模型
- 文字区域应尽量水平，倾斜文字需先用仿射变换校正
- inputWidth/inputHeight 影响检测精度与速度，小文字建议增大分辨率

### 关联算子
- [LightControl]：OCR 前用光源控制确保文字区域光照充足且均匀
- [Variable]：识别结果用 Variable 做格式化或字符串拼接
- [BranchControl]：根据 fullText 内容分支决定后续流程（如型号匹配）

## LightControl（光源控制）

### 核心含义
光源控制算子控制光源亮度、模式及触发时序，支持 IO/串口/TCP 三种设备通信方式。它解决的是"如何通过视觉系统精确控制光源"的问题，是采集高质量图像的前提。支持持续/频闪/关闭三种工作模式，适用于需要多光谱或多通道照明的场景。

### 原理简述
根据 deviceType 选择通信方式：
- **IO**：通过数字 IO 口控制光源开关与亮度（PWM 调光）
- **串口**：通过 RS232/485 串口发送指令控制光源控制器
- **TCP**：通过网络 TCP 协议发送指令控制智能光源

工作模式：
- **continuous（持续）**：光源常亮，intensity 设定亮度
- **strobe（频闪）**：按 strobePeriodMs 周期频闪，strobeDutyCycle 设定占空比
- **off（关闭）**：关闭光源

triggerDelay 为触发信号延迟，用于与相机曝光同步。channel 选择光源通道号（多通道控制器场景）。

### 适用场景
- 场景1：多光谱成像，切换不同光源通道采集不同特征
- 场景2：频闪照明，高速运动场景下用频闪冻结运动
- 场景3：智能光源控制，通过 TCP 远程调光适配不同产品

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| channel | 通道 | Int | 0 | - | - | 光源通道号 |
| intensity | 亮度 | Int | 255 | - | - | 光源亮度值 |
| mode | 模式 | Enum | continuous | continuous/strobe/off | - | 光源工作模式 |
| strobePeriodMs | 频闪周期 | Int | 100 | - | - | 频闪模式下的周期 |
| strobeDutyCycle | 占空比 | Double | 0.5 | - | - | 频闪模式下的占空比 |
| triggerDelay | 触发延迟 | Int | 0 | - | - | 触发信号延迟 |
| deviceType | 设备类型 | Enum | io | io/serial/tcp | - | 光源控制器设备类型 |
| devicePort | 设备端口 | Vector | "" | - | - | 设备端口名或地址 |

### 输入输出
- **输入**：无图像输入，向外部光源控制器发送控制指令
- **输出**：
  - `success`（bool）：控制指令是否成功执行
  - `command`（string）：下发的控制指令

### 使用示例
多通道频闪照明配置：
```json
{
  "channel": 1,
  "intensity": 200,
  "mode": "strobe",
  "strobePeriodMs": 50,
  "strobeDutyCycle": 0.5,
  "triggerDelay": 5,
  "deviceType": "tcp",
  "devicePort": "192.168.1.200:5000"
}
```
步骤说明：通过 TCP 连接光源控制器（192.168.1.200:5000）→ 选择通道 1 → 频闪模式，周期 50ms，占空比 50% → 亮度 200 → 触发延迟 5ms 同步相机 → 下发指令并返回执行结果。

### 注意事项
- devicePort 格式因设备类型而异：IO 为端口号、串口为 COM 名、TCP 为 IP:端口
- 频闪模式下 strobeDutyCycle 范围 0-1，过小导致亮度不足
- 触发延迟需与相机曝光时间匹配，避免光源未亮时相机已曝光

### 关联算子
- [ColorMatch]：颜色比对前用 LightControl 确保光照一致
- [DLOCR]：OCR 前用 LightControl 提供均匀照明提升识别率
- [SurfaceDefect]：表面缺陷检测需配合合适光源角度与亮度
