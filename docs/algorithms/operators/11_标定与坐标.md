## HandEyeCalib（手眼标定）

### 核心含义
手眼标定算子基于棋盘格角点与机械臂位姿文件，求解相机坐标系到机械臂末端坐标系（或基坐标系）的变换矩阵，支持眼在手上（eye_in_hand）和眼在手外（eye_to_hand）两种安装模式。它解决的是"相机看到的坐标如何转换成机械臂能执行的坐标"的问题，是视觉引导机器人系统的标定基础。支持实时配对标定模式。

### 原理简述
手眼标定的数学本质是求解 AX=XB 方程组：
- **eye_in_hand**：A 为相邻位姿间末端在基坐标系的变换，B 为标定板在相机坐标系的变换，X 为相机到末端的变换（cam2gripper）
- **eye_to_hand**：A 为相邻位姿间末端在基坐标系的变换，B 为标定板在相机坐标系的变换，X 为相机到基坐标系的变换（cam2base）

通过 findChessboardCorners 提取棋盘格角点，solvePnP 求解标定板位姿，最后用 Tsai-Lenz 或 Park-Martin 方法求解 X。minPairs 控制最小配对数，pairTimeoutMs 防止未配对帧堆积。

### 适用场景
- 场景1：eye_in_hand 装配，相机装在机械臂末端做抓取定位
- 场景2：eye_to_hand 装配，相机固定在工位上方做全局定位
- 场景3：实时在线标定，机器人运动过程中自动采集配对标定数据

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| mode | 模式 | Enum | eye_in_hand | eye_in_hand/eye_to_hand | - | eye_in_hand=相机装在机械臂末端，eye_to_hand=相机固定在外部 |
| boardW | 棋盘格列数 | Int | 9 | [2, 30] | - | 棋盘格内角点列数（>=2） |
| boardH | 棋盘格行数 | Int | 6 | [2, 30] | - | 棋盘格内角点行数（>=2） |
| squareSize | 方格边长 | Double | 25.0 | [0.1, 200] | mm | 棋盘格方格边长（mm，>0） |
| imagePaths | 标定图像路径 | String | "" | - | - | 多张标定图像路径，分号 ';' 分隔 |
| poseFilePath | 位姿文件路径 | String | "" | - | - | 机械臂位姿文件路径（每行 6 数：x y z rx ry rz，弧度） |
| minPairs | 最小配对数 | Int | 8 | [3, 50] | 组 | 实时模式下触发标定的最小图像-位姿配对数（>=3） |
| pairTimeoutMs | 配对超时 | Int | 5000 | [100, 60000] | ms | 未配对帧的超时丢弃时间（ms） |
| maxCacheSize | 缓存上限 | Int | 100 | [10, 500] | 帧 | 待配对帧缓存的最大数量 |

### 输入输出
- **输入**：多张棋盘格标定图像 + 机械臂位姿文件（每行 6 数：x y z rx ry rz，弧度）
- **输出**：
  - `matrix`（Mat）：4x4 cam2gripper 齐次变换矩阵

### 使用示例
eye_in_hand 离线标定配置：
```json
{
  "mode": "eye_in_hand",
  "boardW": 9,
  "boardH": 6,
  "squareSize": 25.0,
  "imagePaths": "D:/calib/img01.jpg;D:/calib/img02.jpg;D:/calib/img03.jpg",
  "poseFilePath": "D:/calib/poses.txt",
  "minPairs": 8,
  "pairTimeoutMs": 5000,
  "maxCacheSize": 100
}
```
步骤说明：在 8+ 个不同位姿拍摄棋盘格图像 → 提取角点 → PnP 求位姿 → 配对图像与机械臂位姿 → 求解 AX=XB → 输出 4x4 变换矩阵。

### 注意事项
- 位姿文件的旋转分量必须是弧度（非角度），否则标定结果错误
- 标定图像需覆盖不同姿态（旋转角度变化要充分），否则方程组病态
- minPairs 至少 3 组，建议 8-15 组以保证标定精度

### 关联算子
- [RobotPose]：实时模式下提供机械臂位姿数据源
- [CameraCalib]：先做相机内参标定再做手眼标定
- [PositionCorrect]：使用标定矩阵做坐标修正

## RobotPose（机器人位姿）

### 核心含义
机器人位姿算子从 TCP/串口/文件读取机械臂当前位姿（x y z rx ry rz），写入全局 PoseBuffer 供手眼标定配对使用。它解决的是"如何把机械臂位姿接入视觉系统"的问题，支持三种数据源适配不同机器人通信方式。

### 原理简述
根据 sourceType 选择数据源：
- **TCP**：连接机器人控制器（如 UR 的 30003 端口），解析实时位姿数据流
- **串口**：通过串口协议读取位姿（如 Modbus/自定义协议）
- **文件**：轮询读取位姿文件，外部进程持续追加每行位姿数据

位姿数据格式为 6 自由度：x y z（平移，mm）+ rx ry rz（旋转，弧度），可选 frameId 标识坐标参考系。读取后附带 timestampMs 时间戳，便于与图像帧配对。

### 适用场景
- 场景1：UR/AUBO 等协作机器人通过 TCP 实时回传位姿
- 场景2：PLC/单片机通过串口上报位姿
- 场景3：离线模式通过文件交换位姿数据，避免实时通信复杂度

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| sourceType | 数据源类型 | Enum | file | tcp/serial/file | - | tcp=TCP连接控制器, serial=串口读取, file=文件轮询 |
| host | TCP主机 | String | 127.0.0.1 | - | - | TCP模式下的机器人控制器IP地址 |
| port | TCP端口 | Int | 30003 | [1, 65535] | - | TCP模式下的端口号（UR默认30003） |
| serialPort | 串口名 | String | COM1 | - | - | 串口模式下的端口名（如COM1/COM2） |
| baudRate | 波特率 | Int | 115200 | [9600, 921600] | bps | 串口模式下的波特率 |
| filePath | 位姿文件路径 | String | "" | - | - | 文件模式下的位姿文件路径（外部进程持续追加，每行: x y z rx ry rz [frameId]） |

### 输入输出
- **输入**：无图像输入，从外部数据源读取位姿
- **输出**：
  - `pose`（Json）：包含 frameId/x/y/z/rx/ry/rz/timestampMs 的位姿数据

### 使用示例
UR 机器人 TCP 实时位姿读取：
```json
{
  "sourceType": "tcp",
  "host": "192.168.1.100",
  "port": 30003,
  "serialPort": "COM1",
  "baudRate": 115200,
  "filePath": ""
}
```
步骤说明：连接 UR 控制器 30003 端口 → 解析数据流 → 提取 TCP 位姿 → 附带时间戳 → 写入 PoseBuffer 供手眼标定配对。

### 注意事项
- TCP 模式需确保机器人控制器已开启实时数据端口
- 文件模式下外部进程需持续追加（而非覆盖）位姿数据，每行一组
- 位姿旋转分量单位为弧度，与 HandEyeCalib 要求一致

### 关联算子
- [HandEyeCalib]：消费 RobotPose 写入的 PoseBuffer 做手眼标定
- [PositionCorrect]：使用位姿数据做位置修正
- [Variable]：对位姿数据做算术运算或格式化

## PositionCorrect（位置修正）

### 核心含义
位置修正算子根据参考点与当前点位的偏差计算仿射变换矩阵，输出修正后的位姿。它解决的是"实际位置与理论位置有偏差时如何补偿"的问题，适用于机械臂抓取定位、贴标对位等需要高精度位置补偿的场景。

### 原理简述
通过当前位姿（poseX, poseY, poseAngle）与参考点（refX, refY）构建仿射变换：
1. 平移分量：`(dx, dy) = (poseX - refX, poseY - refY)`
2. 旋转分量：由 poseAngle 决定旋转矩阵
3. 缩放分量：poseScaleX/poseScaleY 分别施加于 X/Y 方向

最终仿射矩阵 M = T(平移) × R(旋转) × S(缩放)，输出修正后的位姿用于机械臂运动补偿。

### 适用场景
- 场景1：机械臂抓取定位，补偿视觉检测到的位置偏差
- 场景2：贴标/对位工艺，根据标记点修正贴标位置
- 场景3：多工位切换，统一不同工位的坐标系偏差

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| poseX | 位姿X | Double | 0 | - | - | 当前位姿X坐标 |
| poseY | 位姿Y | Double | 0 | - | - | 当前位姿Y坐标 |
| poseAngle | 位姿角度 | Double | 0 | - | 度 | 当前位姿角度 |
| poseScaleX | 位姿X缩放 | Double | 1 | - | - | X方向缩放系数 |
| poseScaleY | 位姿Y缩放 | Double | 1 | - | - | Y方向缩放系数 |
| refX | 参考点X | Double | 0 | - | - | 参考点X坐标 |
| refY | 参考点Y | Double | 0 | - | - | 参考点Y坐标 |

### 输入输出
- **输入**：当前位姿坐标与参考点坐标（通常来自上游视觉检测结果）
- **输出**：
  - `affineMatrix`（Double[]）：仿射变换矩阵
  - `pose`（Pose）：修正后的位姿

### 使用示例
贴标位置补偿配置：
```json
{
  "poseX": 105.2,
  "poseY": 98.7,
  "poseAngle": 1.5,
  "poseScaleX": 1.0,
  "poseScaleY": 1.0,
  "refX": 100.0,
  "refY": 100.0
}
```
步骤说明：视觉检测到标记点实际位置 (105.2, 98.7) → 参考理论位置 (100, 100) → 计算偏差 (5.2, -1.3) 与角度 1.5° → 输出修正位姿供机械臂补偿运动。

### 注意事项
- poseAngle 单位为度，非弧度，注意与 RobotPose/HandEyeCalib 的单位差异
- 缩放系数默认 1.0，仅在需要坐标轴比例修正时调整
- 参考点应选择稳定特征点，避免因参考点漂移导致修正错误

### 关联算子
- [HandEyeCalib]：提供相机到机械臂的变换矩阵
- [RobotPose]：提供机械臂当前位姿作为 poseX/poseY 来源
- [UnitConvert]：在像素与物理单位间转换坐标

## UnitConvert（单位换算）

### 核心含义
单位换算算子根据标定文件在距离/面积维度上进行毫米与像素单位换算。它解决的是"像素坐标与物理坐标如何转换"的问题，是视觉测量结果输出物理量的关键环节。支持距离和面积两种维度，以及 mm↔px 双向换算。

### 原理简述
基于相机标定得到的像素比例（pixelScale，单位 mm/px）：
- **距离换算**：`物理距离 = 像素距离 × pixelScale`（px→mm），或 `像素距离 = 物理距离 / pixelScale`（mm→px）
- **面积换算**：`物理面积 = 像素面积 × pixelScale²`（px²→mm²），反向同理

inputType 指定输入是距离还是面积，outputUnit 指定目标单位。calibFile 可选，若提供则从中读取 pixelScale，否则使用参数中的 pixelScale 值。

### 适用场景
- 场景1：尺寸测量，将像素距离换算为毫米输出
- 场景2：缺陷面积评估，将像素面积换算为平方毫米
- 场景3：标定验证，反向换算检验标定精度

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| calibFile | 标定文件 | String | "" | - | - | 标定文件路径 |
| inputValue | 输入值 | Double | 0 | - | - | 待换算的输入值 |
| inputType | 输入类型 | Enum | distance | distance/area | - | 输入值类型：距离或面积 |
| outputUnit | 输出单位 | Enum | mm | mm/px | - | 目标输出单位 |
| pixelScale | 像素比例 | Double | 1 | - | mm/px | 像素到物理单位的比例系数 |

### 输入输出
- **输入**：数值（距离或面积，像素或毫米）
- **输出**：
  - `outputValue`（float）：换算后的输出值
  - `unit`（string）：输出值的单位

### 使用示例
像素距离转毫米距离：
```json
{
  "calibFile": "D:/calib/camera_calib.yml",
  "inputValue": 320.5,
  "inputType": "distance",
  "outputUnit": "mm",
  "pixelScale": 0.05
}
```
步骤说明：输入 320.5 px → pixelScale=0.05 mm/px → 输出 320.5 × 0.05 = 16.025 mm。若提供 calibFile 则从文件读取 pixelScale。

### 注意事项
- 面积换算时 pixelScale 需平方，单位为 mm²/px²
- calibFile 优先级高于 pixelScale 参数，两者都提供时以文件值为准
- pixelScale 必须为正数，否则换算无意义

### 关联算子
- [CameraCalib]：生成 calibFile 提供 pixelScale
- [Caliper]：测量结果（像素距离）通过 UnitConvert 转为物理量
- [PositionCorrect]：坐标修正时用 UnitConvert 统一单位

## CameraCalib（相机标定）

### 核心含义
相机标定算子使用标定板（棋盘格）图像进行相机内参标定，输出标定文件、重投影误差和焦距参数。它解决的是"镜头畸变和焦距如何消除/获取"的问题，是所有视觉测量系统的精度基础。标定结果可用于畸变校正和像素-物理单位换算。

### 原理简述
相机内参模型包含焦距（fx, fy）、主点（cx, cy）和畸变系数（k1-k6, p1-p2）。标定流程：
1. 对每张标定图用 findChessboardCorners 提取内角点
2. 用 cornerSubRefine 亚像素细化
3. 已知角点世界坐标与图像坐标，用 calibrateCamera 求解内参与外参
4. 计算重投影误差评估标定质量

boardW×boardH 为内角点数（非方格数），squareSize 为方格物理尺寸。maxImages 限制参与标定的图像数量以控制耗时。

### 适用场景
- 场景1：新建视觉系统时的初始相机标定
- 场景2：镜头更换或焦距调整后重新标定
- 场景3：高精度测量前的畸变校正参数获取

### 参数详解
| 参数名 | 中文名 | 类型 | 默认值 | 范围 | 单位 | 说明 |
|--------|--------|------|--------|------|------|------|
| boardW | 标定板列数 | Int | 9 | - | - | 标定板内角点列数 |
| boardH | 标定板行数 | Int | 6 | - | - | 标定板内角点行数 |
| squareSize | 方格尺寸 | Double | 25 | - | mm | 标定板单个方格的物理尺寸 |
| imagePaths | 图像路径 | Vector | "" | - | - | 标定图像路径列表（分号分隔） |
| outputFile | 输出文件 | String | "" | - | - | 标定结果输出文件路径 |
| maxImages | 最大图像数 | Int | 20 | - | - | 参与标定的最大图像数量 |

### 输入输出
- **输入**：多张棋盘格标定图像（不同角度/位置拍摄）
- **输出**：
  - `calibFile`（string）：标定结果文件路径
  - `reprojError`（float）：标定重投影误差
  - `fx`（float）：X方向焦距
  - `fy`（float）：Y方向焦距

### 使用示例
9×6 棋盘格标定配置：
```json
{
  "boardW": 9,
  "boardH": 6,
  "squareSize": 25,
  "imagePaths": "D:/calib/01.jpg;D:/calib/02.jpg;D:/calib/03.jpg;D:/calib/04.jpg",
  "outputFile": "D:/calib/camera_calib.yml",
  "maxImages": 20
}
```
步骤说明：拍摄 15-20 张不同角度棋盘格图 → 提取 9×6 内角点 → calibrateCamera 求解 → 输出标定文件与重投影误差。误差 < 0.5 px 为优秀。

### 注意事项
- boardW/boardH 是内角点数，比方格数少 1（如 10×7 方格对应 9×6 角点）
- squareSize 必须准确测量，直接影响后续物理量换算精度
- 标定图像应覆盖画面各区域与不同倾斜角度，避免标定退化

### 关联算子
- [HandEyeCalib]：手眼标定前需先完成相机内参标定
- [UnitConvert]：使用 calibFile 中的 pixelScale 做单位换算
- [PositionCorrect]：标定结果用于坐标系转换与畸变校正
