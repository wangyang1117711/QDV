### Task 4: 接通 ONNX Runtime

**修改文件**:
- `CMakeLists.txt`:
  - `HAS_ONNX_RUNTIME` 选项（默认 OFF，启用前提：安装 CUDA 或 CPU ORT）
  - MinGW 环境链接 `onnxruntime.dll`（MinGW 无法链接 MSVC .lib）
  - ONNX Runtime 检测逻辑放在 `if(HAS_ONNX_RUNTIME)` 条件内

**遇到的问题**:
- 启用 `HAS_ONNX_RUNTIME=ON` 后，onnxruntime.dll 被直接链接到 EXE
- onnxruntime_providers_cuda.dll 依赖 CUDA DLLs（cudart64_12.dll, cublas64_12.dll, cudnn64_9.dll 等）
- 用户机器无 CUDA，导致进程启动失败（0xC0000135 DLL_NOT_FOUND）
- **解决方案**: 将默认值改为 OFF，保留 CMake 配置和编译路径，用户可通过 `-DHAS_ONNX_RUNTIME=ON` 手动启用

**验证**: ZeroShotKitCore 构建通过（启用时）；默认 OFF 时不链接 onnxruntime.dll

## 三、遇到的问题与解决方案

### 问题 1: Git index.lock 阻塞分支切换
- **现象**: `git checkout main` 失败，提示 "Unable to create '.git/index.lock'"
- **解决**: `Remove-Item ".git/index.lock" -Force`

### 问题 2: 测试崩溃 0xC0000005
- **现象**: `ResultDatabase boundary very large result count` 测试崩溃
- **根因**: QSqlDatabase 连接泄漏（close() 未调用 removeDatabase()）
- **解决**: 修正 close() 连接清理顺序 + boundary 测试改用事务批量插入

### 问题 3: ONNX Runtime DLL 导致进程启动失败
- **现象**: 启用 HAS_ONNX_RUNTIME=ON 后，测试进程 0xC0000135 崩溃
- **根因**: onnxruntime_providers_cuda.dll 依赖 CUDA DLLs（cudart64_12.dll 等），用户机器无 CUDA
- **解决**: 将 HAS_ONNX_RUNTIME 默认改为 OFF，保留编译路径和 CMake 配置

### 问题 4: 测试运行时 DLL 路径缺失
- **现象**: 测试进程 0xC0000135 崩溃，日志为空
- **根因**: PATH 中缺少 OpenCV（`D:\opencv\build_mingw\bin`）和 Python（`D:\Program Files\Python314`）的 DLL 路径
- **解决**: 在运行测试前设置完整 PATH

### 问题 5: CMakeLists.txt ONNX 路径检查多了一层子目录
- **现象**: 原代码检查 `${ONNXRUNTIME_ROOT_DIR}/include/onnxruntime/onnxruntime_cxx_api.h`（多了一层 onnxruntime/）
- **解决**: 改为 `${ONNXRUNTIME_ROOT_DIR}/include/onnxruntime_cxx_api.h`（直接路径）
