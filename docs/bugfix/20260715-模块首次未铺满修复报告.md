# QDetectVision 模块首次加载未铺满修复报告

- **报告日期**：2026-07-15
- **模块**：编辑模块（EditView）、零样本检测模块（ZeroShotDetectView）及 CentralWindow 视图切换
- **故障等级**：P1（界面显示异常，影响首次使用体验）
- **状态**：已修复并通过构建验证

---

## 一、背景

用户反馈两个模块存在一致的显示异常：

1. **编辑模块**：首次打开主程序并进入编辑模块时，界面显示过小，未能铺满主程序窗口；窗口缩放后恢复正常。
2. **零样本检测模块**：首次进入时模块未铺满，窗口缩放后恢复正常。

要求统一排查共用的窗口布局/组件初始化逻辑，一次性修复所有相关模块。

## 二、根因分析

### 共因：QStackedWidget 中隐藏子视图的布局延迟

`CentralWindow` 使用 `QStackedWidget` 管理 9 个视图模块。`QStackedWidget` 的特性是：

- **只有当前可见的 widget 会接收 resize/layout 事件**
- 隐藏的 widget 尺寸停留在加入 stack 时的初始值（通常是默认 640×480 或构造时尺寸）
- 当用户首次切换到某个视图时，widget 被显示，但内部子控件（QQuickWidget / QSplitter）可能尚未根据实际可用空间重新计算

这导致两个模块虽然实现技术不同，但现象一致：首次进入时内部组件按旧尺寸渲染，看起来"未铺满"；窗口缩放后触发真正的 resize 事件，布局才恢复正常。

### 编辑模块的具体根因

[Main.qml:22-30](file:///e:/anchor/Trae/QDV/qml/EditView/Main.qml#L22-L30) 根元素使用固定尺寸：

```qml
Rectangle {
    id: root
    width: 1280
    height: 800
    color: Tok.DesignTokens.bgCanvas
    ...
}
```

`EditView` 使用 `QQuickWidget::SizeRootObjectToView` 模式，该模式应在 QML 加载后将 root item 拉伸到 QQuickWidget viewport 尺寸。但首次显示时：

1. `QQuickWidget` 本身已占满 `QStackedWidget`
2. 但 `setSource()` 调用时，内部 viewport 尺寸可能尚未稳定
3. root item 被设置为当时的 viewport 尺寸（较小）
4. 固定 `width: 1280 / height: 800` 被覆盖为小尺寸
5. 界面只显示一小块，右侧/底部大片空白

### 零样本检测模块的具体根因

[ZeroShotDetectView.cpp:72-124](file:///e:/anchor/Trae/QDV/src/UI/ZeroShotDetectView.cpp#L72-L124) 使用 `QSplitter` 三栏布局：

```cpp
m_splitter = new QSplitter(Qt::Horizontal, this);
m_panel->setMinimumWidth(360);
m_resultPanel->setMinimumWidth(400);
m_notesView->setMinimumWidth(280);
m_splitter->setStretchFactor(1, 1);  // 中间拉伸
```

`QSplitter` 的 `sizes()` 在构造时按当前 widget 宽度分配。由于 `ZeroShotDetectView` 构造时尺寸尚未确定（隐藏状态），`QSplitter` 初始尺寸可能很小。首次显示时，splitter 不会自动按新的父窗口尺寸重新分配，导致三栏看起来被压缩在左侧。

### CentralWindow 切换动画的影响

[CentralWindow.cpp:334-399](file:///e:/anchor/Trae/QDV/src/UI/CentralWindow.cpp#L334-L399) 的 `switchView()` 使用 `QPropertyAnimation` 实现滑动切换：

- 先调用 `newWidget->move(targetGeometry.x() + xOffset, ...)` 把新视图放到右侧
- 再动画移动到目标位置
- 动画期间 widget 尺寸虽然是目标尺寸，但内部子控件可能未收到稳定的 resize 事件

这加剧了首次显示时的布局不稳定问题。

## 三、修复方案

### 修复 1：Main.qml 根元素改为 `anchors.fill: parent`

[Main.qml:22-30](file:///e:/anchor/Trae/QDV/qml/EditView/Main.qml#L22-L30) 根本性修复：

```qml
Rectangle {
    id: root
    anchors.fill: parent  // 替代固定 width:1280/height:800
    color: Tok.DesignTokens.bgCanvas
    ...
}
```

**效果**：root item 始终跟随 QQuickWidget viewport 自动拉伸，不再依赖手动同步尺寸。

### 修复 2：强化 EditView 的 root item 尺寸同步

[EditView.cpp:205-234](file:///e:/anchor/Trae/QDV/src/UI/EditView.cpp#L205-L234) 在 `onQmlStatusChanged(Ready)` 中增加双重保险：

1. Ready 时立即同步一次 root item 尺寸
2. `QTimer::singleShot(0, ...)` 延迟到下一事件循环再同步一次
3. 增加尺寸有效性检查（width/height > 0）
4. 只有 root item 未占满 viewport 时才重置，避免不必要抖动

### 修复 3：ZeroShotDetectView 首次显示时刷新 QSplitter

[ZeroShotDetectView.h](file:///e:/anchor/Trae/QDV/include/UI/ZeroShotDetectView.h) 新增：

```cpp
void showEvent(QShowEvent* event) override;
void refreshSplitterSizes();
bool m_firstShow = true;
```

[ZeroShotDetectView.cpp:405-449](file:///e:/anchor/Trae/QDV/src/UI/ZeroShotDetectView.cpp#L405-L449) 实现：

- `showEvent()` 中首次显示时延迟调用 `refreshSplitterSizes()`
- `refreshSplitterSizes()` 根据 `m_splitter->width()` 按面板最小宽度比例重新分配三栏尺寸
- 优先保证中间结果面板空间，空间不足时按比例压缩左右面板

### 修复 4：CentralWindow::switchView 统一触发 resize/layout 刷新

[CentralWindow.cpp:334-399](file:///e:/anchor/Trae/QDV/src/UI/CentralWindow.cpp#L334-L399) 提取 `finalizeSwitch` lambda：

```cpp
auto finalizeSwitch = [this, newWidget]() {
    if (newWidget) {
        const QSize sz = m_contentStack->size();
        if (sz.isValid() && sz.width() > 0 && sz.height() > 0) {
            newWidget->setGeometry(m_contentStack->rect());
            newWidget->updateGeometry();
            if (QLayout* l = newWidget->layout()) {
                l->invalidate();
                l->activate();
            }
            QResizeEvent re(sz, QSize());
            QApplication::sendEvent(newWidget, &re);
        }
    }
};
```

- 动画切换时：动画结束后再调用 `finalizeSwitch`
- 首次切换（无 oldIndex）时：直接调用 `finalizeSwitch`
- 统一修复所有基于 QStackedWidget 的视图的首次铺满问题

## 六、影响范围

### 正向影响

- 两个主要模块的首次进入体验修复
- 所有 QStackedWidget 子视图受益于统一的 `finalizeSwitch` 刷新机制
- 不依赖用户手动缩放窗口即可自动铺满

### 潜在风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| `finalizeSwitch` 中的 `setGeometry` 可能与动画结束后的 geometry 冲突 | `setGeometry(m_contentStack->rect())` 与动画 endValue 一致，不会产生跳动 |
| `QResizeEvent` 发送给 QQuickWidget 可能触发额外重绘 | 仅在尺寸有效时发送，且 EditView 内部已有 QTimer 防抖 |
| ZeroShotDetectView 的 splitter 刷新可能覆盖用户手动调整 | 仅在 `m_firstShow` 为 true 时执行一次，后续用户调整不受影响 |
| Main.qml 改为 anchors.fill 后，部分依赖 root.width/height 初始值的代码可能异常 | 内部组件均使用 anchors 或相对尺寸，已确认无硬编码 1280/800 依赖 |
