## 一、结论摘要

**核心结论**：本项目训练推理模块存在 **3 项关键架构缺口** 和 **5 项功能短板**，建议分 4 个阶段、按优先级逐步实施优化，预计涉及 12 个核心文件的改造与新增。

**三大关键缺口**：
1. **推理引擎桩实现未合并**：真实 InferenceEngine 实现存在于 `.pilot-worktree` 分支，主分支 `include/AI/InferenceEngine.h` 仍为桩代码（仅 clone 输入，未执行真正推理）
2. **缺少图执行器架构**：当前 ToolChainExecutor 为线性链执行，不支持 DAG 拓扑排序、多输入多输出算子、DataToken 统一数据载体
3. **训练→推理闭环断裂**：训练完成后无自动注册模型机制，无模型库管理（LRU 缓存/事务性删除/完整性校验），无数据集校验与导出

**五项功能短板**：
- 仅支持分类训练（ResNet/EfficientNet/MobileNet），缺少 YOLO 目标检测训练
- 推理仅支持分类后处理（softmax），缺少 YOLOv5/v8 检测后处理
- 无三层缓存机制（引擎实例/推理结果/图像数据）
- 图像预览无金字塔缓存、无 Snapshot 历史、无前后对比
- 无数据集四维校验框架与 YOLO/COCO 导出

### 2.3 已有优势（不需改动）

1. **依赖注入架构**：AiClassifyTool 通过 `IInferenceEngine` 接口接收引擎实例，Vision→AI 无反向依赖 — 这是优秀的设计

3. **TrainingBridge 心跳监控**：30 秒无输出超时检测，区分"从未输出"和"中途停滞"
4. **TrainingBridge complete 信号防重**：`m_completedEmitted` 标志防止重复 emit
5. **Python 训练模块**：PyTorch AMP 混合精度、早停、ReduceLROnPlateau 调度器、中文路径兼容（np.fromfile + cv2.imdecode）
6. **PreviewManager 防抖+异步**：300ms 防抖 + QtConcurrent + QFutureWatcher 回主线程
7. **40+ 视觉算子**：涵盖滤波/形态学/边缘/阈值/分割/检测等完整 Halcon 风格算子库

| 技术点 | 实现方式 | 价值 |
|--------|---------|------|

## 五、可借鉴的具体技术点及实施建议

### 5.1 【P0 优先】合并 pilot-worktree 的 InferenceEngine 到主分支

**问题**：主分支 `include/AI/InferenceEngine.h` 是桩实现（53 行），而 `.pilot-worktree/include/AI/InferenceEngine.h` 是完整实现（169 行，含 OpenCV DNN、预处理、后处理、缓存、warmUp、batch）。

**实施建议**：
1. 将 `.pilot-worktree/include/AI/InferenceEngine.h` 和 `.pilot-worktree/src/AI/InferenceEngine.cpp` 合并到主分支
2. 验证 InferenceEngineAdapter.h 的接口兼容性（pilot 版本已对齐）
3. 验证 VisionClassifier.cpp 和 AiClassifyTool.cpp 的调用兼容性
4. 确保 `cv::dnn::Net m_net` 在 CMakeLists.txt 中链接 OpenCV DNN 模块
5. 添加 ONNX Runtime 条件编译宏 `HAS_ONNX_RUNTIME`

**避免直接复制**：需根据本项目命名空间规范调整（pilot 版本用全局命名空间，本项目部分代码用 QDV 命名空间）。

### 5.2 【P0 优先】增强 ModelManager 为完整模型管理器

**借鉴点**：
- LRU 缓存淘汰（默认 3 个引擎实例）
- manifest.json 持久化与启动恢复
- SHA256 完整性校验（流式读取，1MB 缓冲）
- 事务性删除（rename .trash → 记录 → remove）
- 自定义模型自动识别（正则匹配 YOLO 训练产物）

**实施建议**：
```
ModelManager 增强清单：
├─ m_engineCache: QCache<QString, InferenceEngine> (LRU, capacity=3)
├─ m_manifest: QJsonObject (从 models/manifest.json 加载)
├─ addCustomModel(path, displayName) → 写入 manifest
├─ removeCustomModelTransactional(id) → rename + 记录 + remove
├─ verifyModelIntegrity(entry) → 大小 + SHA256 校验
├─ autoDetectModelType(path) → 正则匹配设输入尺寸
├─ loadManifest() / saveManifest() → JSON 持久化
└─ signals: modelsChanged() → 驱动 UI 联动刷新
```

**与本项目集成**：本项目 `models/manifest.json` 已有 5 个模型记录，需兼容现有格式并补充 `input_spec`、`tags`、`customPath` 字段。

### 5.3 【P1 优先】实现训练→推理闭环

**借鉴点**：训练完成 → 检测 ONNX 产物 → 自动注册到 ModelManager → 弹窗提示

**实施建议**：
1. 在 `TrainingBridge::onProcessFinished` 中，当 `complete` 信号包含 `onnxPath` 时：
   - 调用 `ModelManager::instance()->addCustomModel(onnxPath, displayName)`
   - 加载对应的 `labels_path` 作为 classLabels
   - emit 信号通知 UI 弹窗「模型已注册，可在 AI分类算子中选择」
2. 在 EditViewBridge 中暴露 `getAvailableModels()` 方法供 QML 选择模型
3. AiClassifyTool 的参数面板增加模型下拉选择（从 ModelManager 获取列表）

### 5.4 【P1 优先】增加 YOLO 目标检测后处理

**借鉴点**：按输出维度自动分派的三分支后处理

**实施建议**：
在 InferenceEngine 的 `postprocess()` 中增加维度判别逻辑：
```
输出维度判别：
├─ dims=2 [1,nc] → 分类模型：softmax → argmax → top5
├─ dims=3 [1,4+nc,anchors] → YOLOv8：概率已就绪，直接过滤
│   └─ 置信度过滤 → 降序排序 → NMS（自实现 IoU）
└─ dims=3 [1,anchors,5+nc] → YOLOv5：sigmoid(cls)*sigmoid(obj)
    └─ 同上 NMS
```

## 八、图像预览功能改进建议

### 8.1 金字塔缓存实现

在 ImageViewer.qml 或 C++ RenderWidget 中实现 4 档缩放缓存：

```cpp
// 伪代码：金字塔缓存策略
struct PyramidCache {
    int level = -1;  // 当前档位 0-3
    cv::Mat cached[4];  // 4 档预渲染图
    // 档位划分：[0.1,0.5)=0, [0.5,1.0)=1, [1.0,2.0)=2, [2.0,10.0)=3
};

cv::Mat getScaledImage(const cv::Mat& src, double zoom) {
    int newLevel = getZoomLevel(zoom);
    if (newLevel == pyramid.level) {
        return pyramid.cached[newLevel];  // 同档复用
    }
    // 跨档重建
    pyramid.cached[newLevel] = cv::resize(src, ..., INTER_AREA);
    pyramid.level = newLevel;
    return pyramid.cached[newLevel];
}
```

## 十、潜在风险与应对措施

### 10.1 技术风险

| 风险 | 等级 | 应对措施 |
|------|------|---------|
| **pilot-worktree 合并冲突** | 高 | pilot 版本与主分支 VisionClassifier 调用签名已对齐，主要冲突在 InferenceEngine.h 结构体定义。建议以 pilot 版本为准，逐文件合并 |

| **推理缓存图像指纹碰撞** | 低 | 使用 16x16 灰度 meanStdDev + sum 作为指纹，非加密但足以区分不同图像。碰撞时推理结果略有偏差但不崩溃 |
| **中文路径 ONNX 加载** | 低 | OpenCV `readNetFromONNX` 在 Windows 下对中文路径有限制，需用 QFile 读字节流 + `readNetFromONNX(bytes)` 内存加载 |
