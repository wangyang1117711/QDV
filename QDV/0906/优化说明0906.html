① 一句话：为什么每次操作算子都卡

没有单一"元凶"，而是 9 个小税点串成一条链——你在属性面板改一个阈值，程序在后台做了：打 30 条同步磁盘日志 → 深拷贝整个节点表广播 → 销毁并重建画布上全部节点卡片 → 11 处面板级联刷新 → 300ms 后从源头重跑整条算子链（上游没变也重跑）→ 每个结果 PNG 编码写盘 → 界面再从磁盘同步解码显示。每一步几毫秒到几十毫秒，叠起来就是你感到的"一顿"。

改一个参数，实际发生了什么（30 节点方案典型值）： 输入阈值 30→35 ├─ ① 全参数表回传 QML→C++（其实只改了 1 个键） ├─ ② 同步磁盘日志 6~30 条（Logger 每条立即落盘，含杀软扫描等待） ├─ ③ emit currentNodesChanged 广播（QVariantList 按值深拷贝 × 每个监听者） │ ├─ ④ 节点卡片 Repeater 全量销毁重建 × 30 张 │ │ 每张卡片内部再调 2 次 getOperatorMeta()（O(n)查找+全量toMap转换） │ ├─ 4 个分组 Canvas 重绘 + 连线 Canvas 重绘（重建 nodeMap 字典） │ ├─ 11 处 onCurrentNodesChanged 级联（变量面板/连接面板/推荐面板…） │ └─ ParamForm._maybeSnapshot：JSON.stringify 全表对比 × 2 ├─ markDirty → 300ms 防抖 └─ ⑤ 后台重跑整条上游算子链（上游参数没变、图像没变，也全部重算） ├─ 构链 O(n²) 线性扫描 + 全部工具对象 new/销毁 ├─ ⑥ 每个算子输出 PNG 编码写 %TEMP%（UUID 命名，永不清理，无限累积） └─ 完成回调 → 主线程读 2 张 PNG 建 Snapshot └─ ⑦⑧⑨ UI 同步解码 + 不缓存 + 纹理重传（×2 个显示面板） → 这时你才会看到新预览图

证据链与文件行号在详版报告第 2 章；此处为提炼版。

② 六大根因（点开看药方）

A · 热路径同步日志高 · 最易修

改 1 个参数打 6~30 条日志，每条都立即写盘+flush（100ms 批量机制被直调废掉）。全部是排查旧 bug 留下的诊断日志，bug 修了日志没删。

➜ 删/降级诊断日志；Logger 只留定时器批量落盘。预计单次省 3~15ms+，全模块受益。

B · 全量重建风暴高 · 卡顿主因

节点数据用 QVariantList 值类型，任何改动 = "整个 model 换了" → Repeater 销毁重建所有卡片；30 节点 = 100 次 meta 全量转换 + 11 处面板级联。节点越多越卡的直接解释。

➜ 改 QAbstractListModel 角色化模型，参数修改发 dataChanged(单节点) 而非整体 reset，卡片只建一次。

C · 无缓存全链重算高 · 调参质变项

改下游参数 → 上游算子全部重新执行（含 YOLO/模板匹配这种百毫秒~秒级算子）；执行还把 CPU 吃满，你紧接着的下一次点击就被拖慢——"连着操作越来越卡"的来源。执行完的结果也不缓存。

➜ 按（节点,参数哈希,输入图哈希）缓存算子结果，只重跑真正变化的节点。

D · 图像绕磁盘三重税中高

内存里明明有图像，却要走"PNG 编码→写 %TEMP%→读盘→UI 线程同步解码→上传纹理"六步；且 cache:false + 全局禁纹理缓存，同一张图反复解码上传。1200×1200 图每次 50~200ms UI 线程占用。

➜ 先：临时文件复用+清理+恢复异步解码；后：QQuickImageProvider 内存直传，磁盘 IO 归零。

E · 视图切换=推倒重来中

编辑↔运行切换时整个 4194 行的 Main.qml 场景销毁重建（为治 QRhi 纹理 bug 的猛药）。切回来白屏 0.5~2s，面板折叠/滚动位置全丢。

➜ QRhi 三件套修复已稳固的前提下，hide() 保活替代卸载，保留异常兜底路径。

F · 交互细节税中

单击选中即跑该节点上游链（浏览方案也会触发执行）；搜索框每键全量重建 70 算子列表，无防抖；meta 查询无索引无缓存。

➜ 选中只切换+显示缓存图；搜索 200ms 防抖；OperatorDescriptors 加 QHash 索引+toMap 缓存。

④ P0 · 立即做（预计消除 60%+ 卡顿感）

🔴 P0 清单 1~2 天 · 低风险高收益 · 建议今天开始
P0-1
日志静音 + 异步批量落盘（EditViewBridge.cpp:655 等四处 + Logger.cpp:36） ✦ 每次操作省 3~15ms 磁盘等待 · 全模块受益 · 风险最低，可单独今天就改
P0-2
节点列表角色化模型（新建 NodeListModel，Repeater 只建一次卡片，参数修改发单节点 dataChanged） ✦ 30 节点方案每次操作省 50~200ms · 消灭"节点越多越卡"
P0-3
参数增量回传（setValue 只传变化的键；TunerDialog 去掉全表 JSON 深拷贝） ✦ 跨边界数据量从全表降到 1 键
P0-4
临时文件治理 + 图像显示提速（预览 PNG 单文件复用+7天清理；Image 恢复异步解码与缓存） ✦ 预览刷新省 50~200ms UI 线程占用 · %TEMP% 不再膨胀

动手前 10 分钟：先给 addOperator / updateOperatorParams / selectNode 加 QElapsedTimer 埋点，用你的真实方案（30 节点级别）记录基线耗时。之后每条优化都拿数字说话——没有基线就没有验收。

⑤ P1 · 本周做（结构性改造）

🟡 P1 清单 2~5 天/项 · 调参体验质变在这里
P1-1
上游链增量执行缓存 —— 按(节点,参数哈希,输入图哈希)缓存结果，只重跑变化节点 ✦ AI 算子方案调参预览从 1~3 秒降到几十毫秒，这是体验质变项
P1-2
构链去 O(n²) —— 先建 QHash 索引再查；工具对象原型缓存 ✦ 链准备成本 O(n²)→O(n)
P1-3
搜索防抖 + meta 索引缓存 —— 搜索 200ms 防抖；OperatorDescriptors 加 QHash 索引与 toMap 结果缓存 ✦ 中文输入法搜索不再逐键刷列表；卡片 meta 查询 O(1)
P1-4
预览重入改"合并最新" —— 执行中来的新请求不再被丢弃，跑完自动补跑 ✦ 修复"改完参数显示旧结果"的正确性体验问题
P1-5
选中与预览解耦 —— 单击只切换并显示缓存图，仅目标从未执行过才排队跑 ✦ 浏览方案不再触发执行风暴
P1-6
视图切换保活 —— hide() 替代整场景卸载（须带 QRhi 回归验证） ✦ 编辑↔运行切换不再白屏，状态保留
